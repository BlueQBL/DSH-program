# 案头待办 · 待办事项应用

一个**零依赖**的待办事项应用：写下来、拆开、排好优先级、到期前撕掉票根。

- 添加待办：标题、描述、截止日期、优先级、分类
- **子任务**：一个大任务可以拆成多个小步骤，逐步推进
- 查看列表：按分类 / 优先级 / 状态筛选，关键词搜索，五种排序
- 编辑、复制、删除（删除有确认，删错能撤销）
- 统计：完成率、待办数、逾期数、今天到期、7 天内、连续完成天数、分类分布、优先级推进、子任务推进、近两周完成量
- 数据存在浏览器 LocalStorage，刷新不丢；另有 JSON / CSV 导入导出

零依赖、零构建、无后端、无账号：三个源文件（`index.html` + `css/styles.css` + `js/core.js` + `js/ui.js`），
`server.js` 只是一个把目录发出去的静态服务，换成任意静态托管（甚至直接双击 `index.html`）都一样能跑。

## 1. 运行

```bash
cd todo-app
npm start            # → http://127.0.0.1:5210
```

不需要 `npm install`（没有任何依赖）。

跑测试：

```bash
npm test             # 数据层 + 界面，共 430 项
npm run test:core    # 只跑数据层（242 项）
npm run test:dom     # 只跑界面（188 项）
```

浏览器里按 `F12` 可以在控制台执行 `__todoSelfCheck()`，它会量一遍三栏布局、溢出情况和卡片数量并返回结果；
带参数访问 `http://127.0.0.1:5210/?selfcheck=post` 时，这份体检结果会 POST 回 `/metrics`，方便无人值守验收
（见第 7 节的实际输出）。

## 2. 功能与操作

### 2.1 立一单

左边栏填写标题（必填）、描述、截止日期、优先级、分类，回车或点「加入案头」即可。
日期旁有「今天 / 明天 / 本周末 / 下周一 / 清空」快捷按钮；分类输入框会给出已用过的分类作为候选。

标题为空会被拦下，并给出明确提示；提交成功后表单自动清空，方便连续录入。

### 2.2 撕票根 = 完成

每张卡片左侧是一条**编号票根**，印着优先级和分类：

- **往下拖** 超过 34px 撕下来 → 标记完成（票根飞出画面，卡片转为已完成样式）
- **轻点** 票根 → 直接切换完成 / 未完成
- **键盘** 聚焦票根后按 `Enter` 或空格 → 同上

已完成的任务标题会划掉，并记下完成时间；恢复未完成时会清掉完成时间。

### 2.3 拆子任务

大任务可以拆成多个小步骤，拆法有两条路：

**立单时就拆好**：左栏的「子任务」输入框写一步、回车（或点「加入」）——可以连续加多条；
草稿列表里每一条都能先勾选、也能移除，点「加入案头」时随大任务一起写进去。

**做完再拆 / 边做边拆**：卡片上会有一条**子任务进度条**（`已完成/总数` + 还有几步），点它展开清单：

| 操作 | 怎么做 |
| --- | --- |
| 展开 / 收起 | 点进度条那一行（右侧小三角会转向） |
| 完成一步 | 点清单里的方框 |
| 再加一步 | 清单底部输入框，回车即加 |
| 改名 | 悬停某一步 → 点「改名」→ 回车保存，`Esc` 取消 |
| 删掉某一步 | 悬停某一步 → 点「×」 |
| 清掉已完成 | 清单底部「清掉已完成」（有已完成项时才出现） |

**顺手完成**：把最后一步勾掉时，大任务会被**自动划掉**（提示条会说明）；反向则不自动——
把子任务改回未完成，大任务仍然保持已完成，要恢复得自己撕票根或点「恢复未完成」。
子任务不参与逾期计算，逾期只按大任务自己的截止日期算。

「编辑」对话框里也有一份同样的子任务编辑器（带「全部完成 / 清掉已完成」两个批量按钮），
在那里改的东西**要点「保存改动」才生效**，直接关掉对话框不会有任何改动。

### 2.4 筛选、搜索与排序

| 维度 | 说明 |
| --- | --- |
| 状态 | 全部 / 未完成 / 已完成 / 已逾期（分段控件，带数量；数量为 0 时按钮置灰） |
| 分类 | 多选，多个分类取并集（标签上带未完成数量） |
| 优先级 | 多选，紧急 / 高 / 中 / 低 |
| 搜索 | 同时匹配标题、**子任务标题**、描述、分类、优先级和日期；空格分隔多个关键词（AND 关系） |
| 排序 | 智能 / 按截止日期 / 按优先级 / 按创建时间 / 按标题 |

筛选条件之间是**交集**，并与搜索词叠加。工具栏底部显示「显示 N / M 条」，一键「清空筛选」。
「智能排序」的规则是：未完成在前 → 逾期的往前 → 截止日期近的在前 → 优先级高的在前 → 新建的在前。

### 2.5 编辑与删除

每张卡片右侧有四个按钮：切换完成、编辑、复制一份、删除。
编辑走对话框（复用同一套字段与校验）；删除先弹确认框，确认后仍然可以通过底部提示条上的「撤销」找回
（支持 `Ctrl/⌘ + Z`，最多回退 10 步）。
「复制一份」会把子任务一起复制过去，并且给副本里的每一步都换上新 id——副本和原件互不影响。

### 2.6 统计

右栏是「案头账」：

- **完成率**环形图（已完成 / 全部）
- 全部、待办、已完成、已逾期、今天到期、7 天内、连续完成天数
- **分类分布**：每条分类的「已完成 / 总数」，点分类名可直接筛选该类
- **优先级推进**：每个优先级的完成进度条
- **子任务推进**：子任务的 `已完成/总数` 与完成率、还差几步、以及「哪几个大任务拆得最多、剩得最多」的
  分解明细（点任务名会跳到并展开那张卡片）。没用过子任务时这一块整体不显示，不占位置
- **近两周**：14 格完成量柱状图，今天那一格用朱红标出

### 2.7 数据与备份

- 所有数据存在 LocalStorage 的 `todo-app/v1` 键下，刷新、关标签页都不丢
- **JSON**：完整备份（任务 + 分类），导入时**合并**而不是覆盖
- **CSV**：带 BOM 的表格，Excel 双击直接不乱码
- **夜间模式**、**到期提醒**（浏览器桌面通知，需授权）、**示例数据**（一键铺 6 条样例）
- 存储被禁用（隐私模式）时会自动降级到内存，界面明确提示「刷新会丢」，不会静默失败

### 2.8 快捷键

| 键 | 作用 |
| --- | --- |
| `N` | 聚焦标题输入框 |
| `/` | 聚焦搜索框 |
| `Ctrl/⌘ + Z` | 撤销上一步 |
| `Enter`（票根上） | 切换完成状态 |
| `Esc` | 收起提示条 |

## 3. 视觉设计

视觉母题是**铺着网格纸的案头 + 凸版印刷 + 可撕下的编号票根**。

- **纸与墨**：纸 `#E9EAE6`（带 22px 网格，每 5 格一条重线），卡面 `#FBFBF8`，正文墨色 `#22262B`；
  批注只用一个朱红 `#D2401F`，另外三个墨色（青 `#1F6F78`、赭 `#C08A2B`、紫 `#5B4BA6`）按分类分配
- **字体分工**：Bahnschrift 做标题与票根大字（窄体、工业感），Cascadia Mono 做日期、编号与计数
  （等宽，数字对齐），正文用系统中文黑体
- **撕线**：票根与票面之间是一条虚线，骑缝用 `repeating-radial-gradient` 打出一排真实齿孔
- **子任务是"小票"**：展开后的清单挂在票面下方，左侧一条虚线，视觉上像是从票面撕下的一串小票；
  进度条是一条细长齿孔条，不用额外的颜色和图标，靠同一套墨色和齿孔语言把层级讲清楚
- **签名元素**：整页唯一"张扬"的地方就是这条票根——它是把「完成一件事」变成一个有手感的动作，
  其余部分一律安静（细边框、极少阴影、没有渐变泡泡）

深色模式不是简单反色：纸变成深墨 `#15181C`，墨色整体提亮，网格线降到几乎看不见。

工程上的取舍：所有颜色、字号、节奏都从 `:root` 的 token 推导，改一处即可换整套皮肤；
`prefers-reduced-motion` 下关掉撕票根的动画（直接切换状态）；所有图标是内联 SVG sprite，零额外请求。

## 4. 代码结构

```
todo-app/
├── index.html          页面结构、SVG 图标表、内联启动脚本 + 自检脚本
├── css/styles.css      设计 token 与全部样式（含深色模式、响应式、打印样式）
├── js/core.js          数据核心：纯逻辑，不碰 DOM，浏览器与 Node 都能跑
├── js/ui.js            界面层：渲染、事件、撕票根交互、存储写入
├── server.js           零依赖静态服务（另有一个 /metrics 验收端点，见第 7 节）
└── test/
    ├── core.test.js    数据层测试 242 项
    ├── dom-shim.js     极简 DOM 垫片（只覆盖本应用用到的 DOM/事件语义）
    └── dom.test.js     界面测试 188 项：把真实 index.html + core.js + ui.js 跑起来
```

分层的意义在于**数据规则只有一份**：`core.js` 里的枚举（优先级、状态、排序方式）会被界面直接读取来渲染选项，
不会出现"前端写死一套、逻辑层另一套"的漂移；`ui.js` 只负责把状态画出来、把操作翻译成状态变更。

### 数据模型

```js
{
  id: 't...',            // 生成后不变
  title: '写季度复盘',
  desc: '结论放第一页',
  due: '2026-09-21',     // 'YYYY-MM-DD'，空串表示没有截止日期
  priority: 'urgent',    // urgent | high | normal | low
  category: '工作',
  subtasks: [            // 子任务：最多 50 条，每条不超过 60 字
    { id: 't...', title: '导出季度数据', done: true, createdAt: 1758..., completedAt: 1758... },
    { id: 't...', title: '补三张图表', done: false, createdAt: 1758..., completedAt: null }
  ],
  done: false,
  createdAt: 1758...,    // 毫秒时间戳
  updatedAt: 1758...,
  completedAt: null      // 完成时间，恢复未完成时清空
}
```

子任务是**一段嵌套数据，不是独立的任务**：它们不出现在列表里、不参与筛选与逾期统计，
只挂在自己的大任务下面。这样「一个大任务分解成多个小任务」不会把列表和统计搅乱。

因为老数据里没有 `subtasks` 字段，读取时会自动补成空数组；schema 版本号仍是 `1`，
本次新增是**向后兼容**的改动，旧备份可以直接导入。

状态对象还包含 `categories`（分类表）、`filters`（当前筛选，会被一起存下来，刷新后回到同样的视图）、
`prefs`（主题）和 `version`（schema 版本号，便于以后迁移）。

日期一律用**本地日历日**处理：`parseDate` 手工解析 `YYYY-MM-DD` 而不是走 `Date.parse`，
避免时区把「今天到期」漂成「昨天到期」。

## 5. 测试

两套零依赖测试，`npm test` 一起跑：

**数据层（242 项）** —— 把 `core.js` 当纯模块跑，不碰 DOM：

- 日期工具：本地时区解析、闰年、跨月、拒绝 `2026-02-30` 这类不存在的日期
- 到期文案与逾期判断：今天 / 明天 / N 天后 / 逾期 N 天 / 无日期
- 字段归一化：标题去空格、超长截断、非法优先级回落、非法日期丢弃
- 增删改的**不可变性**（改一个状态不会污染原状态）、完成时间记录与清除、复制、清空已完成
- 筛选：分类 / 优先级 / 状态 / 多条件取交集；搜索：多关键词 AND、命中描述、分类与**子任务标题**、日期可搜
- 排序五种模式，含「已完成沉到最后」「无截止日期排最后」的边界
- 统计：完成率取整、空列表不产生 NaN、分类与优先级分布、近 14 天序列与连续天数
- **子任务**：构造与清洗（空标题 / 重复 id / 非对象输入 / 条数上限）、增删改切换、改名不会把原名冲掉、
  一键全部完成 / 清掉已完成、进度对象、汇总统计、批量完成时"顺手动完成"（反向不自动撤销）、
  复制时换新 id、搜索命中子任务标题、JSON / CSV / LocalStorage 三种往返保真、老数据自动补空列表
- LocalStorage：保存/读取往返、坏 JSON 不炸、脏数据（空标题、重复 id、非法枚举）自动清洗
- 导入导出：JSON 往返保真、CSV 引号转义、坏文件抛错
- 400 条任务下的筛选与统计耗时上限

**界面（188 项）** —— 把真实的 `index.html` + `core.js` + `ui.js` 装进 `test/dom-shim.js`
（一个只实现 DOM 语义与事件流的极简垫片）里跑，覆盖：

添加（含字段落位与表单清空）→ 空标题拦截 → 状态筛选 → 分类/优先级叠加筛选 → 搜索防抖与多关键词 →
排序切换 → **撕票根（指针拖拽、轻点、键盘三种路径）** → 统计随完成率变化 → 编辑（回填、保存、空标题拦截）→
复制 → 删除需确认 → LocalStorage 落盘 → **重建整个应用后数据仍在** → 撤销 → 清空已完成 →
夜间模式 → 导出 → 导入（含坏文件不破坏数据）→ **子任务八组**（立单时拆、展开勾选与顺手完成、
反向不自动撤销、就地加/改名/删、清掉已完成、编辑框里改了要保存才生效、搜索命中、复制与刷新后仍在）→
120 条任务的分批渲染

垫片刻意不做布局渲染，能断言的只有"逻辑与状态对不对"；"好不好看、有没有溢出"由第 7 节的真浏览器体检兜底。

## 6. 开发过程中修掉的真问题

这份代码是边写边测的，测试确实抓出了几个不靠肉眼发现的缺陷，记录在此：

1. **`isOverdue` 参数传反了**（`js/core.js`）——`diffDays` 的语义是 `a − b`，而调用处传成 `diffDays(截止日, 今天)`，
   结果**逾期判断整个反了**：未来到期被判成逾期。这是最严重的一个，被数据层测试逮住。
2. **排序比较器返回 `NaN`**（`js/core.js`）——没有截止日期的任务参与比较时返回 `NaN`，
   让 `Array.sort` 的结果取决于输入顺序。现在缺失日期显式当作 `Infinity` 处理。
3. **编辑对话框的优先级选项从未生成**（`js/ui.js`）——`renderPriorityInputs` 只在开工时给立单表单那一组建过，
   编辑框那一组永远是空的，于是"改优先级"保存下去的始终是默认值。现在两组共用同一个构造逻辑。
4. **重绘会冲掉正在输入的搜索词**（`js/ui.js`）——搜索有 120ms 防抖，窗口期内任何重绘都会把输入框
   回填成旧值。现在只在输入框没有焦点时才回填。
5. **票根拖拽依赖 MutationObserver 异步挂载**（`js/ui.js`）——任何一次重绘后，在下一次微任务之前
   卡片都是"死的"，表现是偶尔点不动 / 撕不动。现在改为渲染完**同步**绑定，观察器整个删掉了。

### 加子任务时又抓到两个

6. **复制任务时子任务沿用了原件的 id**（`js/core.js`）——副本和原件里同一步共享一个 id，
   意味着两边再也分不开了。现在复制时给每一步换新 id，并补了数据层与界面层两处断言。
7. **子任务编辑器的点击找不到目标**（`js/ui.js`）——草稿列表的按钮把 id 写在 `data-id` 上，
   而委托处理器读的是 `data-subtaskId`，于是勾选/移除全是静默失效。改完 id 约定后两条路径才通。

另外测试垫片本身也修了几个"骗人"的地方（HTML 解析器被注释和带 `>` 的属性值截断、
`el.title = x` 没有反映到属性、`form.reset()` 把单选按钮的 `value` 清空、
`MutationObserver` 只在下一轮微任务触发、`checked` 属性与 property 不同步、
`:last-child` 等伪类没实现、输入框没有 `select()`），这些修好之后测试才有资格作数——
其中"`checked` 不同步"一度让**所有任务的优先级都被记成默认值**，是垫片的锅，不是应用的。

## 7. 真实浏览器验收

```bash

msedge --headless=new --user-data-dir=<临时目录> \
  --window-size=1500,1280 "http://127.0.0.1:5210/?selfcheck=seed&selfcheck=post"
# 再做一次"刷新"：同一个浏览器 profile，不带 seed 参数
msedge --headless=new --user-data-dir=<同一个临时目录> \
```

## 8. 已知边界

- **统计不随日期自动滚动**：页面里的"今天"是打开页面时算出来的，跨零点需要刷新一次
- **不做云同步**：数据只在本机浏览器，换浏览器或清站点数据就没了——所以带了 JSON 导出
- **不做拖拽排序**：顺序由排序规则决定，不提供手工拖拽排列
- **到期提醒需要授权**：浏览器拒绝通知权限时只影响桌面通知，不影响应用本身
- **CSV 导出不含分类的颜色/顺序**：它是给人看的表格，不是可回灌的备份（要回灌请用 JSON）
- **子任务只有一层**：子任务下面不能再挂子任务；如果需要更深的分解，把那一层拆成独立的大任务更清楚
- **子任务不参与逾期**：逾期只按大任务自己的截止日期算，子任务没有独立的截止日期
