# 番茄钟 · Pomodoro

一台放在桌面上的**机械定时器**：上弦、专注、响铃。

25 分钟专注，5 分钟休息，每 4 个番茄换一次长休。时长可以自己调，
到点会敲铃、发桌面通知、在页面底部弹一张提醒条；
每走完一轮就打印一段到「今日纸带」上，顺手记下今天完成了几个番茄。

零依赖，纯静态，数据只存在本机浏览器里。

---

## 1. 快速开始

```shell
cd pomodoro
node server.js          # 或 npm start
```

打开终端里打印的地址（默认 <http://127.0.0.1:5230/>）即可。

> 桌面通知要求"安全来源"，`http://localhost` 满足条件。
> 直接双击 `index.html`（`file://`）也能用，只是桌面通知可能被浏览器拦下，
> 页面横幅、铃声和标题倒计时仍然有效。

## 2. 功能

| 需求 | 实现 |
| --- | --- |
| 倒计时 | 表盘 + 计数窗双显示，精确到秒 |
| 开始 / 暂停 / 重置 | 三个按键，另配 空格 / R / N 快捷键 |
| 自定义时长 | 专注 1–60、短休 1–30、长休 1–60、每组 2–8 个番茄 |
| 长休息 | 每 4 个番茄自动进 15 分钟长休（组数与时长都可改） |
| 到点通知 | 桌面通知 + 页面横幅 + 提示音 + 标题提醒，四路齐发 |
| 提示音 | Web Audio 现场合成，不加载音频文件；专注结束敲三下，休息结束敲两下 |
| 任务列表 | 加 / 改 / 勾完成 / 删，选中一条后番茄逐个记到它头上，带预估番茄数与进度 |
| 统计 | 每日番茄柱状图（7 / 30 天可切）+ 目标线、几点最出活、番茄花在哪儿了、六项指标 |
| 背景声音 | 七种现场合成的环境音（雨 / 海浪 / 咖啡馆 / 炉火 / 棕噪声 / 白噪声），或播放自己的本地音乐 |
| 额外 | 跳过本轮、删除某条记录、自动进入下一轮、秒针轻响、屏幕常亮、刷新后续跑 |

## 3. 怎么用

### 先写一条任务，再开始

右栏第一张卡就是任务列表：

- 输入框里写完按**回车**加入。第一条会自动成为「当前任务」。
- **点任务行**把它设为当前任务；**点左边圆圈**标记完成（做完的那条会让位给下一条没做完的）。
- **改**：就地改标题和「预估番茄数」，回车保存、Esc 取消。
- **删**：删掉任务不影响历史——它名下的番茄会留在统计里，归到「已删除的任务」。

面板上会别一张**工单条**，写着这一轮在办什么。开工前是淡色的「待办」，
按下开始就变成阶段色的「在办」，旁边是这条任务累计的番茄数。点它可以直接跳回任务列表。

### 上弦

三种方式，改的都是**这一轮**的时长，不会动设置里的默认值：

- **拖表盘** —— 指针跟着手指转，每跨过一格响一声「嗒」。松手即定。
- **键盘** —— 选中表盘后 `↑ ↓ ← →` 各调 1 分钟，`Shift` 加 5 分钟，`Home` 归到 1 分钟，`End` 拉满 60 分钟。
- **± 按钮** —— 计数窗两侧，一次 1 分钟。

计时中表盘会锁住（指针位置就是剩余时间，不能一边走一边改）。想改就先暂停。

### 背景声音

「背景声音」那张卡里二选一（同时响只会互相盖住，所以做成互斥）：

- **环境音** —— 雨 / 海浪 / 咖啡馆 / 炉火 / 棕噪声 / 白噪声，全部用 Web Audio 现场合成，
  不加载任何音频文件。计时没在跑时点一下会先试听 6 秒，让你听听是什么动静。
- **我的音乐** —— 选一个本地音频文件循环播放。用 `blob:` 直接喂给 `<audio>`，
  不上传、不写进存储，刷新页面要重新选一次。

环境音永远跟着计时状态走：**计时停下自动淡出**；打开「仅专注时段播放」后，进休息也会淡出。
这样不会出现「钟停了音乐还在放」。

### 快捷键

| 键 | 作用 |
| --- | --- |
| `空格` | 开始 / 暂停 |
| `R` | 重置本轮 |
| `N` | 跳过本轮（不计入统计） |
| `Esc` | 收起提醒横幅 |

### 一轮走完之后

横幅上给两个选择：**开始下一轮** 或 **先不开始**。
在设置里打开「自动进入下一轮」，就会自己接上，横幅改成「正在短休 · 暂停」。

### 看效率

「效率」卡上有一个 **7 天 / 30 天** 的切换，下面的四块内容都跟着它变：

- **每日番茄**：柱子 + 每日目标的虚线。切到 30 天时柱子变细、日期标签自动抽稀。
- **几点最出活**：把区间里的专注按开始时间摊到 24 个小时上，一眼看出自己什么时候最能干。
- **番茄花在哪儿了**：区间内每个任务的番茄数与时长排行，最多列前六。
- **六项指标**：区间番茄数、活跃日平均、时间在专注的比例、达标天数、连续天数、累计小时。

> 日均按**有记录的天**算，不按日历天——否则周末会被算成 0，把平均值拉低。

## 5. 设计说明

### 为什么是表盘，不是进度环

番茄工作法的原型就是一只厨房定时器。这只定时器的表盘外圈印着 **0–60 分钟的刻度**，
指针的高度**直接就是剩余分钟数**——不用读小字，扫一眼指针指在几，就知道还剩几分钟。

- 指针从设定的时长（比如 25）出发，逆时针扫回正上方的**零位**；
- 指针扫过的那段扇形带，颜色跟着阶段走；
- 已经走过的刻度会被点亮，像仪表盘一样"泄"下去；
- 计数窗（`25:00`）在表盘下方，是机械计数器的样子——精确读数看它，粗读看指针。

### 三个阶段的颜色是有含义的

| 阶段 | 颜色 | 含义 |
| --- | --- | --- |
| 专注 | 番茄红 `#D6402C` | 果子熟了 |
| 短休 | 嫩芽绿 `#5C8A39` | 长叶子 |
| 长休 | 黄铜 `#B0821F` | 收工 |

只改 `<body data-phase>` 一个属性，指针、扇形带、按钮、柱状图、开关全部跟着变色。

### 字体

- `Big Shoulders Display` —— 表盘数字、标题。工业标牌味的窄体，像钢印打上去的。
- `Azeret Mono` —— 计数窗、纸带时间戳。等宽，数字跳动时不会左右抖。
- `Archivo` —— 正文和按钮。

字体走 Google Fonts。断网时会退回系统字体，功能不受影响。

## 6. 几个实现上的坑

这些都是写的时候真踩到的，代码里留了注释。

**计时不能用累加。**
`setInterval` 会被浏览器降频：切到后台标签页会降到 1 秒甚至 1 分钟一次，
笔记本合盖休眠回来更是直接断档。所以计时统一记**截止时刻**：

```js
deadline = 开始时刻 + 总时长;      // 只写一次
剩余 = deadline - 现在;            // 每次渲染算一次减法
```

无论中间被降频多久、睡了多久，剩余时间始终准确。页面关掉再打开也能接着走。

**超时太久的那一轮不算数。**
如果凌晨 2 点打开页面，发现昨晚 8 点那轮番茄"该结束了"，那多半是人早走了。
超过 10 分钟才回来的一轮只推进阶段、**不记进统计**，横幅里也如实说明。
同理，迟到超过 90 秒就不会自动接下一轮。

**运行中改时长不追溯当前这轮。**
否则会出现"剩余时间比总时长还长"这种自相矛盾的状态。改动的生效规则是：
待机的立刻生效，跑着或暂停中的从下一轮生效，界面上会说明。

**任务的归属也在开工那一刻冻结。**
同一个道理：开工后把当前任务从甲换成乙，这一轮仍然记给甲，从下一个番茄开始才算乙，
工单条上会说明。否则一个已经做了 20 分钟的番茄会被记到刚点的那条上。

**删任务不改历史。**
记录里保留 `taskId`，任务没了就归到「已删除的任务」。删一条任务不该让上周的数字变小。

**环境音只跟着计时状态走，不单独做开关。**
规则写成 core.js 里的一个纯函数，所以能单测：计时没在跑就静音，
开了「仅专注时段」后休息也静音。切换场景时先淡出旧的再淡入新的，
炉火的噼啪用随机间隔调度——固定周期一听就假。

**通知和铃声只发一次。**
页面重新可见时会重新判断是否到点，用一个 `chimedFor` 式的结算路径保证不会重复敲铃。
桌面通知带 `silent: true`，因为铃声由页面自己发，否则会响两下。

**隐私模式下 localStorage 会抛错。**
存不进去时退化成内存存储，功能照常，只是刷新后不保留。

## 7. 测试

### 核心逻辑（不需要浏览器）

```shell
npm test          # node test/core.test.js
```

覆盖状态机、计时换算、阶段推进、上弦、设置变更、任务与番茄归属、效率统计、存档容错等 216 项断言。

### 真实浏览器（需要 playwright）

```shell
# 先起服务
node server.js

# 方式一：脚本自己拉起本机 Chrome
node scripts/smoke-test.js
node scripts/verify-layout.js

# 方式二：连到已经跑着的 Chrome（需要 --remote-debugging-port=9222）
set CDP_URL=http://127.0.0.1:9222
node scripts/smoke-test.js
```

**端到端**（152 项）用假时钟快进，实测倒计时、暂停、拖拽上弦、到点结算、通知内容、
纸带与统计、刷新续跑，以及新加的三块：任务的加 / 选 / 关联 / 改 / 完成 / 删、
效率图表的区间切换与标签抽稀、环境音与本地音乐（用一段内存里现造的静音 WAV 当素材，
不往仓库里塞音频文件）。并在 `.screens/` 留下四种宽度的截图。

**版面体检**（49 项）量的是截图看不出来的东西：面板内六块的间距与不重叠、右栏五张卡片的顺序、
任务行的三段式布局、计数窗放不放得下 `25:00`、九种宽度下的重排与溢出、
十三处文字的对比度、深色卡片与底色的层次，最后**解开截图的 PNG 直接采像素**，
确认指针真的画在刻度 25 上、反方向确实是空白的搪瓷。

> 为什么要采像素：这一条抓到过真 bug。指针原本同时用了 SVG 的 `transform` 属性
> 和 CSS 的 `transform-origin`，两者叠加使它绕两倍原点旋转，被推出表盘之外飘在页面右下角
> （因为 SVG 设了 `overflow: visible`）。而所有只读 `rotate()` 属性的断言都显示"一切正常"。
> 现在的做法是只用 CSS `transform`，并让 SVG 不再 `overflow: visible`，
> 这样再出这类错误会直接表现为被裁掉，而不是偷偷飘到别处。

### 看截图

```shell
node scripts/inspect-shot.js .screens/desktop-idle.png 104
```

把 PNG 降采样成终端里的字符画（深色→空格、浅色→@、彩色→R/G/Y），并采几个关键点的真实色值。
在没有图形界面的环境里，这是确认"版面有没有错位、配色有没有跑偏"的可用手段。

## 8. 浏览器要求

| 能力 | 说明 |
| --- | --- |
| 基本计时、上弦、统计 | 所有现代浏览器 |
| 提示音 | 需要 Web Audio；首次点击后才会解锁 |
| 桌面通知 | 需要 `Notification`，且页面在 `http://localhost` 等安全来源下 |
| 保持屏幕常亮 | 需要 Wake Lock API（Chrome / Edge）；不支持的浏览器里该选项自动禁用 |

数据保存在 `localStorage` 的 `pomodoro/v1` 键下，历史保留 180 天，不会上传到任何地方。
