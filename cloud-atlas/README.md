# 云图 · 天气台

一个用**城市名、定位或坐标**查天气的小应用：当前气温与天气状况、湿度、风速风向、气压、降水概率，
未来 24 小时气温曲线，未来 7 天预报，以及可以收藏的常用城市。

界面按**气象观测台**的思路做：不是一叠卡片，而是一张观测图——
坐标纸底、发丝线分区、等宽数字读数，左边一栏像值班表，中间是主读数与曲线。

**零依赖**：前端是原生 HTML / CSS / JS，服务端只用 Node 内置模块，`npm install` 不需要装任何东西。
天气数据来自 [Open-Meteo](https://open-meteo.com/)（免密钥）。

---

## 1. 跑起来

```bash
cd cloud-atlas
node server.js
```

打开 <http://127.0.0.1:5240>。

端口被占用时会自动往后试（最多 +10）；也可以指定：

```bash
node server.js 5250
```

首次打开会尝试用浏览器定位取当地天气；**拒绝授权也没关系**，会自动退到默认城市，页面顶部给一句说明。

## 2. 能做什么

| 你能做的事 | 怎么用 |
| --- | --- |
| 按地名查天气 | 在顶部输入框打地名，候选会列出同名地点的经纬度，选一个 |
| 查县级、乡镇级地名 | 直接打县名（临县、离石、碛口），或带上级写成「山西临县」「吕梁临县」 |
| 取当地天气 | 点「定位」。失败时会说清是拒绝授权、没信号还是超时 |
| 收藏常用城市 | 查到城市后点「收藏这个城市」；之后在左栏一点就切过去 |
| 换单位 | 右上角 °C / °F。气温、风速、气压、7 日数字一起换 |
| 看某一天 | 点「未来 7 天」里的任意一行，上方曲线切到那一天的 24 小时 |
| 逐小时读数 | 在曲线上按住左右拖，或用方向键。读数条跟着走 |
| 看空气质量 | 仪器区第六格是 AQI（按中国国标算），展开可得六项污染物与健康建议 |
| 看天气提示 | 达到预警量级的天气会列在报头下方，每条都写明推导依据 |
| 多城市对比 | 下方「多城市对比」默认只展示当前城市的曲线；用面板里的搜索框加入**任意**城市，最多 5 个 |
| 查历史天气 | 最下面「历史天气」选区间（30 天到 5 年，也可自定义），看统计与趋势 |

### 五处值得说明的设计

**配色跟着天气走。**
`--paper`、`--ink`、`--accent` 这些变量由 `body[data-tone]` 决定，而 `data-tone` 来自真实数据
（WMO 天气码 + 当时是否白天）。所以清晨下雨的杭州和夜里晴朗的拉萨是两套配色，
但版面结构、字号、间距完全一样。变化的是天气，不是产品。

**天象符号会动，但只在主读数上动。**
符号本身是一套"刻线"语言（同一个圆盘，不同天气是同套排线的不同走向）。
动画全部由 CSS 的 `.wx-icon--animate` 触发，符号的几何完全不参与——
这样同一个天气在 7 日条带（静态）和主读数（动）里必然长得一模一样。
动效幅度小、周期慢：雨丝 2.8 秒一个来回，太阳射线 60 秒转一圈。
一排七个符号同时动的时候，任何一个动大了都会变成干扰。

**AQI 用中国国标算，不用上游给的美标值。**
Open-Meteo 会返回一个 `us_aqi`，但那是美国 EPA 口径。同一份空气，
美标可能报「对敏感人群不健康」，国标可能报「良」。给中国用户看天气应用，
分级必须按国内口径，否则用户照着美国分级采取行动就是被误导了。
所以 `js/aqi.js` 按《环境空气质量指数（AQI）技术规定》HJ 633—2012 从原始浓度自己算。

**多城市对比：默认只画当前城市，名额留给用户自己加。**
面板里有自己的搜索框，可以加入任意城市，最多 5 个。

默认值这里改过一次，值得记下来：最初默认装入收藏城市（最多 5 个），
结果这个默认值本身变成了障碍——清单已经占满 5 个名额时，
用户想加一个城市反而必须先删掉一个，而他默认那 5 个未必是想对比的。
**默认值应该是一个起点，不是一个结论。** 所以现在：

- 默认清单里只有当前城市，图上先画着它自己的 24 小时气温曲线，
  提示行告诉用户"还能再展示 4 个城市"；
- 城市数达到 2 个时才显示对照表——一行的表格没有"对照"，留着会让人以为少渲染了几行；
- 城市数为 0 时给一句引导，不留空白。

对比清单和收藏是**分开**的两份数据，所以"为了对比得先收藏"这道坎不存在：

- 用户自己加过或删过一个城市之后（`picksTouched`），收藏再变动也不覆盖清单——
  否则精心挑的那几个会被下一次收藏动作打乱，而用户完全不知道为什么；
- 清单存在本地，下次打开还是这几个城市；
- 默认值每个会话只算一次，而且要等"当前城市"确定之后才算（`picksPending` 标记）。
  启动时收藏是先于主城市数据就绪的，早期版本在这里就合上了闩，
  于是对比区永远停在"随便挑的一个收藏城市"，而用户看到的当前城市是另一个。

**存储格式带版本号和来源标记。** 这一段踩过一次坑，值得记下来：

旧版把「自动生成的默认清单」（收藏城市的前 5 个）**也写进了 localStorage**。
于是从旧版升级上来时，那份自动生成的清单被当成"用户自己的选择"读回来，
新的默认值永远不生效——用户看到的是自己删剩下的那几个城市，
而功能看起来"根本没改"。

根因是存储格式分不出"程序填的"和"用户挑的"。修法有三层：

1. 换成带版本号的键 `cloud-atlas.compare.v2`，存成 `{ v, source, places, pending }`，
   只认 `source === 'user'`；
2. 对旧键做一次性迁移判断：清单里的城市**全部都在收藏里** → 认定为旧版自动填的，丢掉；
   只要有一个不在收藏里（旧版只能通过搜索加入非收藏城市）→ 保留。迁移必须在
   `boot()` 里做，因为收藏是从本地存储读的；早先只放在 `?fav=` 那条分支里，
   普通冷启动根本不经过它，迁移在真实使用中等于没生效；
3. 加 `test/compare-store.test.js`：用真实浏览器**冷启动**（预置好 localStorage 再加载页面），
   把"旧格式全收藏""旧格式含非收藏""新版 source=user""新版 source=default"四种情况都验一遍。
   跑起来之后再改内存状态是测不到这个 bug 的——它就在"读存储"那一步。

上限 5 不是随手定的数：对比图共用一根温度轴，线条越多越难分辨，
5 条是这个配色序列加上图例标签还能一眼对得上的上限，再多只能靠逐个点图例来回试，
那已经不叫对比了。

**多城市对比共用一根温度轴。**
各自归一化的话，"哪条线在上面"就不再等于"哪个城市更热"，
图看着热闹但读不出结论——这和 7 日量程条是同一个道理。
数据用一次批量请求取回（上游支持逗号分隔的多组坐标），5 个城市一次调用。

**历史趋势用"带"而不是两根线。**
读历史的人关心的是"这段时间大概多少度"，上下两条线中间的空间才是重点，
两根线各自拐来拐去反而看不清。所以画成温度区间带 + 均值线 + 下缘降水柱。
统计里给的不只是平均值，还有"后半段比前半段升降多少"——
单看一个平均数，用户没法判断这一年到底算不算热。

### 关于「天气提示」的诚实说明

**这不是中国气象局发布的官方预警，本应用也拿不到官方预警的免费接口**
（[官方渠道](https://platform.weathercn.com/)需要注册 Key，第三方聚合服务同样要 Key，
[Open-Meteo](https://open-meteo.com/en/docs) 也没有统一的预警接口）。

所以这一块的做法是：按国内气象预警的**公开分级标准**，对预报数据做阈值判断，
得出"按标准衡量，这里的天气达到了某级预警的量级"。
界面上因此固定写着「按气象标准阈值由预报数据推算 · 非官方发布」，
每条还给出推导依据（哪个要素到了多少），用户可以自己核对。

判定不了的类别（台风路径、地质灾害、中小河流洪水）**没有做**——
那些需要本地数据和机构的综合研判，硬凑一个看起来热闹的假预警是不负责任的。

覆盖的类别与依据：

| 类别 | 依据 | 分级阈值 |
| --- | --- | --- |
| 高温 | 日最高气温 | 35 / 37 / 40 °C |
| 寒潮 | 过程降温幅度 + 最低气温 | 降温 ≥8°C 且最低 ≤4°C |
| 大风 | 阵风风力（蒲福风级） | 8 / 9 / 10 / 11 级 |
| 暴雨 | 日累计降水量 | 25 / 50 / 100 mm |
| 暴雪 | 日累计降雪量 | 5 / 10 / 20 cm |
| 雷电 | 天气码 + 对流有效位能（CAPE） | 有雷暴码 / CAPE ≥1000 |
| 大雾 | 能见度 | 500 / 200 m |
| 霾 | 空气质量指数 | AQI > 200 / 300 |
| 紫外线 | 紫外线指数 | 8 / 10 / 11 |

## 4. 地名检索（为什么不是简单地查一个接口）

只用一个地名库是查不全中国地名的。实测（2026-09）：

| 查询 | Open-Meteo | Photon（OSM） |
| --- | --- | --- |
| 临县 | 查不到 | 临县 · 山西省吕梁市 ✓ |
| 离石 | 查不到 | 离石区 · 山西省 ✓ |
| 碛口 | 查不到 | 碛口镇 · 山西省吕梁市 ✓ |
| 吕梁 | 「河南许昌」「江苏徐州」← 名字对上、省份全错 | 吕梁市 · 山西省 ✓ |
| 杭州 | 杭州市 · 浙江省 ✓ | 杭州市 · 浙江省 ✓ |

两类问题都要治：**查不到**（县级、乡镇级地名大量缺失）和**张冠李戴**（同名不同省）。
所以 `lib/geocode.js` 两个源并行查，然后：

1. **按"去掉行政区划后缀的名字"分组**，而不是按坐标判重。
   这一条是关键：「吕梁」在河南和山西各有一个，坐标不同、名字一字不差，
   只按坐标判重会当成两个地方，而错的那条还会因为"名字完全匹配"排在前面。
   分组之后让更像个正经地方的那条胜出——山西的吕梁市是 city，河南的吕梁是 PPL，选对了。
2. **组内互相补字段**：Photon 有准确的上级行政区，Open-Meteo 有准确的时区，合成一条。
3. **行政区划查询里把 POI 降序**：查「岚县」不该先给「岚县中学」。
   只降序不删除——查「萧山机场」时那些 POI 恰恰就是答案，而且少给候选可能把正确答案删光。
4. **整串查不到时逐级兜底**，改动量从小到大：
   - 拆省级前缀：`山西临县` → 查 `山西 临县`（这个空格是必须的，实测无空格会去匹配学校名）；
   - 拆地级市前缀：`吕梁临县` → 查 `临县`，并用结果的上级市字段验证拆对了没有；
   - 换外文原名：`雷克雅未克` → `Reykjavik`（两个地名库都没有中文译名）。
   每次兜底都会给前端一句 `note`，界面把它显示在搜索框下面——
   用户要知道为什么自己打的中文名字冒出来一个外国名字。

一个源挂了不影响另一个：Photon 是社区公益服务，偶发抽风或限流，
这时仍然返回 Open-Meteo 的结果并标记 `partial`，而不是整个搜索失败。

## 5. 接口

前端所有取数都走本机服务，不直连上游。

| 接口 | 参数 | 说明 |
| --- | --- | --- |
| `GET /api/search` | `q` `limit` | 地名 → 候选地点（含经纬度、地级市、省份、国家、时区），可带 `note` 兜底说明 |
| `GET /api/place` | `lat` `lon` | 坐标 → 地名（定位反查） |
| `GET /api/forecast` | `lat` `lon` | 坐标 → 当前观测 + 未来 24 小时 + 未来 7 天 |
| `GET /api/batch` | `lat` `lon`（逗号分隔，≤12 个） | 多城市批量预报，一次请求取回，用于对比 |
| `GET /api/air` | `lat` `lon` | 空气质量：六项污染物浓度 + 逐小时序列 |
| `GET /api/archive` | `lat` `lon` `start` `end` | 历史档案：**统计摘要** + 已聚合序列 + 天气构成 |

历史接口给的是**统计之后**的结果，不是原始日值。查五年是 1800 多天、几十万个数字，
全丢给浏览器再算，传输和解析都不划算，而且每次切换时间范围都要重来一遍。
服务端算好摘要与"已经对齐到合适粒度"的序列（超过 120 天自动按月聚合）再返回。
前端只负责画。

统一响应形状：

```json
{ "ok": true, "cached": false, "data": { }, "note": null, "sources": [ ] }
{ "error": "坐标无效" }
```

**为什么要在中间放一层服务，而不是让浏览器直连上游：**

- 上游限流按调用方算。加一层内存缓存后，切来切去查收藏城市不会把额度刷爆。
  观测数据缓存 10 分钟，地名缓存 1 小时——地名基本不变，而 Photon 是公益服务，要省着用；
  查不到的地名也会缓存（空结果），否则反复打同一个查不到的字会一直被限流。
- 上游偶尔抽风或变慢。这里统一超时、统一错误形状，前端只需要处理一种失败格式；
  上游彻底不通时还会退回过期的旧数据并标注 `stale`——天气停在一小时前也比一片报错好。
- 参数校验做在服务端：`lat=&lon=` 这种空串会被 `Number('')` 变成 0，
  上游不会报错，它会返回几内亚湾的天气。所以空值和超范围一律拒绝，不悄悄换个地点。
- 地名检索合并两个源、做兜底，这些逻辑放服务端才能被缓存和测试。

## 6. 测试与自检

```bash
node test/core.test.js           # 纯逻辑：换算、几何、排重、层级显示、脏数据容错
node test/aqi.test.js            # 空气质量：逐档对国标 IAQI 断点表；预警分级阈值
node test/archive.test.js        # 历史统计：聚合、缺报处理、逐年对齐、趋势斜率
node test/geocode.test.js        # 地名检索：合并排序、前缀拆分、县级地名回归锁定
node test/server.test.js         # 接口：路由、参数校验、缓存、越界、错误形状
node test/compare-store.test.js  # 对比清单的存储迁移（需要浏览器，做真实冷启动）
node scripts/check-html.js       # 页面结构：标签配平、id 唯一、脚本与探针引用齐全
node scripts/check-icons.js      # 天象符号：有没有空白图形、有没有引用未定义的图案
node scripts/check-icons-anim.js # 动画符号：几何一致、结构标记都有动画规则
```

后三者需要联网，无网络时会跳过联网用例而不是失败。
`server.test.js` 对"上游超时"会重试一次——上游偶尔慢过 9 秒是抖动，
不是本项目的问题，而随机变红的测试很快就没人看了。

需要真实浏览器的两项（会自己起服务，需要本机有 Chrome 或 Edge）：

```bash
node scripts/verify-layout.js            # 五种宽度：溢出、重叠、塌陷、对比度、点击目标、交互
node scripts/capture.js "?city=临县"      # 截图到 .screens/

```

`verify-layout.js` 是在真实浏览器里量真值，不是看截图：
它读 `getBoundingClientRect` 和 `getComputedStyle`，沿祖先链把半透明背景逐层叠起来算对比度，
再按顺序走一遍真实交互（拖光标、切某一天、切单位、收藏城市、对比图例、时间范围）核对结果。
探针是异步的：对比和历史是在主读数之后才取数的，探针会等它们落地再测，
否则量到的会是"正在取数"的中间状态——那是测量时机不对，不是页面的问题。

> 它抓到的问题都是"看着正常但其实是错的"：夜间天气符号引用了一个自己没用上的填充（渲染成空白）、
> 点了某一天之后列表重建导致 `aria-expanded` 一直停在"未展开"、
> 取整后再换算华氏导致差 1 度、收藏的移除按钮小于最小点击目标、
> 地名查不到时页面永远停在「读表中」、批量接口漏要 `hourly` 导致对比图画不出线、
> 以及时间范围按钮缺少初始的 `aria-pressed`（读屏软件读到的是"状态未知"）。

### 开发用 URL 参数

| 参数 | 作用 |
| --- | --- |
| `?city=临县` | 直接查这个地名（也支持「山西临县」这类写法） |
| `?lat=37.95&lon=110.99` | 直接按坐标取数 |
| `?unit=f` | 以华氏开局 |
| `?nolocate=1` | 跳过自动定位，用默认城市 |

## 7. 已知限制

- **「天气提示」不是官方预警**（见上文「关于天气提示的诚实说明」）。它是阈值推算，
  无法判断台风路径、地质灾害、中小河流洪水这类需要本地数据和机构研判的灾害。
  真要防灾，请以气象部门发布的信息为准。
- **AQI 是"实时"口径，与官方日报会有出入。** 国标定的是 24 小时平均，
  而这里只有当前一小时浓度，没有历史小时序列去凑够 24 小时。
  趋势图用的是 24 小时滑动平均（更接近国标口径），但需要至少 24 小时数据才可靠。
- **历史趋势里的"前后半段差"不是气候态距平。** 严格的气候距平要一个 30 年基准期，
  这里只能和"本区间的前半段"比，界面上写的是"与前一段相比"。
- **乡镇以下的自然村、街道小地名仍然查不到。** 两个地名库的覆盖下限大致到"乡镇/街道"。
  这时会明确提示"没有找到"，并建议加上省份或改用英文名。
- **同名地点只给一个。** 合并时按"去掉后缀的名字"分组，同名不同省的只保留更像正经地方的那条。
  县名重名的场合可以写「山西临县」来指定。
- **中文译名的外文城市靠一份对照表**（`lib/geocode.js` 的 `FOREIGN_ALIAS`，约 50 个常见世界城市）。
  表里没有的译名查不到，界面会提示改用英文名。这不是翻译词典。
- **对比上限 5 个城市**，且没有"任意两个城市对比"的独立入口——对比清单就在对比面板里，
  搜索加入、点标签上的叉移出。清单与收藏分开保存，默认只有当前城市。
- **收藏只存在浏览器本地**（`localStorage`），换浏览器或清缓存就没了。上限 12 个。
  对比清单同样存在本地（`cloud-atlas.compare`）。
- **历史档案有几天产出延迟**，结束日期会被自动截到前天；直接查"今天"上游返回空，
  看起来会像功能坏了，所以由服务端统一截取。
- **定位精度取决于浏览器**，本应用不做 IP 定位兜底。
- 无降水雷达图、无卫星云图——那需要图像数据源，不是这套接口能给的。

## 8. 无障碍与细节

- 全站键盘可达：曲线可以聚焦后用方向键逐小时读（上下键按 3 小时跳），收藏行的移除按钮也能 Tab 到。
- 曲线本体带 `role="slider"` 与实时的 `aria-valuenow`/`aria-valuetext`，读屏软件念的是温度和时刻。
- 正文对比度实测 ≥ 7:1（WCAG AA 要求 4.5:1），最低的一项也在 7 倍以上。
- 尊重 `prefers-reduced-motion`（关掉所有过渡与动画）与 `prefers-contrast: more`。
- 有打印样式：打印时去掉坐标纸与天空底色，只留数据与线条。
- 不引外部字体与 CDN，断网时版面与联网时一致。
