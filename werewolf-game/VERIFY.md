# 怎么自己验证这个游戏

这份文档只回答一件事：**别信我，自己查。**

按"从最快到最费时间"排。前两节纯 Node，不需要装任何东西，也不需要构建。

---

## 0. 三十秒：跑自动检查

```bash
npm run simulate      # 跑 400 局完整对局，打印平衡性与规则审计
npm run fairness      # 公平性审计：验证机器人有没有偷看底牌
npm run check         # 上面两件事 + 公平性审计的自检，一次跑完
```

`npm run check` 会依次做三件事，任何一件出问题都会以非零码退出：

1. 模拟 400 局 —— 流程会不会卡死、规则有没有被守住
2. **植入一个作弊的机器人** —— 确认审计真的抓得到（见下）
3. 审计真实 AI —— 确认它没作弊

如果三行都是 ✅ / "未发现异常"，说明流程、规则、公平性这三件事同时成立。

---

## 1. 机器人有没有偷看底牌？

这是最容易造假、也最值得怀疑的地方。所以我没有写"保证不作弊"的注释，而是写了一个**能证伪它的测试**。

`scripts/fairness.mjs` 的思路：

> 如果一名玩家真的只能看到公开信息，那么把**他不可能知道的那部分信息换掉**，他的决定必须一字不变。

具体做法是：在一局进行中的真实局面里，把所有"该玩家无从得知身份的其他人"的角色**随机重排一遍**——公开事实（谁跳了什么、谁投了谁、谁死了、谁说了什么）全部原地不动——然后分别调用同一个决策函数，比对输出。

```
输出不一致  →  这个决策读了它不该读的东西，也就是作弊
```

只钉住玩家**有权知道**的三样：自己、狼人同伴、预言家验过的人。

实测结果：

```
参与比对的（局面 × 玩家）组合：3084    跳过：0
按身份分布：平民 1021 / 狼人 1034 / 女巫 402 / 猎人 361 / 预言家 266
✅ 全部决策在隐藏身份重排后完全不变 —— 没有任何机器人偷看底牌。
```

### 但一个不会失败的测试等于没测

所以审计带自检。`npm run check` 中间那一步会**故意植入一个翻底牌的投票函数**（专挑活着的狼投票），再跑同一套比对：

```
⚠ 自检模式：已植入一个偷看底牌的投票函数作为对照组
✅ 自检通过：植入的作弊被抓出 891 处，审计有效。
   （示例）局面 day=1 1号（平民）的决策 "vote" 依赖了隐藏身份：
```

你可以自己手动跑这两个对照组，对比着看：

```bash
node scripts/fairness.mjs 25 --selftest --cheat-vote   # 应该报"抓出 891 处"
node scripts/fairness.mjs 40                           # 应该报"完全不变"
```

第一次看到红色的 ❌ 才是重点——它证明这套比对不是在走过场。

### 这个方法的边界

老实说清楚它能证明什么、不能证明什么：

- **能证明**：决策函数的返回值不依赖隐藏身份。这是"不作弊"的必要条件，也是绝大部分作弊会露馅的地方。
- **不能证明**：不排除通过极其间接的渠道泄漏（比如某个公开数值恰好在生成时被真实身份影响过）。我没有发现这种情况，但这份测试不能排除它。
- 广度上也有限：它覆盖 40 局里的 419 张快照，不是所有可能局面。

## 2. 规则真的被守住了吗？

"代码里写了所以一定对"是假的安全感。`scripts/simulate.mjs` 会读每一次行动留下的**审计记录**（`state.audit`）并断言：

| 规则 | 怎么查 |
| --- | --- |
| 解药与毒药不可同夜使用 | 同一条 night 记录里不允许同时出现 `savedId` 和 `poisonedId` |
| 女巫首夜可自救，之后不可 | 任何 `day > 1` 且 `savedId === witchId` 即违规 |
| 解药/毒药各只有一次 | 每局统计用量，超过 1 即违规 |
| 猎人被毒死不能开枪 | `kind: 'hunter'` 且 `reason === 'poison'` 且 `targetId != null` 即违规 |

关键是这些规则**真的被触发过**，而不是"从没发生所以没违规"：

```
女巫行动夜数    1029
用过解药的局    297  用过毒药的局 174
猎人出局        138  其中开枪 100（其余为被毒死或压枪）
```

## 3. 平衡性是编的吗？

跑就行，数字会自己出来：

```bash
node scripts/simulate.mjs 1500
```

你会看到狼人/好人胜率、平均天数、逐日放逐命中率、对跳时村庄站对的比例、胜负方式分布。我给你的数字是 1200 局的结果（49.0% / 51.0%），你自己跑会有正常浮动，但应该落在同一区间。

几个可以拿来判断"这局像不像真的"的锚点：

- **放逐命中狼 ≈ 65%** —— 随机放逐是 37.5%（3 狼 / 8 个候选人）。明显高于随机，说明推理在起作用，但远没到看穿一切。
- **逐日准确率 50% → 70% → 91%** —— 第一天信息最少，差不多是掷硬币；越往后越准。这是真实牌局的形状，不是一条平线。
- **胜负方式分散** —— 屠神 10%、屠民 3%、狼人凑够人头 36%、狼全出局 51%。如果某一种占 90%，说明判胜逻辑写歪了。

想验证**人类席位**强不强，看输出的最后一段"按人类身份拆分"——每种身份各占 1/6，狼人胜率应该都在 40–60% 之间。

## 4. 亲手玩，重点看这几处

自动检查覆盖不到的，是"手感"。打开 <http://localhost:5180/> 或 `npm run dev`。

**先看观战。** 开局页有一个「观战一局」按钮：你的席位交给同一套 AI，全程只看不动手。这是核验 AI 行为最直接的办法——一局大约两分钟，看两三局你就能判断这些机器人是"在盘逻辑"还是"在随机数"。

重点观察：

- 首日有没有人跳预言家、有没有人**悍跳**（会有一个狼跳出来对咬）
- 悍跳狼会不会给同伴发**假金水**（一个狼被塞进好人的信任圈）
- 第二天预言家被刀之后，村庄的票有没有**突然变准**
- 女巫是不是只在场上出现明确查杀时才动毒药
- 猎人有没有在没把握时**压枪**不开

**然后自己玩几局**，专门验证规则：

| 想验证 | 怎么做 |
| --- | --- |
| 女巫首夜可自救、之后不可 | 选「女巫」。第一夜若刀到你，解药按钮可用；第二夜再刀到你，按钮应该禁用并提示"从第二夜起不能自救" |
| 解药毒药不可同夜 | 选「女巫」。点了「救回」之后，毒药按钮应该被禁用 |
| 猎人被毒死不能开枪 | 选「猎人」。被狼刀或被投票放逐会弹开枪界面；被女巫毒死则不会 |
| 平票不放逐 | 投票时观察：票数并列第一名时，结算应该显示"平票，本轮无人放逐" |
| 出局不翻牌 | 白天出局的人，身份到结算页才揭晓 |
| AI 不作弊（体感） | 你当狼、全程藏好，看看它们能不能凭空点你出来 |

**看票型弧线。** 投票阶段会有一圈弧线从每个人飞向他投的人。这是整局信息量最大的一个画面：狼队的三票往往高度重叠——如果看到三条弧线指向同一个人，那多半是一次有组织的冲票。

## 5. 界面有没有崩

```bash
npm run smoke
```

它把开局页、对局页、发言中、选人、女巫用药、投票、发言编辑器、观战托管面板、揭示卡、结算页共 10 个场景**真实渲染一遍**，并捕获 Vue 的运行期警告。

这个测试是有战果的：开发过程中它抓出了 `App.vue` 里一个没做环境判断的 `document` 全局引用。

另外 `npm run build` 会把模板全部编译一遍，模板层的错误在这里就过不去。

## 6. 一个诚实的总结

**已经被验证的：**

- 流程不会卡死（1500+ 局无异常、无空发言、全部正常收官）
- 规则被守住（400 局的每一次用药与开枪都审计过，且规则确实被触发过）
- 决策不依赖隐藏身份（3084 组比对，且审计本身经受过植入作弊的检验）
- 十个界面场景渲染无警告
- 平衡性可复现（49% / 51%）

**没有被验证的：**

- 机器人**打得好不好**。以上所有检查都只能证明它们"守规矩"，不能证明它们的推理接近人类高手。目前的手感是：会盘票型、会站边、会悍跳，但**不会**做深度反逻辑（比如"狼不会这么明显地保人，所以保人的那个反而是好人"）。这类二阶层推理没有实现。
- 观感。我没有浏览器截图能力，配色、字距、动效在你屏幕上的实际效果需要你自己看。这也是我建议你先点「观战一局」的原因——它同时验证了 AI 行为和视觉效果。
- 长时间稳定性。最长的连续游玩记录是几局，不是几十局。
