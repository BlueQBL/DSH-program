# 狼人杀 · 九人局

一个可以直接在浏览器里玩的九人标准局狼人杀。你坐一席，其余八人由 AI 扮演。

**3 狼人 · 预言家 · 女巫 · 猎人 · 3 平民**

单机、零后端、零外部资源。发牌、夜间行动、白天发言、投票放逐、胜负判定全部在浏览器里跑完。

开局页有一个 **「观战一局」** 按钮：你的席位交给同一套 AI，全程只看不动手。
想核验机器人打得像不像人、有没有作弊，这是最直接的办法。

---

## 跑起来

```bash
npm install
npm run dev        # http://localhost:5180
```

其它命令：

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 打包到 `dist/`，产物是纯静态文件，扔到任何静态服务器都能跑 |
| `npm run check` | **一条命令跑完全部验证**：400 局模拟 + 规则审计 + 公平性审计（含自检）。纯 Node，不需要构建 |
| `npm run simulate [局数]` | 无头模拟对局，打印平衡性、逐日准确率、规则审计 |
| `npm run fairness` | 公平性审计：重排隐藏身份，验证机器人没有偷看底牌 |
| `npm run smoke` | 把 10 个界面场景真实渲染一遍，检查运行时错误 |

**想知道我是怎么验证的、以及怎么自己复核，看 [`VERIFY.md`](./VERIFY.md)。**

## 界面

版面就是一张桌子，从上到下四层：

```
┌──────────────────────────────────────────────────────┐
│  天幕   天色 = 当前阶段，亮着的窗 = 还活着的人         │
├───────────────────────────────────┬──────────────────┤
│                                   │                  │
│        圆桌  九个席位             │      纪要        │
│              票型画成弧线         │   一整晚的卷宗    │
│                                   │                  │
├───────────────────────────────────┤                  │
│  我的手牌        行动坞（此刻唯一要做的事）           │
└───────────────────────────────────┴──────────────────┘
```

**天幕**是这一页的签名元素，也是唯一投入了装饰预算的地方。它是一整片手绘的夜空压在村庄屋脊之上，同时承担三件事：

1. **阶段指示器** —— 天色的冷暖直接告诉你现在是入夜、深夜、拂晓还是白天；月亮会随着夜间流程从东边移到西边。
2. **人口计** —— 村里每一扇亮着的窗，就是一名还活着的玩家。有人出局，就是他家的灯灭了。你的那扇窗多一圈铜边。
3. **情绪发生器** —— 狼人睁眼时天最黑，天亮时屋脊后透出一线暖光。

其余部分刻意保持安静：木牌与火漆印的形制、1px 的黄铜细线、圆角一律压到 2–3px，靠字距和留白撑住场面。

### 关于字体

只用系统字体，**不下载任何字体文件**，所以离线打开也一定是这个样子。中文按「楷 / 宋 / 黑」三体分工：楷体题字（阶段大字、角色符号），宋体做标题，黑体做界面，数字用等宽。

## 机器人是怎么想的

这是这个项目里真正的核心。八个机器人**不作弊**——每个决策只看它身份允许它知道的东西：

- 狼人知道同伴是谁
- 预言家知道自己验过谁
- 其余人只能看公开信息：谁跳了身份、谁验了谁、谁给谁上票、谁死了

所有好人的推理共用一套**怀疑度模型**，它来自真实的狼人杀经验法则，而不是随机数：

| 信号 | 在模型里怎么用 |
| --- | --- |
| 真预言家跳出来通常活不过两晚 | 跳了预言家还活过两晚的，怀疑度上升 |
| 悍跳狼倾向咬"村里的好人" | 报一个高信誉玩家是查杀 → 该声明的可信度下降 |
| 被狼刀的预言家多半是真的 | 死于狼刀的声明者可信度上升 |
| 真预言家的金水会被狼优先处理 | 金水被夜里刀了 → 该声明可信度上升 |
| 票型会出卖人 | 投过铁狼的加分，咬过铁好人的大幅扣分，跟着可疑的人投票也扣分 |
| 划水的人多半有问题 | 第二天还没有有效发言的加一点怀疑 |
| 村里的火力要集中 | 当天被多人指认的人，怀疑度按指认者的话语权加权上升 |

于是会出现一些不是写死的、而是**涌现**出来的局面：

- 首日两个预言家对跳，村庄会根据"谁咬的是好人"和"谁在保谁"自行站边，而不是掷硬币
- 狼队里有人悍跳预言家，会给同伴发一个假金水，把一个狼塞进好人的信任圈
- 大队人马信一个预言家，但总有一两个人不认——这条"异议"就是狼人的翻盘空间
- 女巫读到场上有一个明确的查杀，才会动毒药
- 猎人没把握时压枪不开

跑 `npm run simulate 1500` 会打印这套逻辑的实际表现。当前 1200 局的统计：

```
狼人胜          588  (49.0%)
好人胜          612  (51.0%)
平均天数        2.69
平均发言条数    18.0
放逐命中狼      1528 / 2347  (65.1%)      ← 随机放逐只有 37.5%
预言家首日跳牌  975 / 1200   (81.3%)
预言家对跳局    946   村庄站对 56.2%  站错 24.2%

逐日放逐命中：  第1天 50.3%  →  第2天 68.8%  →  第3天 91.9%
```

第 1 天信息最少，村子差不多是掷硬币；越往后越准——这正是真实牌局的形状。
胜负也分得很散：屠神 10.0%、屠民 2.6%、狼人凑够人头 36.4%、狼全部出局 51.0%。

### 发言不是套话

每一句话都引用**本局真实发生过的事**：谁跳了预言家、验了谁、谁给谁上了票、谁昨晚倒牌。
句式随九个人各自的性格（`personas`）变化——老陈沉稳、阿蛮急躁、白露只讲逻辑、半仙半信半疑，
不会出现全场一个腔调的情况。

你发言时也可以两种方式并存：**选立场**（跳预言家 / 指认 / 站边 / 辩解）让系统按你的立场组织语言，
或者**自己写一段话**，原文进记录，但你的立场仍然会被机器人听懂并记住。

## 本局规则

**流程**：入夜 → 狼人行动 → 预言家查验 → 女巫用药 → 天亮公布死讯 → （猎人开枪）→ 发言 → 投票放逐 → （猎人开枪）→ 下一夜

**细则**

- 女巫首夜可以自救，从第二夜起不能自救
- 解药与毒药不可在同一夜同时使用
- 猎人被投票放逐或被狼刀死可开枪；被女巫毒死不能开枪
- 本局不翻牌，出局不公布身份，全靠发言与票型推理

**胜负**

- 好人胜：三只狼全部出局
- 狼人胜：杀光三名神职（屠神），或杀光三名平民（屠民），或狼人数量已不少于好人

## 代码结构

```
src/
  game/          纯逻辑，不依赖 Vue，可以直接在 Node 里跑
    roles.js       角色与九位村民的人格
    setup.js       发牌、建席位、胜负判定
    ai.js          机器人决策：怀疑度模型、夜间行动、悍跳、投票
    speech.js      发言生成：按人格与实际局势组句
    director.js    导演——用 async/await 写成的完整流程
    autopilot.js   托管：观战模式与模拟器共用同一套答题逻辑
    audio.js       WebAudio 现场合成的音效（无音频文件）
  composables/
    useGame.js     全局对局仓库 + 导演需要的 wait/ask/reveal 宿主接口
    useTypewriter.js
  components/    SkyCanopy · SeatRing · SeatCard · TableHub · RoleCard
                 ActionDock · LogRail · RevealOverlay · LobbyScreen · EndScreen
  styles/        tokens.css（设计令牌）· base.css（原语）
scripts/
  simulate.mjs   无头对局模拟 + 平衡性统计 + 规则审计
  fairness.mjs   公平性审计：重排隐藏身份，验证 AI 没有偷看底牌（带自检）
  ssr-smoke.js   十个场景的渲染冒烟测试
```

`src/game/` 下的文件完全不 import Vue，所以整个游戏内核可以在 Node 里无头跑完，
这也是 `npm run simulate` 能在一秒内跑完一千多局的原因。

## 音效

没有音频文件。钟声、木声、枪声、夜风都是用 WebAudio 现场合成的：
噪声缓冲做风与枪，正弦/三角波做钟与提示音。右上角的 `♪` 可以随时静音。
