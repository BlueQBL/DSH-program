# 三易 · 智能写作台

一张**绿格稿纸**，一支**朱笔**。

选一种写作模式，粘一段素材，一次给你几份不一样的稿子；
创意度和篇幅自己调；哪一段不顺眼，按一下就让朱笔把语法和表达过一遍，
每一处改动都标出来、能逐条采纳；所有成稿自动存进留档，随时翻回来。

零依赖：Node 原生 + 原生 HTML/CSS/JS，没有构建步骤，没有 `node_modules`。

---

## 1. 快速开始

```shell
cd writing-assistant
node server.js          # 或 npm start
```

打开终端里打印的地址（默认 <http://127.0.0.1:5260/>）即可。
按 `Ctrl+C` 停止。

**不配 API Key 也能用。** 没有 Key 时由内置的离线引擎成稿，六个模式、
多版本、朱批、留档全部可用（区别是文字质量：能看能改，但不如真实模型）。
想接真实模型，见第 6 节。

## 2. 需求与实现

| 需求 | 实现 |
| --- | --- |
| 支持多种写作模式 | **十个板块**：文章续写 / 内容改写 / 文案生成 / 邮件撰写 / 摘要提炼 / 大纲起草 / **学术论文 / 工作报告 / 小说创作 / 多语言翻译**。每个板块有自己的素材输入、专属参数、语气选项和版本角度 |
| 可调创意度 | 创意度滑杆 0–1.6，五档有名字：严守事实 / 稳妥 / 均衡 / 灵动 / 放飞，每档写明「会发生什么」 |
| 可调输出长度 | 短（约 200 字）/ 中（约 500 字）/ 长（约 900 字）/ 自定义（80–2000 字），按字数换算 token 上限 |
| 一键优化语法与表达 | 校对后**逐处朱批**：划线待删、朱字新增、右上角小号编号，右侧列出改动前后与原因，可**逐条采纳 / 还原**，也可一键全采纳 |
| 一次生成多个版本（批量） | **1–4 稿并行生成**，十个板块每个都有四个角度可用。多版本靠**换角度**拉开差别（不是只调温度），每稿的稿签上写明角度名 |
| 不同版本对比差异 | **对比两稿**：任选两样（原稿 / 任意一稿 / 润色稿）逐处标出增删，给出相似度、改动字数与全部改动清单 |
| 自定义提示词模板 | **模板库**：自己写提示词，保存后成为一个板块（我的模板），和内置板块一样能调参数、出多稿、进留档 |
| 多语言翻译 | **多语言翻译**板块：英 / 日 / 韩 / 法 / 德 / 西 / 俄 / 繁中或自填语言；四个角度是四种译法。任一稿上都有「翻译」按钮，一键把它递到翻译板块 |
| 生成内容存入历史 | 每次成稿自动写进留档；可搜索、按板块筛选、只看星标、改名、标星（免于被自动清理）、删除、导出 Markdown / 纯文本 / JSON |
| 可选模型 | 导航栏模型下拉框列出上游**所有能写字的模型**；启动时自动实测哪个可用，选中的模型只作用于自己（见第 6 节） |

## 3. 界面：两张实物拼出来的

视觉来自中文手稿里两件真东西：

- **绿格稿纸**——原稿写在一条条绿格线上，字压着线走；右下角是字数。
- **朱笔批改**——改动一律用朱砂标出。稿纸负责「写」，朱批负责「改」，
  所以**朱色只出现在改动、圈定与删除上**，日常按钮和强调一律用松绿，
  免得朱色被稀释成一种装饰色。

界面分四块（宽屏下左中右三栏，窄屏自动竖排）：

```
┌──────────────────────────────────────────────────────────────┐
│ 三易  智能写作台   [续][改][文][函][摘][纲]      离线引擎  留档 12 │
├──────────────────────────────────────┬───────────────────────┤
│  原稿（绿格稿纸）                      │  参数                  │
│  ┌────────────────────────────────┐  │  创意度 ──●─── 0.8 均衡 │
│  │ 把开头粘进来……                  │  │  输出长度 短 中 长 自定义│
│  └────────────────────────────────┘  │  一次几稿  一 二 三 四   │
│  共 328 字                [一键优化]  │  语气  平实 专业 亲切    │
│                            [ 起稿 ]  │  续写方向 顺着往下 ……    │
├──────────────────────────────────────┤                        │
│  朱批 · 第一稿     3 处  已采纳 2 处   │                        │
│  ┌────────────────────────────────┐  │                        │
│  │ 今天我们讨论了一次，大家都觉得  │  │                        │
│  │ 这个方案非常重要，需要尽快落实。│  │                        │
│  └────────────────────────────────┘  │                        │
│  ① 冗余 「进行了一次讨论」→… 「删」   │                        │
│  ② 标点 「,」→「，」          「标」   │                        │
├──────────────────────────────────────┴───────────────────────┤
│  ┌─第一稿·顺着语气─┐ ┌─第二稿·落到细节─┐ ┌─第三稿·收个尾─┐      │
│  │ 稿纸正文……      │ │ 稿纸正文……      │ │ 稿纸正文……      │      │
│  │ 812 字 [采用][一键优化][接着写][复制]                    │      │
└──────────────────────────────────────────────────────────────┘
```

几个具体的设计决定：

- **稿签**：原稿那格的稿签写着「小说创作 · 原稿」这样的**板块名 + 原稿**，一眼能确认自己在哪个板块；
  每张稿片左上角贴一张小纸条写着「第一稿 · 顺着语气」。稿次是真正的次序
  （第几稿就是第几次生成），不是装饰性编号。选中的那一稿，稿签会换成朱色。
- **角度而不是温度**：同一批的几稿用不同角度写——「顺着语气」「落到细节」「换个视角」
  「收个尾」。只调温度只会得到三份几乎一样的稿子，换角度才有得挑。
- **朱批可回溯**：划线保留原文而不是抹掉，能看出「原来写的是什么」；未采纳的建议
  用朱色虚线标出，采纳后才变成实线朱字。全部采纳的结果**必定**等于润色稿
  （由测试保证，见第 9 节）。
- **同一条格子线**：稿纸的行高、稿片的行高、朱批稿的行高都是同一个 CSS 变量
  `--rule-h: 28px`，绿格线正好落在每一行的下沿。

## 4. 怎么用

### 每个板块各自独立

**每个板块有自己的工作区**：原稿、成稿、采用稿、朱批、留档关联都是分开的。内置的十个板块按「写作 / 专业 / 创作与工具」分三组排在导航里，自定义模板排在第四组「我的模板」。
- 第一次进某个板块，原稿是**空的**（不会带上一个板块的内容，成稿也不会跟着串过去）。
- 切走再切回来，这个板块自己那份原稿与成稿会**原样装回来**——来回对照着改稿是常态
  （续写出来不满意 → 去改写试一遍 → 回续写接着调），每次清空会白丢一次工作。
- 想从头写，按 **清空**（原稿与成稿一起清，留档里的不受影响）。
- **参数不跟着板块走**：创意度、篇幅是你的偏好，切板块时保持不变；
  语气、一次几稿、以及各板块的专属设置（投放平台、收件人、摘要形态……）跟着板块走，
  因为它们是那个板块自己的事。

成稿后都会自动进留档，所以就算清空了工作区，稿子也还在留档里翻得回来。

### 起一稿

1. 顶上选板块（稿签单字：续 改 文 函 摘 纲 论 报 小 译；自己写的模板用你指定的那个字）。
2. 把素材粘进原稿（不知道怎么开头就点空稿纸下面的两条示例）。
3. 右栏调参数：创意度、篇幅、一次几稿、语气，以及该模式的专属项
   （文案要选投放平台、邮件要填收件人、摘要要选形态……）。
4. 按 **起稿**（或 `Ctrl/Cmd + Enter`）。

几稿会并行往稿纸上写，可以中途按 **停笔** 停下（已经写出来的部分留在稿上）。

### 挑一稿

每张稿片下面四个动作：

| 动作 | 做什么 |
| --- | --- |
| 采用 | 圈定这一稿（稿签变朱色），留档里会记下「采用了第几稿」 |
| 一键优化 | 对这一稿做朱批校对 |
| 接着写 | 把这一稿放到原稿上，改模式（比如换成「内容改写」）再来一轮 |
| 复制 | 复制正文到剪贴板 |

### 让朱笔过一遍

按 **一键优化语法与表达**（没有稿子时校对原稿，有稿子时校对优先稿）。
校对结果默认**全部采纳**，你可以：

- 在正文里看改动：朱字带底纹的是新增，朱色波浪线的是删去，虚线的表示「有建议但还没采纳」。
- 在下面的批注清单里逐条看「改前 → 改后 + 为什么」，点 **采纳 / 还原** 单独切换。
- **全部采纳** 会把结果写回原稿或那一稿；**全部还原** 一处都不改；**复制润色稿** 只取文字。

### 留档

右上角 **写作留档** 打开抽屉（`Esc` 关闭）：

- 搜索框搜标题、素材和正文；上面一排按模式筛选；右边「只看星标」。
- 点任意一条把它载回写作台（素材、参数、所有稿子、朱批状态一起回来）。
- `☆` 标星、`✕` 删除。
- 底部可导出：**Markdown**（带稿次与朱批小节，适合归档）、
  **纯文本**（适合直接粘）、**JSON**（适合搬家备份）。
  导出会带上当前的筛选条件，所以勾上「只看星标」时只导这几篇。

#### 星标是什么，不是什么

**不是置顶。** 留档一律按时间倒序（最近写的在最前），星标不会把稿子往前排——
这是有意的：星标一多，置顶就等于把时间序废掉，「我上次写的那篇在哪」反而找不到了。

**它是三件事：**

1. **留档清理时不会被删掉**（这是主要作用）：留档超过上限（本机文件留档 800 篇、
   浏览器本地留档 120 篇）时会从最旧的开始清，**星标的一律留住**。
2. **「只看星标」筛出来**：勾上就只列这几篇。
3. **导出范围**：勾着「只看星标」导出时，只导这几篇。

所以不勾那个框时，星标依然在干第 1 件事——它是「别被清掉」的保险，不是那个复选框的开关。

### 对比两稿

有稿子之后，成稿区顶上会出现一条工具行（写着「已出 N 稿 · 可对比的对象 M 个」），
点 **对比两稿**：

- 左右两个下拉框各选一样：**原稿 / 任意一稿 / 润色稿**（有什么就能选什么）。
- 正文以左稿为底：**右稿新增的用朱字标出，左稿被删的划掉**，带上改动编号——
  和朱批用的是同一套记号，也同一个差异引擎，所以「改了哪里」两处口径一致。
- 上面一行摘要给出：**几处不同、相似度百分比、新增与删改各多少字**。
- 下面列出全部改动（改前 → 改后）；可以 **左右对调**、**复制右边全文**、**收起**。

相似度是「没被改动的比例」的粗略指标（改掉的字数 ÷ 较长的那篇），用来一眼看出
「这两稿差多远」，不是编辑距离，不做精确承诺。

### 模板库

右上角 **模板** 打开（`Esc` 关闭）。模板 = 一段你自己写的提示词 + 几个说明字段：

| 字段 | 作用 |
| --- | --- |
| 模板名 | 成为板块名；必填，至少两个字 |
| 稿签 | 导航里那个单字（默认取名字第一个字） |
| 提示词 | **模板的核心**：你是谁、要写什么、不要写什么。它会**替代**默认的角色与任务说明 |
| 输出要求 | 这一段怎么写（可选，会进系统提示） |
| 素材字段名 | 空稿纸上那个输入框叫什么（默认「素材」） |
| 示例素材 | 空稿纸下面那两条可点的示例（一行一条，最多两条）。留空则从你的提示词里**自动推一个结构**，例如提示词写了「分进展、风险、下周计划三块」，示例就是「进展：…　风险：…　下周计划：…」 |

点 **给个例子** 会填一份「产品周报」的样例，改成你自己的就行。保存后：

- 它立刻出现在导航最右边一组 **我的模板** 里（带一个朱点标记），点进去就能用；
- 和内置板块完全同等待遇：四个角度（所以也能一次出 1–4 稿）、四种语气、
  创意度与篇幅可调、一键朱批、自动进留档、板块工作区独立、能对比两稿；
- 提示词里的「不要编造数据」这类要求会和平台自身的硬要求叠加，
  平台那几条（不要复述任务、不要编造可核查的事实……）不会被顶掉。

模板落在 `data/templates/`，一模板一文件；浏览器本地模式下存在 localStorage。

> **离线时不会执行自定义提示词。** 离线引擎没有语料可依，只会给一段说明，
> 告诉你接上模型才能用这个模板。接上真实模型后就是真正的自定义模板了。

### 多语言翻译

**多语言翻译** 板块（稿签「译」）就是普通板块，加两处便利：

- 参数栏里选 **目标语言**（英 / 日 / 韩 / 法 / 德 / 西 / 俄 / 繁体中文 / 其它自填）、
  **术语要求**（比如「把『抓手』译成 lever」）、**格式**（保留分段 / 合并一段 / 中对照）。
- 四个角度是**四种译法**：忠实直译 / 自然地道 / 本地化改写 / 保留语气节奏——
  一次出四稿正好当译法对比。

任一稿上都有 **翻译** 按钮：点一下会把那一稿放进翻译板块的原稿（目标语言与角度在那边选），
所以「先写中文再翻成英文」是一条顺路。

## 6. 接入真实模型

只认 **OpenAI 兼容协议**，所以 DeepSeek 官方、OpenAI 官方，以及
**OpenAI-HK** 这类聚合平台都能直接接（一个 Key 下挂很多家模型）。

```shell
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-xxxx"; node server.js

# macOS / Linux
DEEPSEEK_API_KEY=sk-xxxx node server.js
```

### 6.1 换平台：只改一个地址

| 平台 | `AI_BASE_URL` | `AI_MODEL` 举例 |
| --- | --- | --- |
| DeepSeek 官方（默认） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| **OpenAI-HK**（聚合多家模型） | 以平台控制台给的地址为准，通常形如 `https://api.openai-hk.com/v1` | `gpt-4o-mini` / `claude-3-5-sonnet-20241022` / `qwen-max` |
| OpenAI 官方 | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 自建 / 其它中转 | 你自己的地址 | 网关支持的模型名 |

```shell
# 接 OpenAI-HK 的样子
$env:DEEPSEEK_API_KEY="sk-xxxxxxxx"
$env:AI_BASE_URL="https://api.openai-hk.com/v1"
node server.js
```

### 6.2 启动时自动探测哪个模型能用

聚合平台的模型列表里常混着向量、语音、画图、审核模型，而 `AI_MODEL` 写的那一个
未必在你的账号下存在。所以**服务一启动就去问清楚**：

```
三易 · 智能写作台 已启动：http://127.0.0.1:5260/
  正在探测可用的上游模型……
  上游返回 213 个模型，其中可写字的 48 个
  模型 deepseek-chat 调不通：模型名或接口地址不对，请检查 AI_MODEL / AI_BASE_URL（…）
  已验证可用模型：gpt-4o-mini
  成稿方式：已接入上游模型，当前用 gpt-4o-mini
  上游地址：https://api.openai-hk.com/v1
  配置的模型：deepseek-chat（探测时发现调不通，已换）
  页面右上角可以随时换模型；探测结果有 5 分钟缓存
```

探测做三件事：

1. 拉一次 `GET /models`，**滤掉不能写字的**（embedding / whisper / tts / dall-e /
   moderation / rerank / sdxl / sora…），再按「适合写作」的顺序排：默认模型最前，
   其次是通用大模型（deepseek / gpt-4o / claude / gemini / qwen / glm…），最后按名字排。
2. 拿 `AI_MODEL` 加排名前两位做候选，各发一个 **1 token 的极小请求**实测。
3. 第一个调通的就作为当前模型。**认证、余额、限流是账号级问题**（401/402/403/429），
   遇到就停手不再试；**模型名不存在（404）或那个模型正好过载（5xx）**则继续试下一个。

探测结果缓存在进程里（列表 5 分钟），`GET /api/models?refresh=1` 可以强制重取。

### 6.3 页面上换模型

导航栏右上角有模型下拉框，列出所有**能写字的模型**，标出当前实测过的那一个。
选择会记住（刷新后还在），下一起稿与一键优化就用它。

两条规矩：

- **不偷偷换模型**。你在下拉框里选了 A，请求就只会用 A；A 挂了会明确报错让你换，
  而不是拿 B 的回答冒充 A。只有「你没选、由服务端挑」时才走默认。
- **选了列表里没有的**（下架了、换账号了），界面会说明「X 不在当前账号的可用模型里，
  已改用 Y」，而不是拿一个不存在的模型名去撞上游。

成稿后，每张稿片右下角会写明这一稿是哪个模型写的（例如
`1.2 千字 · 模型 · gpt-4o-mini`），留档里翻回来也认得出。

### 6.4 环境变量

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |

### 6.5 没有 Key，也想看真实模型链路长什么样

项目里带了一个**假上游**（OpenAI 兼容，故意做出一台「不好用的平台」的样子：
默认模型不存在、有一个模型永远 500、列表里混着向量和语音模型）：


打开写作台就能看到：启动探测把默认模型换成了可用的那个、右上角下拉框里
列出了能写字的模型、起稿真的是流式的、一键优化真的走 JSON 返回。
`test/upstream.test.js` 用的就是同一个套路。

**上游出问题时的兜底**：某一稿失败只影响那一稿，会退回离线引擎把它补上，
并在稿片上方说明原因（不会整批失败）；一键优化失败也会退回离线校对。
界面上不会假装成功。

## 7. 离线引擎：它做什么，不做什么

`lib/mock-writer.js` 是一个**模板 + 语料 + 规则**的写作引擎，
用来在没有 Key 时把功能演示完整。

它做这些：

- 六个模式各自的语料与结构（邮件有主题行/称呼/正文/敬语/落款；文案按五个平台排版，
  小红书带话题标签；摘要四种形态；大纲分级标题 + 每点一句说明）。
- 从素材里抽关键词、数字、专有名词，织进产出；同一素材的不同版本走不同角度。
- 确定性：同样的输入永远给同样的结果（随机性全部走种子随机数）。
- 一键优化走 **40 条中文校对规则**：冗余（「进行了一次讨论」→「讨论了一次」）、
  中英标点混用、连用标点、错别字（「截止目前」→「截至目前」、「做为」→「作为」）、
  程度副词堆叠等。

它**不**做这些（如实说明）：

- 不懂专业领域。医疗、法律、金融题材会显得泛。
- 文案走的是「选品 / 体验帖」口吻（挑什么、用了一个月怎么样、为什么留下它），
  不是硬广参数表；要参数、要资质，得自己补。
- 写不出真正的新事实。邮件里的「原因」句是通用说法（「准备时间比预计的长」），
  数字、人名、日期一律不编，需要你自己替换。
- 改写偏保守，是「换个说法」，不是「重写」。
- 摘要和改写是抽取式的：素材只有 300 字，产不出 900 字。
- **翻译做不了**：离线引擎不会翻译，它只会在稿纸上写一段说明，告诉你接上模型才能译，并把原文留下供对照。这不是占位符，是实话。
- **自定义模板执行不了**：模板的提示词要真实模型才认；离线时同样只给一段说明。所以这两个板块（多语言翻译、我的模板）离线时只有「流程能跑通」，没有「结果」。
- 校对有意保守：只改确凿的错，宁可漏改不误改（测试里有「干净原文一个字不动」的断言）。

把它当**演示与降级方案**，不要当真实模型用。

两条被测试钉死的不变量：

1. **朱批是完整可还原的**——全部采纳的结果必须逐字等于润色稿，一条都不采纳必须逐字等于原文。
   这条性质在服务端接口、前端渲染和本地模式三条路径上都被断言。
2. **参数进来必须被规整**——界面上拖的、URL 里带的、直接打接口的，都要过
   `lib/modes.js` 的 `normalizeParams`，非法值一律退回默认而不是传给上游。

### 为什么要做「接线检查」

原生前端最容易出的错不是逻辑，而是名字对不上：`$('#generete')` 少一个字母、
CSS 里 `var(--rule-h)` 忘了定义、`<script>` 顺序错了导致 `window.WriterCore` 是 `undefined`。
这些错在浏览器里的表现是「点了没反应」，排查起来很费时间。
`scripts/check-wiring.js` 把这类问题在读代码阶段就挡掉，不需要起浏览器。

## 11. 数据与隐私

- 留档写在 `data/history/<id>.json`，一稿一个文件；自定义模板写在 `data/templates/<id>.json`，同样一文件一份。写入都走「先写临时文件再改名」，断电不会留下半截 JSON。
- 留档最多 800 篇，超出后从最旧的开始清；**星标的不会被清**。
- 素材与成稿只在本机和你的上游服务之间流动，没有第三方统计、没有埋点。
- `data/`、`test/`、`node_modules/` 这几条路径在静态服务里被挡住（`403`），
  页面（或同机的其它程序）取不到留档原文；**服务端专用代码也一并挡住**——
  `server.js`、`lib/llm.js`（上游接入）、`lib/store.js`（留档落盘）都不给浏览器取，
  浏览器只拿得到它真正要跑的那几个共享模块（`modes` / `record` / `polisher` / `mock-writer`）。
- 留档是纯文本，随时可以 `rm -rf data/` 重来；界面上「清空留档」需要二次确认。

## 12. 无障碍与兼容

- 全部键盘可用，焦点有 2px 描边；`Ctrl/Cmd+Enter` 起稿、`Esc` 关闭抽屉。
- 抽屉关闭时同时设 `inert` 和 `aria-hidden`，不会让键盘 Tab 进到看不见的控件里。
- 成稿进度、错误提示都在 `aria-live` 区域里播报。
- 尊重 `prefers-reduced-motion`：打字光标与朱批落笔的动画都会关掉。
- 颜色对比：墨 `#1b2320` 在纸 `#f6f7f2` 上约 15:1；小号朱字用 `#8c2a1d`（约 8:1）。
- 字体只用系统自带：楷体（标题、稿签）、宋体（稿纸正文）、黑体（界面）、
  等宽（数字）。**不下载任何 web font**，断网也是这个样子。
- 打印样式已备：只留稿纸与正文，去掉参数栏、按钮和抽屉。

## 13. 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 当前成稿方式（真实模型 / 离线引擎）、当前模型、模式清单、留档篇数 |
| GET | `/api/models` | 模型下拉框的数据源：可写字的模型清单、默认模型、当前模型、上游总数；`?refresh=1` 强制重取 |
| GET | `/api/templates` | 模板库列表（含完整记录，浏览器用它注册板块），支持 `q` 搜索 |
| POST | `/api/templates` | 新建模板。校验不过返回 400 并指明是哪个字段 |
| PATCH | `/api/templates/:id` | 改模板（只传要改的字段） |
| DELETE | `/api/templates/:id` | 删模板（那个板块随即消失，旧稿仍在留档里） |
| GET | `/api/engine/test` | 验一遍上游：当前模型、是否实测通过、可写字的模型清单 |
| POST | `/api/generate` | 起稿。请求体 `{params, material, model?, template?}`，返回 **SSE 流**：`meta`(计划) → `delta`(逐字) → `done`(结果)。`template` 只在自定义板块用得上，服务端会按长度收口 |
| POST | `/api/polish` | 一键优化。请求体 `{text, model?}`，返回 `{before, polished, edits, stats, engine, model}` |
| GET | `/api/history` | 留档列表，支持 `mode` / `q` / `starred` / `limit` / `offset` |
| POST | `/api/history` | 存一篇 |
| GET | `/api/history/:id` | 取一篇（含全部稿子） |
| PATCH | `/api/history/:id` | 改名 / 标星 / 改采用稿 / 记朱批 |
| DELETE | `/api/history/:id` | 删一篇 |
| DELETE | `/api/history?confirm=1` | 清空（**必须带 `confirm=1`**） |
| GET | `/api/history/export?format=md\|txt\|json` | 导出，带上当前筛选条件 |

`/api/generate` 的 SSE 事件里，`delta` 带 `{version, text}`——多个版本并行推，
前端按 `version` 分派到各自的稿片上。`meta` 里带 `model`（这一批实际用的模型）
与 `modelNote`（模型被替换过的话说明原因）。

## 14. 已知限制

- **离线引擎的文字质量**：如第 7 节所述，能演示功能，不能替代真实模型。
- **没有对着真实平台端到端跑过**：开发机上没有 Key，所以真实链路是用
  `test/upstream.test.js` 里那个假的 OpenAI 兼容上游验证的（协议、SSE、JSON 返回、
  404/5xx 降级都覆盖了），但各平台在细节上仍可能有出入——
  真接上以后如果哪里不对，先看 `GET /api/engine/test` 的输出。
- **模型列表的取舍**：`/models` 给的是账号可调用的**全集**，其中某些模型可能
  并不适合长文写作（这里是按名字排序的启发式）。列表里那个一直 500 的模型照样会
  出现在下拉框里——它确实在你的可用列表里，只是当下不可用。
- **改写模式的篇幅**：改写不比原文长太多（有意为之），素材很短时到不了 500/900 字。
- **一次最多四稿**：版本数上限来自每种模式提供的角度数（3–4 个）。
- **朱批的行内标记是「你现在的文本」的视图**：采纳状态改变时，正文会重绘；
  如果你想把改动直接落到别处，用「复制润色稿」。
- **板块工作区在内存里**：刷新页面后只有「你当前所在板块」的原稿会留着重来（存在浏览器本地偏好里），其它板块的现场会清空——它们在留档里，不会被丢。这样也在一定程度上避免了「以为切过去是空的、实际上还留着上次的稿」这种困惑。\n- **多用户/登录**：没有。这是一个本机单用户的写作台。
- **留档不做云同步**：用导出 JSON 换机器。
