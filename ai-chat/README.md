# 对谈录 · AI 聊天助手

一个能真正对话的聊天页面：你问，它答，回答**一个字一个字写出来**；一轮轮聊下去它记得你前面说过什么；刷新、关掉再打开，这一页的字都还在。

可以同时开好几个话题（左边一列会话，互不串台），每个会话有自己的**角色**（编程助手 / 写作助手 / 心理咨询师……或者你自己写提示词）和**模型**；能用**语音**说，能贴**图片**让它看图回答；**回答里的一段可以划出来引用**,接着往下问；聊完可以**导出**成 Markdown / 纯文本 / JSON。

界面不做「聊天气泡」，做的是一份**对谈记录**：页边有序号，一条竖线把一问一答串起来，回答像稿件一样写在正文栏里，正在生成时那里有一道红墨光标在写。

零依赖：Node 原生 HTTP + 原生 HTML/CSS/JS，`npm install` 都不用。

## 七个主要功能

| 功能 | 怎么用 | 说明 |
| --- | --- | --- |
| **会话管理** | 左栏顶部两个并排按钮：「＋ 新对话」和「引用会话」；下面一个搜索框（按标题或正文找）；左栏切换、重命名、自动命名、删除、**置顶** | 每个会话各自保存消息、角色、模型；超过 50 个自动淘汰最旧的（**置顶的先不淘汰**）。列表分**「置顶」和「最近」两组**，两组各自能收起/展开（见下）。**进入页面默认开新会话**（**刷新是例外**：刷新时留在当前会话，免得正在生成的回答看不见）；切到已有对话时，自动开的那个空白会话会被清掉。标题由 AI 起（见下），你改过的名字不会被覆盖 |
| **角色 / 系统提示词** | 顶部「角色」下拉框；「系统提示词」可查看、可改、可收起 | 内置通用 / 编程 / 写作 / 心理咨询 / 学习导师 / 数据分析 / 翻译。**新会话一律从「通用助手」开始**，角色由你显式选择；回到旧会话时它自己的角色还在 |
| **语音输入** | 点「语音输入」开始，再点「结束」 | 用浏览器 Web Speech API；Chrome / Edge 可用，Firefox 不支持（按钮会直接说明原因） |
| **图片识别** | 「加图片」、直接粘贴、或拖进输入区 | 自动压缩到长边 1568px；**需要支持看图的模型**（见下） |
| **引用一段接着问** | 在回答里划中一段 → 点浮出的「引用这段」 | 引用的原文会挂到输入框上方，你补一句问题发出去；**引用跟着那一版提问走**，翻回旧页看到的还是当时引的那段 |
| **给回答打分** | 每条回答下面的「👍 有用 / 👎 没用」 | 点一下就算数；再点一次取消、点另一边改判；拉踩可以勾原因、补一句说明。评价跟着那一页保存，也写进服务端日志 |
| **压缩上文** | 会话变长后输入区的「压缩上文」 | 也可以自动：答完一轮后台压、太长时发之前先压。摘要顶替前面若干轮，**原始消息一条不删**，正文里留下一道看得见的标记 |
| **编辑并重新回答** | 提问右上角的「编辑」 | 改完可以「重新回答」或「只改不发」；**旧回答不会被覆盖**，改更早的那一页会生成新的一页 |
| **会话分支** | 每条回答下面的「分出新会话」 | 把「到这一轮为止」的对话**复制**到一个新会话（标题 `原标题-分支1`，还能再分支），**原会话一条都不动**，两边从此各聊各的。图片不复制、评价不复制（见下） |
| **会话引用** | 左栏顶部的「引用会话」按钮 | 把**另一个会话**的内容当**背景材料**：默认用它的摘要，也可以选 **1–3 轮的原文**（一问一答成对）。材料就地挂在**当前会话**上、从下一轮开始生效，也可以带着它另开一个新会话。材料不进消息，随时能看、能换、能删（见下） |
| **导出** | 底部「导出」，或左栏「导出全部」 | Markdown / 纯文本 / JSON / 复制全文 |

### 顶部是固定的

「对谈录」标题、收起会话列表的**图标开关**、模型框固定在页面顶部，不跟着正文滚走。

**这一条的高度从头到尾恒定**，往下滚也不会变矮，而且是**不透明的纯纸色**。
这两件事都是用户明确要求的：

- **高度恒定** → 会话列表的吸顶偏移（`top: var(--masthead-h)`）和高度上限都按报头高度算，
  报头一变，**会话列表就会跟着往上跳、还变高** —— 用户的原话是「正文翻滚，会话列表不该跟着联动」。
  以前有过「滚下去自动收窄、把空间让给正文」那版，为它还写过一整套防抖机制（滞回阈值、
  只在状态变化时写 DOM、故意不给过渡），最后整块去掉了：**正文滚，会话列表纹丝不动**，
  「在阈值附近整页抖」这件事也从根上不可能再发生。要更多正文空间，拖会话栏那条缝改宽度。
- **不透明** → 半透明 + 模糊那版会让正文的字**从标题下面透出来**（「字往标题那块区域翻出去了」）。

**报头的第一行分成两格，列宽和下面 `.board` 的列宽逐字一致**（左格对着会话栏、右格对着正文）：

```
┌─ 左格（＝会话栏宽）──────┬─ 右格（＝正文宽）────────────┐
│ 对谈录              [▤] │        [新对话] [模型框]     │
│ AI 聊天助手 · 多会话 · …  │                            │
└─────────────────────────┴────────────────────────────┘
```

于是这一行看上去就是**「会话栏的顶栏 + 正文的顶栏」**，而不是一条横跨整页的标题带：

- **开关钉在左格的右端** —— 也就是会话栏和正文之间那道缝的左边一点。
  ChatGPT 的开关也是贴着侧栏的边，而不是压在大标题前面。它用的是**绝对定位**（钉在这一格的 `right: 0`），
  脱离标题的宽度，所以标题字号怎么变、备用入口出不出现、正文怎么滚，**它都纹丝不动**。
- **右格贴右边缘**：收起时的备用入口在前、**模型框在后**。右对齐 + 模型框排最后，意味着模型框的
  右边缘是钉死的，备用入口从它左边长出来。
- 两格的列宽和那道缝**共用同一个 CSS 变量**（`:root` 里的 `--rail-w`），所以拖会话栏时两边一起动
  （`test/ui-tests.mjs` ⑭ 盯着这条）。

**新建会话在会话列表里**（列表最上面一个占满一栏的「＋ 新对话」）—— 新会话就是从那儿生出来的，
按钮放在它自己的地盘上最顺手，这也是 ChatGPT 的做法。**样式是描边的淡按钮而不是黑底实心**
（它天天在那儿，实心黑块在这一列里太抢眼）。列表**收起来**之后，报头会露出一个备用入口，
否则就没地方开新对话了。

收起 / 展开是个**图标开关**（内联 SVG 画的面板图标，收起时镜像一下指向列表在哪边），不是一行字；
没有文字，所以带 `aria-label` 和 `title`。**这个选择会被记住**（`localStorage` 的 `duitanlu.rail.v1`）：
宽屏上收起来，刷新之后还是收起的。窄屏（≤1000px）默认收起 —— 手机上这一栏有用，但得先把位置让出来。

**窄屏（≤1000px）报头也只剩一栏**，和 `.board` 用同一个断点：两边列数始终一致；
而且这时左右两格的对应关系不存在了，开关就回到标题旁边（钉在左格右端的话，它会变成孤零零挂在报头最右边）。

实现上三处必须注意，不然容易出问题：

- **报头要挡住下面的正文**，所以它有半透明背景 + 模糊。用纯色会把这一页的稿纸横格切得很生硬；模糊能让下面的字迹透出一层，又不影响读按钮。
- **浮层必须比报头高**，否则导出菜单会被压在下面。层级顺序：正文 1 → 输入区 2 → 会话栏 3 → **固定报头 4** → 导出弹层 6。
- 会话栏的粘性偏移跟着报头的**实测高度**走（写进 CSS 变量 `--masthead-h`），而不是写死数字 —— 字体、系统缩放、窄屏换行都会改变它的高度。

### 会话标题：让模型起，但你改过的名字说了算

标题分两步走，和 ChatGPT 的做法一致：

1. **本地先给一个**。第一次发消息时立刻算一个兜底标题（去掉「帮我」「你好」这类客套话和「看看」「解释一下」这类请求动词，只取第一句），侧栏任何时候都不会是空的，也不用等网络 —— ChatGPT 在模型标题回来之前侧栏里是「New chat」，这一步是我们比它多做的一点。
2. **答完第一轮再让模型换一个**。这是一次**独立的非流式小请求**（`POST /api/title`），把开头的一问一答交给模型，提示词要求「只输出标题、用同一种语言、中文 6–14 字、不要引号、不要句末标点」。它不拖慢正文：正文写完之后才发，失败、超时、离线都只是「标题保持本地那版」，不弹错误；失败的话下一轮答完会再试一次。

**两条硬规则：**

- **AI 起的标题永远不会覆盖你改过的名字。** 每个会话记着 `titleSource`（`none` / `fallback` / `auto` / `manual`），后台的**自动命名**只允许动 `fallback` 那一种。你自己改过名的会话，之后不管聊多少轮都不会被改掉。
- **想换个名字，点会话那行的「自动命名」。** 那是你明确要求，所以它可以覆盖任何来源（包括你自己重命名过的），并且会把**后来问过的那几件事**一起交给模型 —— 标题只描述开头是自动命名最常见的毛病，你的对话聊到第十轮时常常早就不是第一轮那个话题了。

另外三点：

- **离线模式不请求模型**，直接用本地算的名字（`fallback`）；接上模型后点「自动命名」即可补上。
- **老数据靠内容反推来源**：没有 `titleSource` 的旧会话，如果标题正好等于「按本地规则算出来的那个」，就认定是机器起的、可以被升级；对不上就认定是你改过的，绝不动它。
- **清空会话**会连名字一起作废，下一轮重新起。

**标题太长怎么办**（会话栏只有 292px，而标题上限是 60 字 —— 一行只放得下约 20 个汉字）：

| 机制 | 说明 |
| --- | --- |
| **一行 + 省略号** | 标题**只占一行**，放不下的部分在末尾收成省略号（`text-overflow: ellipsis`）。试过放宽到两行，实际不好看：行高参差不齐、列表被撑高、扫读也慢 —— 所以**不换行**，看全交给下面那一条 |
| **悬停看全文** | 鼠标停在那一行上（或键盘 Tab 到它）浮出**完整标题**的小卡片；**只在真的被截断时才弹**，没截断不弹（否则是噪音）。文字可以**选中复制** —— 所以鼠标离开后有 160ms 才收起，够移到卡片上 |
| **原生 `title`** | 每一行的标题都带原生 `title`：触摸屏、屏幕阅读器，以及浮层没跑起来的任何情况，都还有这个出口 |
| 位置会变就收起 | 列表一滚动、窗口一缩放、列表一重画，浮层立刻收起 —— 位置变了还留在原地会指错地方 |

**为什么是「悬停」而不是「点一下」**：会话行的点击就是**切到那个会话**（那是它的主要动作）。
把"点标题看全名"挂上去会和它抢 —— 点一下到底是切过去还是弹个卡片？所以看全名用悬停（还有键盘聚焦），
点击保持原样：切过去。

关于角色的几条约定：

- **新会话的角色是「通用助手」**，不继承上一个会话的角色 —— 角色的语义是「这个会话让 AI 扮演谁」，换话题就该重新选。**模型则相反**，会沿用上次选过的，因为那是「用哪个引擎」。
- **回到已有会话时，角色是那个会话自己的。** 会话 A 用编程助手、会话 B 用写作助手，来回切不会互相覆盖。
- **点「保存到本对话」不会改变你选的角色。** 在某个预设角色（比如编程助手）下只是看了看提示词就点保存的话，角色仍然是编程助手；只有你真的改了内容才会记录改动，而且角色名保持不变。想用完全自定义的角色，请显式在下拉框里选「自定义」。
- **只想看提示词**：展开后点右上角的 **×** 或底部的「收起」即可，不会写入任何数据。

代码块带**语法高亮**（关键字、字符串、注释、数字、函数名、类型名），支持 JS / TS / Python / Java / Go / Rust / Shell / SQL / CSS 及常见别名。高亮是**流式安全**的：代码写一半时该上色的照样上色，且不会把内容吞掉。

### 复制会给就地反馈

所有复制入口点下去都会有**眼前就能看到的**变化，不用去猜有没有成功：

| 位置 | 反馈 |
| --- | --- |
| 代码块右上角「复制代码」 | 按钮变成**深绿色「已复制」**，1.6 秒后复原 |
| 回答下方「复制回答」 | 变成**绿色「✓ 已复制」** |
| 导出菜单「复制全文」 | 菜单项整行变绿并显示「已复制」 |
| 复制失败时 | 按钮变**暗红「复制失败」**，停留 4 秒（比成功更久，好让你来得及手动选中） |

同时底部提示条也会说明复制了什么 —— 就近看不到时还有第二层反馈。

配色上有个刻意的取舍：**成功用绿、失败用暗红，都不用页面的红墨**。红墨在这一页的语义是「问」标和「正在写」，拿它表示「复制成功」会让人以为出了什么事。颜色变量定义在 `styles.css` 顶部（`--success` / `--failure`）。

三种按钮（代码块、链接式按钮、菜单项）复用同一套状态类（`is-copied` / `is-copy-failed`），所以以后新增复制入口只要调 `copyWithFeedback()` 就自动带上反馈。

### 编辑并重新回答（分页）

对已经不理想的提问，把鼠标移到那条提问上会出现「**编辑**」：

- **重新回答** —— 用改后的内容再问一次，**每次都会新增一页**。原来那一页原样保留，
  所以「本次生成的内容」和「上一次生成的内容」都在，可以来回对比。
- **只改不发** —— 只把文字改掉，不触发回答。
- 多页之后，提问下方出现页码（**第 1 / 2 / 3 页**），点数字即可来回切换查看。

编辑框里会提前写明这一按的后果：**「将生成第 2 页，当前这一页会保留」**。

**发给模型的上下文是完整的**：编辑过的提问，它之前每一版以及各自得到的回答都会按顺序带上。
否则模型会看到「我问了 A，它答了 B，然后我又问 B」这种自问自答，回答就会跑偏。

**改的是更早的那一问时，只发「到那一问为止」的上文。** 会话里那一问之后还挂着旧那条线的轮次
（我们永远不删消息），但它们跟这次要回答的问题不在同一条线上，所以不跟着发出去。
这同时是服务端的**硬契约**：请求必须以一条 user 消息结尾 —— 把那些轮次也带上，请求就会以
一条回答结尾，服务端直接 400，界面上只会显示一句看不懂的报错。这件事有专门的断言守着
（`store-tests` 的「请求历史 · 最后一条必须是 user」和 `ui-tests` 第 ⑬ 节里对**真实请求体**的检查）。

**「重新生成」和「编辑后重新回答」是两个不同动作**，别混：

| 动作 | 输入 | 结果 |
| --- | --- | --- |
| 重新生成 | 不变 | 原地替换这一页的回答，**不新增页** |
| 编辑后重新回答 | 改了 | **新增一页**，旧页保留 |

### 引用一段回答，接着问

长回答里总有一两句是你真正想追问的。这时不必把那段话复制出来再贴进输入框 —— **在回答里划中它**，选区旁边会浮出一个「引用这段」：

- 点它，那段原文就挂到输入框上方（带「引」标和出处），底下接着打你的问题，回车发出。
- 引用的原文会随这一轮一起发给模型，包成 **Markdown 引用块**（`> …`）并标出引自第几页 —— 模型看到的是「这是转引的原文」，不会误当成你自己说的话。
- 挂错了点引用条右边的 **×** 取消；只引用还没打字时不会误发（发送按钮仍是灰的）。
- **引用只认回答那一侧**：划自己的提问不会出现这个按钮 —— 「引用」的语义是「引用它说过的话」。

两条和数据有关的约定：

- **引用跟着那一版提问走**。你翻回「第 1 页」看到的，就是当时引的那一段，而不是最新一版引的内容；编辑重发时新一页继承同样的引用（你改的是文字，不是「引了哪一段」）。
- **库里存的仍然只是你打的那句话**。引用是单独一个字段，只有发给模型时才拼进正文。导出时它也不会被混进 `content`：Markdown / 纯文本里以引用块呈现，JSON 里是独立字段 —— 少了这个区分，导入方就再也分不清「用户说了什么」和「他引用了哪一段」。

引用正文最多带 **1200 字**（超出截断，界面上会写明「过长，只带上前面一段」）：它是整段重复发送的，既进这一轮请求体，也留在历史里跟之后每一轮走。

### 给回答打分：赞 / 踩 + 意见反馈

每条回答下面都有 **👍 有用** 和 **👎 没用**（鼠标移到那条回答上就会出现，最新那条一直显示）。做法参考 ChatGPT，但有三处刻意做得不一样：

1. **点下去就算数**。点赞或拉踩本身就是一次完整反馈，不需要再填任何东西 —— 下面那个补充框是可选的。
2. **点错了能改**。再点一次同一个按钮＝取消，点另一边＝改判（ChatGPT 点下去就改不了，社区里为这点抱怨了很久）。每次变化都会往服务端追加一条事件，所以日志里始终看得出「他最后到底是赞还是踩」。
3. **拉踩时给一排原因**：事实有错 / 没按我的要求来 / 该答的没答全 / 不该拒绝却拒绝了 / 太啰嗦 / 其他（对应 ChatGPT 那套选项），可以多选，再加一句自由说明。点赞不再多问一层，只留一个可选的说明框。

**评价跟着「页」走**：一条回答可以有多页（编辑重发而来），第 1 页点了赞，切到第 2 页看到的是它自己的评价。**重新生成会清掉那一页的旧评价** —— 它评的是已经不存在的文字。

评价存在两处，各有各的用处：

- **浏览器里**（`localStorage`，跟着那一版回答）—— 刷新、重开都还在，界面上那个按钮保持着选中态，导出时也会带上。
- **服务端 `data/feedback.jsonl`** —— 一行一条 JSON 的**追加**日志。之所以追加而不是覆盖：评价要能改，日志就得留住改的过程。每条记下档位、原因、说明、模型、以及**答案开头的一小段**（只记「用户点了踩」而不知道踩的是什么，那条日志没有意义）。

服务端写不进去时不会假装成功：本地照样记下，同时明确提示「评价已留在本机，但没能交给服务端」。

### 会话变长之后：压缩上文，而不是悄悄忘掉

对话一长，模型能看到的上下文就有上限。**这里不会偷偷把开头丢掉**（那是 ChatGPT 的做法：
它不告诉你「这轮太长了」，你只会发现模型把开头忘了，而且没法查）。这里做的是**看得见的压缩**：

- **自动压**：会话体量过了软线（约 1.6 万字）之后，会在**这一轮回答写完**时后台压一次 ——
  不挡你，下一轮开始模型看到的就是摘要；体量过了硬线（约 3.2 万字）时，**发之前先压**（界面会说明「正在压缩…」）。
- **手动压**：输入区会出现「压缩上文」按钮，点了立刻压；已经压过一次的话它是「再压一次」，会把范围往下扩。
- **看得见**：正文里会留下一道标记 —— 「⌁ 以上 6 条已压缩成摘要 · 约 120 字」，
  「查看摘要」能展开**模型实际看到的那段文字**，「取消压缩」则恢复成发送完整上文。
- **原始消息一条都不删**。压缩只改「发给模型的那一份」：localStorage、界面、导出始终是完整的对话，
  导出里另外注明「这个会话压缩过 + 摘要原文」。

**四个数字，各管一件事**（都在 `public/lib/compress.js` 顶部，想调就调一个数）：

| 数字 | 值 | 管什么 |
| --- | --- | --- |
| `SOFT_LIMIT_CHARS` | 16000 | 未压缩部分过这么大 → **答完这一轮后台压** |
| `HARD_LIMIT_CHARS` | 32000 | 未压缩部分过这么大 → **发之前先压**（这一轮会等它） |
| `MIN_COMPRESS_CHARS` | 2000 | 自动压：可压的部分少于这么多就不值得压 |
| `MIN_COMPRESS_CHARS_MANUAL` | 1200 | 手动压：门槛低得多（用户都点了，能省下就干） |
| `KEEP_RECENT` / `KEEP_RECENT_MANUAL` | 6 / 2 | 保留最近几条原文：自动留 6 条，**手动只留最后一轮** |

所以「聊天到 2000 字才压」是误会：**2000 是「值不值得压」的下限，而且只算「可压的那部分」**
（最近 6 条不算在内）。真正触发自动压缩的是 1.6 万 / 3.2 万字。手动按钮则宽松得多：
**攒够约 1200 字**（大概两三轮实在的内容）就会出现，点一下立刻压 ——
按钮不出现，就说明确实还没有值得压的东西（连最后一轮之外的内容都不到 1200 字）。

压出来的摘要是这样发出去的（作为一条 system 消息，排在你的角色提示词之后）：

```
【较早对话的摘要】
（这是本次对话前面部分的压缩摘要，细节已省略。需要时可以请用户复述。）
用户在做「对谈录」项目，已经决定用零依赖方案；API 用的是 OpenAI 兼容接口……
```

提示词要求保留**事实、已做的决定、你的偏好、未解决的问题，以及代码与专有名词原样**，
只丢寒暄和重复确认。**再压一次会把上次的摘要一起带上**，所以是越压越紧，而不是把上一次扔掉重来。
压缩失败（上游挂了、离线模式）不影响说话：继续用原文发，服务端还有一层兜底裁剪。

### 正文只画最近 20 轮：更早的按需补

一个会话可以聊到几百轮，而正文是**整段重画**的：每条回答都要建一个完整节点（评价、编辑、版本条、
引用、页码都在里面）。会话越长，问题不只是「打开慢一下」，而是**每一次交互都慢** ——
点个 👍、翻一页版本、切一次会话，那几百个节点都要重新建一遍。所以：

- **默认只画最近 20 轮**，正文顶上有一条「**更早的 20 轮**」；点一下往前补 20 轮；
- **滚到最上面也会自动补**一段（只在顶部附近，页面中间滚动不会凭空补历史）；
- **补历史时视口不动**：往上插进去多高，就把视口往下挪多高 —— 你正在看的那一行待在原地；
- **轮次编号永远是全局的**（第 41 轮就是第 41 轮），不因为窗口从哪儿开始而改口 ——
  引用面板里勾的、导出里写的都是这个号；
- **展开状态不持久化**：刷新、切走再回来，都回到最近 20 轮（按会话复位）。

**只有「画哪些」分页，数据一条都不少**：请求历史、导出、压缩摘要、引用「原文」档、分支复制读的
都是**全部**消息 —— 分页不参与「有什么」。压缩标记同理：界线落在窗口上方时它挂在窗口顶上
（「以上 N 条已压缩成摘要」说的还是实话），界线那一轮画得出来时就紧跟在那条回答后面。

### 三块区域各占各的：会话列表 / 会话详情 / 输入区

版面是**两栏**，而且这三块互不共享空间 —— 会话开到几十个也不会挤到输入框：

```
┌ 报头（吸顶）：第一行分成两格，和下面两栏对齐 ──────┐
│ 对谈录                [▤] │ [引用会话][新对话][模型框]│
│ AI 聊天助手 · 多会话 · …   │  ↑ 只在左栏收起时才出现 │
├──────────────────────────┼───────────────────────┤
│ [＋ 新对话][引用会话]      │ 角色 / 模型 / 系统提示词 │
│ 会话                 12  ├───────────────────────┤
│ 置顶               2  [▾] │ 会话详情（正文，随页面滚）│
│   （置顶的会话行…）       ├───────────────────────┤
│ 最近              10  [▾] │ 清空确认条（就地）       │
│   （其余的会话行…）       │ 输入区（吸底）          │
│ 导出全部                  │                       │
└──────────────────────────┴───────────────────────┘
```

（「引用会话」「新对话」这两个备用入口只在会话列表收起来的时候出现在报头，平时藏起来 ——
免得同一件事摆两个入口。报头左格里的 `[▤]` 是收起/展开开关，它钉在与会话栏同宽的那一格右端。）

- **左栏**：最上面是**两个并排的按钮**（「＋ 新对话」和「引用会话」），下面是会话列表 ——
  列表再分成**「置顶」和「最近」两组**，每组自己有一个收起/展开按钮（见下一节）。
  列表有高度上限、在**自己那一格里滚动**（滚到头也不会把整页带着滚），所以会话再多也不会把页面撑高。
  **这一栏的宽度可以拖**（见下）。
- **右栏**：角色与模型设置、会话详情、清空确认条、输入区，从上到下依次排列。

**会话栏宽度可以拖**（宽度记在本地，刷新之后还在）：

| 操作 | 效果 |
| --- | --- |
| 拖会话栏右边缘 | 改宽度。200–460px，而且**正文至少留 640px** —— 拖过头就停在边界上，不会把对话挤成一条 |
| 双击那条缝 | 回到默认宽度 292px |
| 键盘：`←` / `→` | 各 8px（`Shift` 加大到 24px），`Home` / `End` 到最小 / 最大（手柄是个按钮，Tab 能聚焦） |
| 窄屏（≤1000px） | 单列布局，没有「那道缝」可拖 —— 手柄藏起来，JS 也拒绝开工 |

实现上的两个要点：**宽度只写一个 CSS 变量 `--rail-w`**，报头第一行和正文两处栅格都用它 ——
以前是两处各自写死 292px，改一处忘一处是必然的（收起/展开开关就钉在那道缝上，一错位就对不准）；
**手柄钉在会话栏里、从报头下面开始** —— 报头那一行左格的右端已经钉着「收起/展开」开关了，
两个东西压在同一条缝上会抢点击。

**宽度的账：正文和输入区共用同一条版心**（这一节是「正文甩出版心、输入框比正文宽」那两处修好之后立下的规矩）：

- **正文的版心是 760px，写法是「有上限、可收窄」**（`grid-template-columns: var(--margin-col) minmax(0, var(--text-col)) 1fr`）：
  宽裕时它就是 760px（一行 30 来个汉字），装不下时（会话栏拖宽、窗口变窄）**按可用宽度收窄、文字换行**。
  以前那两条轨道是固定宽度，一装不下就**横向溢出**到版心外面 —— 看起来就是「正文甩到报头那块区域外面」。
- **输入区跟正文同一条版心**：左边对齐正文栏、宽度不超过正文栏。主流那几家（ChatGPT / Claude）的输入框
  和消息流本来就是同宽、同一条中线 —— 输入框比正文宽一大截时，读的人和写的人眼睛要在两个宽度之间来回换。
- **页宽公式跟着会话栏走**：整页宽度用 `var(--rail-w)`（不是写死的 292px），所以**拖宽会话栏 = 整页变宽**，
  只有视口真不够时正文才开始收窄。写死 292px 时，拖宽会话栏等于直接从正文身上割肉。
- **会话栏拖拽的上限跟「正文还能读」挂钩**：正文至少留 640px（以前是 320px，那时一行只剩十来个汉字）。
- 断不开的长串（URL、一长串英文/代码）按字符换行，不许把版心撑破；输入区那一排按钮会换行，不横向挤出去。

**这几条以前为什么是坏的（数字账）**：正文需要 `84 + 24 + 760 + 24 = 892px`（页边栏 + 缝 + 正文栏 + 又一道缝），
而默认宽度下页宽只给得起 `1176 − 292 − 28 = 856px` —— **差 36px**。也就是说默认宽度下就已经在溢出了，
拖宽会话栏只是把它放大到两百多像素。现在这 36px 由「正文可收窄」+「页宽跟着会话栏涨」两件事一起兜住。

- **输入区在右栏内部**（不在 `.board` 外面）：它和会话列表各占一列，
  所以会话再多也碰不到输入框 —— 列表撑得再长，也只是在自己那一格里滚。
- **窄屏**（≤1000px）：会话列表变成正文上方的一段（高度上限 210px），不再是独立一列；
  这也是「不重叠」的另一种形式 —— 它是让开位置的独立一行。
- 新建 / 切换到某个会话后，会把那一行**滚进可视区**：列表很长时不做这件事的话，
  刚建的会话可能停在看不见的地方，看起来像「点了没反应」。

### 会话列表：置顶 / 最近，两组各自收放

列表分两组，布局参考 ChatGPT：

```
[＋ 新对话] [引用会话]   ← 两个并排的按钮，永远在，不归任何一组管
[搜索会话（标题或正文）]  ← 有输入时列表切成平铺的「搜索结果」
会话            12
置顶          2 ▾      ← 组标题：左边是名字，右边是条数和收起/展开
  会话行…  3 分钟前
  （鼠标停在这一行上 → 3 分钟前 原地变成 ⋯）
最近         10 ▾      ← 这一组默认只画 6 个
  会话行…  昨天
显示全部（还藏着 4 个）   ← 纯显示开关，不是「滚到底再加载」
导出全部
```

**行尾那一小块有两副面孔**：平时是「**这个会话多久没动了**」（`3 分钟前` / `昨天` / `2 周前`），
鼠标停在那一行上（或键盘聚焦）就**原地换成「⋯」**——置顶 / 重命名 / 自动命名 / 删除都在它打开的菜单里
（「重命名」是你自己敲一个，「自动命名」是让模型按现在的对话重新起一个）。

| 细节 | 说明 |
| --- | --- |
| 分档 | `刚刚` → `N 分钟前` → `N 小时前` → `昨天` → `N 天前` → `N 周前` → `N 个月前` → `N 年前`（**不出现日期**：日期会把这块撑宽，而宽度必须固定） |
| 为什么宽度固定（52px） | 两副面孔是**重叠**在同一个槽位里、都右对齐。要是各占各的宽度，鼠标一停上去标题的可视宽度就变了、省略号位置跟着跳一下 —— 很扎眼 |
| 算哪个时间 | **最后活动时间**（`updatedAt`），不是创建时间。所以刚发过消息的会话立刻回到「刚刚」 |
| 会自己刷新 | 每 30 秒刷一次（页面不可见时不干活），回到这个页面时也刷一次 —— 挂久了不会一直显示「刚刚」 |
| 触摸屏 | 没有 hover，「⋯」常显，时间藏起来（两个都露会叠在一起） |

**为什么行尾只放一个「⋯」**（而不是四个文字按钮）：以前四个按钮是**常驻**排着的
（只做了 `opacity: 0`，视觉上藏起来了，**宽度照占**），292px 的行里被吃掉约 145px，
**标题只剩六七个字**。收进菜单之后整行宽度都归标题（现在再让给时间 52px，约 16–17 个汉字）。

菜单的几个约定（和「完整标题」浮层同一套纪律）：同时只开一个；点条目 / 点外面 / `Esc` /
列表滚动 / 窗口缩放 / 列表重画都收起；它是 `position: fixed`（会话列表是 `overflow-y: auto`，
`absolute` 会被裁掉），位置按「⋯」算，贴到视口下边就翻到上面。

- **置顶**：点行尾的「⋯」→「置顶」（已经置顶的写着「取消置顶」，再点一下就回到「最近」）。
  **没有置顶的会话时，这一组连标题都不显示** —— 不摆一个空的「置顶」在那儿占地方。
- **组里怎么排**：仍然按最近使用排。置顶决定的是「在哪一组」，不是「组里的第几名」；
  置顶也不会改 `updatedAt`，所以会话行上那个时钟不会莫名其妙跳一下。
- **两个收起按钮，管的是两件不同的事**：
  - 组标题右边的 **▾** 只收这一组的**会话行**，「置顶」「最近」这两个标题和条数**一直都在**；
  - 报头那个 `[▤]` 收的是**整栏**（连标题一起）。
  两者互不影响，也都不影响「＋ 新对话」—— 它在两组之外，怎么收都开得了新会话。
- **收起来只是不显示**：会话行照常在、照常切换，只是不占地方；组标题上的条数告诉你里面还剩几条。
- **搜索**（左栏顶部那个框）：按**标题或正文**找会话，中英混排也认（大小写不敏感）。
  正文**连编辑过的旧版本一起搜**（提问改过、回答重新生成过，那些文字都还在）—— 只搜当前显示的那一版，
  会出现「我明明写过却搜不到」的情况。命中的那一段会摘在结果行下面。
  有输入时列表切成平铺的「搜索结果」：分组让位，也不受「只显示 6 个」的限制；**一个都没命中就说一句
  「没有匹配的会话」**，不给一个空列表。清空（或按 `Esc`）就恢复原样 ——
  搜索**不改任何数据**，也不动你的分组收起状态，输入框本身也不持久化（刷新回来是干净的）。
- **「最近」这一组默认只显示 6 个**：排在第 7 个以后的收在「显示全部（还藏着 N 个）」后面，
  点开就全画出来，再点一下收回去（这个选择记在本地）。它是**纯显示开关**，不是「滚到底再加载」：
  数据一直全在内存里，分组标题上的条数永远写**真实条数**（跟画出来几行无关）。
  **当前会话永远在列** —— 哪怕它是最老的那个；不然刷新之后你会看到自己正待着的会话不在左栏里，像丢了。
- **「置顶」那一组不裁**：用户明确说过重要的东西，不用藏在「显示全部」后面。
- **挪组的时候自动展开**：置顶 / 取消置顶会把会话挪进另一组，那一组要是正收着就先展开 ——
  否则点一下看起来像「这个会话不见了」。
- 收起状态和「显示全部」都记在本地（`duitanlu.railGroups.v1`），刷新之后还是你离开时那个样子。
- **淘汰不会先淘汰置顶的**：会话超过 50 个要腾位置时，先淘汰没置顶里最旧的；置顶的排在淘汰队列的最后。

### 会话分支：从某一轮分出一个新会话

聊到一半想换条路走，又不想丢掉前面几十轮攒下来的上下文 —— 每条回答下面都有一个「分出新会话」：

```
（第 1 轮）… （第 2 轮）… （第 3 轮）…
                              └─ 点这里的「分出新会话」
                                   ↓
   新会话 = 到第 3 轮为止的全部内容（它自己的副本），标题「原标题-分支1」
   原会话 = 一个字节都没动，想继续往下聊也行
```

- **点哪一轮就从哪一轮分**（和 ChatGPT 的 Branch in new chat 一致）：从中间那条分，就只带「到它为止」的内容，它后面的轮次留在原会话里。
- **原会话永远不动**。分支拿到的是副本，从此两边各聊各的 —— 也就是说，分支看不到原会话后来聊了什么，原会话也看不到分支里的。
- **可以一直分下去**：在分支上再分支，标题自然接成 `原标题-分支1-分支2`。同一个源会话的第二个分支叫 `-分支2`，删掉中间那条之后新建的也不会重名。
- **带什么、不带什么**：角色、系统提示词、模型、压缩摘要跟着走；**图片一律不带**（图片是 base64，复制一份就是真的多占一份本地空间），**👍/👎 也不带**（那是对原会话那几页的评价）。没带过来的图片有几张，会在会话顶部如实写清楚。
- **分支会话在列表里行首带一个 `↳`**，正文区顶部有一条说明写着「分支自《X》」，点「回到那个会话」跳回去；源会话要是被删掉了，说明里会写「原会话已删除」—— 因为出处是**快照**，不是活引用，源会话怎么样都不影响分支自己。
- **正在生成的时候不能分**（那一轮还没定稿，复制过去的是半截），会提示等这一轮结束。

**它和「编辑 → 重新回答」是两件事，谁也替代不了谁：**

| | 在哪儿发生 | 时间线 | 旧内容 |
| --- | --- | --- | --- |
| 编辑 → 重新回答 | **同一个会话里**，针对某一问 | 不岔开：后面的轮次共用 | 旧页永远保留，新版**追加一页** |
| 分出新会话 | 跨会话，从某一条回答分出去 | 岔开：两条线各自独立长 | 原会话一条不动，分支拿的是副本 |

而且两者是**接力**的：在一个「编辑重发过」的会话上分出分支，会把它的一问两版**一起带过去** ——
在新会话里翻回第 1 页，看到的还是当初那一版（`test/ui-tests.mjs` ⑰ 的最后两条断言守的就是这条）。

### 会话引用：把另一个会话当背景材料

手边要有**另一个会话**的内容 —— 左栏顶部的「引用会话」（和「＋ 新对话」并排）：

```
选一个会话  →  选材料形式  →  （原文档时）勾 1–3 轮  →  在这个会话里生效
                                                        （或者：带着它开一个新会话）
```

**两种用法，判据是同一条：材料是「这个会话」的背景。**

| 用法 | 什么时候用 | 结果 |
| --- | --- | --- |
| **在这个会话里生效**（主按钮） | 正在聊的会话里，这一轮突然需要另一个会话的内容 | 材料挂到**当前这个会话**上，**从下一轮开始生效**；前面对话照旧在上下文里，消息一条不动 |
| **带着它开一个新会话**（次要入口，会话里已经聊过时才出现） | 想开个新话题，只是手边要有那个会话的内容 | 复制一份材料到新会话，当前会话一个字不动 |

两种都**不会**动别的东西：材料不进消息、不进导出正文、不占压缩下标；已经答过的轮次一个字不变
（前一份材料答过的那些轮次，内容早就落成本会话自己的消息了 —— 所以「先后各带一份」也能达到
同时用两个会话内容的效果，这也是不做「一个会话带多份材料」的理由：那正是要避开的隐形引用链）。

**它们都摆在输入区那一边**（不是正文最上面）：材料条在**输入区里面**、引用面板在输入区**正上方**。
输入区是贴底（`position: sticky; bottom: 0`）的，所以材料条**永远在眼前** —— 存量会话聊了几十轮，
也不用手动翻回开头去看「这一轮到底带没带上材料」；面板打开时还会被滚进可视区，
否则长会话里从底部点开会一点反应都看不见。分支出处（`branch-note`）**没有**跟着搬：
它说的是「这条线从哪儿来」，属于正文的开头。

**列表收起时也够得着**：收起左栏后，报头会同时露出「引用会话」和「新对话」两个备用入口
（引用在前、新对话在后 —— 这样新加的按钮不会把已有的「新对话」挤走）。两处做的是同一件事，
所以**长得也一样**（都是按钮）：同一件事在两个地方长两个样，会让人以为是两个不同的功能。

- **两种材料形式**：
  - **摘要**（默认）：整段会话压成一段摘要（不限轮数），也可以只压你勾的那几轮 —— 复用压缩那套机器和 `/api/summarize`；
  - **原文**：把勾中的**一问一答原样照搬**，**最多 3 轮**。
- **面板上显示的就是实际会做的**：材料形式下拉框的值由草稿决定（重开面板会回到默认那一档），
  状态行永远和它说同一档 —— 显示「原文」就一定走原文，显示「摘要」才会去调模型。
- **一个会话一份材料**：材料是**这个会话**的背景，能被「改选轮次」改、被「移除材料」清。
  所以三个入口（左栏「引用会话」、报头备用入口、材料条上的「改选轮次」）做的是**同一件事**：
  这个会话已经有材料时，打开面板就是**接着改它**（来源会话 / 材料形式 / 勾选的轮次都预填好）。
  面板顶上总会写明这一按的后果：**一个会话只带一份材料，所以确认会替换它（旧的那份就没了）**；
  主按钮也跟着改口成「替换这份材料」。
- **为什么不做「一个会话带多份材料」**：换材料只影响**之后**的轮次 —— 前一份材料答过的轮次，
  内容已经落在这个会话自己的消息里了（这也是「已经答过的轮次一个字不变」那句话的意思），
  所以「先后各带一份」就能达到同时用两个会话内容的效果；而把多份材料并排堆着，
  正是这个功能当初要避开的那条路（引用悄悄长成一条隐形引用链）。
  「分出新会话」帮不上这件事：分支复制的是**对话和摘要**，材料不在复制范围内。
- **`改选轮次` 会把上次勾的带回来**：材料上记着「这份是从哪几轮来的」，点回去时勾选框、材料形式、
  源会话都拨回原样（摘要档也记：它虽然不限轮数，但「压的是哪几轮」同样要写下来，否则一改选
  范围就被悄悄放大成整个会话）。
- **为什么原文有 3 轮上限**：这不是随便定的数字，它是「引用」和「分支」的分界线 ——
  引用是**参考资料**（手边放着），分支是**把整段搬过去接着聊**。超过 3 轮就该去用「分出新会话」。
  界面上会在你勾到第 4 轮时**当场说清走不通**，而不是让你白点一次再看报错。
- **材料是背景知识，不是「你们聊过」**：材料正文外面包了一层说明（「这是用户提供的背景资料，供参考用。
  它不是你和用户现在这段对话的一部分」），所以模型会把它当参考资料，不会接着它往下说。
- **它不进这个会话的消息**：只在发请求时拼在最前面一条 system 里（排在角色提示词之后、本会话摘要之前）。
  所以导出正文、压缩下标、消息条数、置顶分组全都不受影响 —— **随时能查看、能改、能删**；
  删掉之后只是下一轮不再带上，**已经答过的轮次一个字不变**。
- **材料是快照**：建立时把正文抄一份存在当前会话上。源会话之后被改名、被删掉、被清空都不影响它，
  标注里会写一句「原会话已删除」；源会话没了之后再点「改选轮次」，面板会落到列表里第一个会话，
  并且**把上次勾的轮次一起清掉**（那些轮次号属于那个已经不在的会话，照勾过去就是一份对不上号的材料）。
- **引用取的是「最新那一页」，而且这件事写在明面上**：某一问被编辑重发过多次时，材料和这个会话的
  请求历史一样取**最后一页**（旧页是留给对比看的，不是「当前的样子」）—— 这是正常用法，不是取舍：
  想连旧页一起搬走，用「分出新会话」（那个是把整段历史复制过去）。
  不藏着：面板的轮次后面标着「N 页」，材料里会写一句「第 2 轮原先有 3 页，这里给的是最后一页」，
  所以「查看材料」看到的和实际发给模型的是同一份，也能一眼看出它取自哪一页。
- **离线时降级**：摘要档要调模型，离线用不了 —— 界面会**当场说明**并让你改成「原文」档（它不需要模型），
  不会转圈、也不会静默失败。材料有长度预算，超了会明确拒绝并给出替代方案，**绝不静默截断**。
- **导出会如实交代**：JSON 里材料是一个单独字段（`reference`），Markdown / 纯文本里是一段附注 ——
  「模型看过它」这件事必须留在记录里，但它不算对话正文。

**三条线各管一段，互不替代：**

| 概念 | 在哪儿发生 | 时间线 | 旧内容 |
| --- | --- | --- | --- |
| 编辑 → 重新回答 | **同一个会话里**，针对某一问 | 不岔开：后面的轮次共用 | 旧页永远保留，新版**追加一页** |
| 分出新会话 | 跨会话，从某一条回答分出去 | 岔开：两条线各自独立长 | 原会话一条不动，分支拿的是副本 |
| 引用别的会话 | 材料挂在**哪个会话**由你定（就地生效 / 带着它开新会话） | 不岔开（材料不是对话），从**下一轮**开始生效 | 两边都不动 |

### 图片：必须换成能看图的模型

**DeepSeek 全系不支持图片** —— 在 DeepSeek 模型上贴图，上游会直接拒绝。所以服务端会**提前拦住**，并告诉你当前账号里哪些模型能看图，而不是让你发出去才收到一个看不懂的报错。

能看图的通常是：`gpt-4o`、`gpt-4.1`、`gpt-5`、`gemini-*`、`claude-*`、`grok-4+`。模型下拉框里会给这些加「· 可看图」标记。

另外两点：

- 图片只在浏览器本地保存，**不会写入服务端兜底副本**（那是 base64，存进去会把 `data/` 迅速撑爆）。
- 每张图会先压到长边 1568px、单张约 1.2MB 以内；一条消息最多 4 张。GIF 不压缩（重绘会丢动画）。

### 语音输入的现实限制

用的是浏览器的 Web Speech API，各浏览器差别很大：

- **Chrome / Edge**：可用，识别走云端（需要联网）。
- **Firefox**：长期不支持，按钮会显示「语音不可用」并说明原因。
- **Safari**：支持但行为不同，可能提前结束。

首次点击会请求麦克风权限。识别过程中可以随时点「结束」，已经识别出的文字会留在输入框里（不会覆盖你原本打的字）。

## 运行

```bash
cd ai-chat
node server.mjs          # → http://127.0.0.1:5250
```

启动后终端会告诉你当前是哪种模式：

```
对话模式：本地离线回答（未配置 API Key）
接入真实模型：设置环境变量 DEEPSEEK_API_KEY 后重启（可选 AI_MODEL / AI_BASE_URL）
```

### 接入真实大模型（可选）

不配也能用。配上就是真实模型的回答，其余代码一行都不用改：

```bash
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-xxxx"; node server.mjs

# macOS / Linux
DEEPSEEK_API_KEY=sk-xxxx node server.mjs
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | 也接受 `OPENAI_API_KEY`。为空即进入离线模式 |
| `AI_MODEL` | `deepseek-v4.1-flash` | 也接受 `OPENAI_MODEL`。服务端的初始默认模型；页面上选过的模型优先 |
| `AI_BASE_URL` | `https://api.deepseek.com/v1` | 任何 OpenAI 兼容接口（也接受 `OPENAI_BASE_URL`） |
| `AI_MODEL_CANDIDATES` | 空 | 逗号分隔，覆盖内置候选模型链（测试用） |
| `AI_STALL_TIMEOUT_MS` | `45000` | 上游多少毫秒没有新内容就算卡住（见下） |
| `AI_TITLE_TIMEOUT_MS` | `15000` | 起会话标题那次小请求的超时（超时就只用本地标题） |
| `AI_SUMMARY_TIMEOUT_MS` | `45000` | 压缩上文那次小请求的超时（超时就继续用原文发） |
| `AI_FORCE_MOCK` | 空 | 设为 `1` 强制留在离线模式，便于演示 |
| `PORT` / `HOST` | `5250` / `127.0.0.1` | 监听地址 |

### 在页面上换模型

顶部有一个模型选择框，列出你这个上游账号**实际可用**的模型（服务端问上游拿，已过滤掉绘图 / 语音 / 向量 / 视频等非聊天模型 —— 那个账号 156 个模型里滤掉 28 个）。选中的模型存在浏览器本地，刷新后仍然生效。

两条明确的行为约定：

- **默认模型**取 `AI_MODEL`（默认 `deepseek-v4.1-flash`）。你没在页面上选过时就用它。
- **你选过就用你选的，绝不静默替换。** 如果选的模型挂了，会明确报错并让你换一个，而不是偷偷用别的模型回答 —— 那种「界面显示 A、实际回答来自 B」的行为比报错更糟。

### 上游模型挂住时

有些模型会长时间不返回。为了不让你对着「正在生成」干等，服务端用的是**卡住检测**而不是总时长上限：只要还在持续出字就一直等，但**超过 `AI_STALL_TIMEOUT_MS`（默认 45 秒）没有任何新内容就中断**，并提示换一个模型。

实测经验（同一个 Key、同一时刻）：`deepseek-v3.2` 与 `gpt-4o-mini` 稳定在 2 秒左右，而 `deepseek-v4.1-flash` / `deepseek-v4-flash` 会整轮无响应。**这是上游侧的状态，与本项目无关，也可能随时间变化** —— 哪个快就用哪个，随时用 `node test/check-upstream.mjs` 测一遍。

### 上游报错时先跑这个

```bash
node test/check-upstream.mjs      # 或 npm run check:upstream
```

它用与服务端完全相同的配置直接问上游三件事：**这个 Key 能用哪些模型**、**当前模型能不能跑通流式**、**不能的话哪个能用**，并给出可以直接照着改的启动命令。

最容易踩的坑：**第三方代理往往没有你想要的模型名**（例如某个代理在 default 分组下没有 `deepseek-chat`）。此时上游返回 `503 model_not_found` —— 这**不是**「服务暂时不可用」，等多久都不会好。服务端启动时会自动探测可用模型并改用它，启动日志里能看到：

```
  模型 deepseek-chat 不可用：上游没有 「deepseek-chat」 这个模型：…无可用渠道（model_not_found）
  已验证可用模型：deepseek-v3.2
```

想看这个 Key 的全部可用模型（含被过滤的非聊天模型）：`/api/models` 与 `/api/models?all=1`。

### 界面上的报错怎么读

两种完全不同的故障，说的是两句不同的话 —— 别被第一句骗去查进程：

| 界面上的话 | 意思 | 该做什么 |
| --- | --- | --- |
| **连不上服务端：…。确认 node server.mjs 还在运行。** | 连接在传输过程中断了（浏览器给的原因通常是 `network error`）—— 本机的 `node server.mjs` 可能真的没在跑 | 看一眼那个终端窗口；端口在不在：`Get-NetTCPConnection -LocalPort 5250` |
| **服务端拒绝了这次请求（HTTP 400）：…** | 服务端**活着**，它只是拒了这一轮，后面那句就是它给的原话 | 那是服务端给的判断，照原话排查，不用动进程 |

**别把这两句当成一句**：它们的下一步动作完全相反 —— 一句让你去查进程，另一句让你去看原话。

### 服务端日志：出事了要留痕

`node server.mjs` 是一个终端里的一次性进程 —— 窗口一关、滚过去，线索就没了。所以服务端会往
**`data/server.log`** 写三类东西（可用 `AI_SERVER_LOG` 换路径）：

| 记什么 | 长什么样 |
| --- | --- |
| **启动** | `启动：端口 5250 · 模型 deepseek-v3.2 · 上游 https://…/v1` |
| **崩溃** | `未捕获异常（EPIPE）：` + 完整堆栈；未处理的 Promise 拒绝单独一类，措辞不同 |
| **结束** | `进程结束：退出码 1`，或者 `收到 SIGINT：进程被外部结束（关终端窗口 / Ctrl+C / 被杀进程）` |

**怎么用它判断「服务端为什么不见了」**：

- 有崩溃行 → 是它自己崩的，堆栈就在下面；
- 有「收到 SIGxxx」→ 是外面结束的（Ctrl+C、脚本 kill）；
- **只有启动行，别的什么都没有** → 是被外部**硬终止**的。Windows 上关掉控制台窗口就是这样，
  进程收不到任何信号，所以日志里干干净净 —— 这个"干净"本身就是答案。

另外两条自我保护的规矩：

- **日志写不进去绝不影响服务**（磁盘满、没权限都只是丢日志）：日志是附件，不是功能。
- **一直崩就不再硬撑**：一分钟内崩超过 10 次，记完最后一条就以退出码 1 退出 ——
  状态已经不可信的服务会给出看起来正常、其实是错的回答，那比停下来更糟。
- 日志超过 1MB 自动轮转（留一份 `.1`），不会无限长。

## 需求对照

| 需求 | 实现 |
| --- | --- |
| 完整聊天界面，输入问题 AI 回答 | 原生前端，问 / 答按轮次排版，回答支持 Markdown 与代码块 |
| 多轮对话，AI 记得之前说过的 | 每轮把完整历史一并发给模型；离线模式会真的从你的原话里抽取事实并回溯引用 |
| 回答逐字显示（流式输出） | 服务端 SSE 逐段 flush，前端逐帧读取、按帧渲染；实测一条回答产生约 200 个独立数据段，跨越数秒陆续到达 |
| 对话记录保存在本地，刷新不丢 | 主副本在 `localStorage`，流式中的半截文字也实时落盘；服务端在 `data/conversations/` 另留一份纯文字兜底副本 |
| 清空对话，方便开始新话题 | 「清空」就地二次确认，清掉当前会话的消息；左栏每一行也能单独删除整个会话 |
| 系统提示词 / 角色扮演 | 7 个内置角色 + 自定义提示词，按会话独立保存，从下一轮生效 |
| 多个对话会话管理 | 左栏会话列表，新建 / 切换 / 搜索 / 重命名 / 删除，各自独立的角色、模型与消息 |
| 会话很多时的浏览与查找 | 正文只画最近 20 轮（顶上的「更早的 20 轮」按需补，滚到顶也会自动补）；会话列表「最近」默认只显示 6 个 + 「显示全部（还藏着 N 个）」；搜索按标题和正文找（连编辑过的旧版本一起搜）。三处都只动**显示层**：请求历史、导出、摘要、引用原文读的仍是全部消息 |
| 语音输入 | Web Speech API，实时显示识别中的文字，不支持时明确说明原因 |
| 图片识别 | 选择 / 粘贴 / 拖拽图片 → 压缩 → 以多模态格式发给模型；非多模态模型提前拦截并提示换哪个 |
| 引用回答里的一段接着问 | 在回答里划中一段 → 「引用这段」→ 原文挂到输入框上方，随这一轮以 Markdown 引用块发给模型；引用跟着那一版提问保存，导出也不丢 |
| 导出对话记录 | Markdown / 纯文本 / JSON / 复制全文；可导出当前会话或全部会话 |

额外做了：手动停止生成、出错/中断后重新生成、复制回答、跨标签页同步、刷新时自动恢复中断的半截回答、旧版单会话数据自动迁移。

## 接口

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/chat` | POST | 主接口。请求 `{ messages, sessionId, model? }`，响应是 SSE 流 |
| `/api/title` | POST | 起会话标题。请求 `{ question, answer, laterQuestions?, model? }`，返回 `{ ok, title }`。非流式、小输出；失败也是 200（调用方保留本地标题即可） |
| `/api/feedback` | POST | 记录一条评价。请求 `{ action, rating, reasons, note, sessionId, messageId, version, model, answerExcerpt… }`，追加写进 `data/feedback.jsonl` |
| `/api/summarize` | POST | 把一段对话压成摘要。请求 `{ messages, model? }`，返回 `{ ok, summary }`。非流式、小输出；失败也是 200（调用方继续用原文发） |
| `/api/config` | GET | 当前模式（`model` / `mock`）、默认模型、实际使用的模型、接入提示 |
| `/api/models` | GET | 本账号可用的**聊天**模型列表（带 5 分钟缓存）；`?all=1` 含非聊天模型，`?refresh=1` 绕过缓存 |
| `/api/history/:sessionId` | GET | 读兜底副本（会先等本轮落盘任务收尾） |
| `/api/history/:sessionId` | DELETE | 删除兜底副本 |
| `/api/health` | GET | 健康检查 |

`POST /api/chat` 的 `model` 字段就是页面上选的那个模型。它会被校验（只允许字母数字与 `._:/-`），非法值一律忽略并回落到服务端默认 —— 免得被塞进上游请求体。

SSE 帧格式（一行一个 JSON 对象）：

```
data: {"type":"meta","mode":"mock","model":"本地离线回答","sessionId":"s_xxx"}
data: {"type":"delta","text":"**闭包**指的"}
data: {"type":"delta","text":"是函数记住"}
data: {"type":"done","reason":"stop"}
```

中途失败会先发 `{"type":"error","message":"..."}` 再发 `done`，已经写出的部分会保留在界面上，可以原地重新生成。

模型名以 `meta` 帧里的值为初始值；如果服务端换了模型，会在第一段内容之前补发一帧：

```
data: {"type":"model","model":"deepseek-v3.2","switchedFrom":"deepseek-chat"}
```

十个变异脚本共用 `test/mutation-harness.mjs`：快照、还原、「上次没正常结束就拒绝开工」、
以及「跑完再干净地跑一遍套件」都在那里 —— 这套机器写到第四遍时抽出来的，
因为几份拷贝已经开始分叉（有的把「套件中途崩溃」算成抓到了，有的没算）。
新增一个变异脚本现在只要几十行。

`repro-overwrite.mjs` 把「编辑重发不能吃掉旧内容」这条约定跑成一串可执行的步骤：
「发第一版 → 得到回答 → 编辑 → 重新回答」，然后断言两版内容都还在。
这类脚本的价值在于：**它把一句话的约定变成了能被机器检查的判据**。

**变异测试**临时改坏源码里的一个关键判断（比如「编辑更早的版本改成覆盖」「请求历史里丢掉旧版本」），跑一遍对应套件，然后还原。**如果某个变异没被抓到，说明对应断言是无效的** —— 补断言，而不是删变异。

关于它们的两点说明：

- 临时文件放在 `.tmp-mutations/`（已 gitignore）。脚本会在开工时写一个 `in-progress` 标记，**如果检测到上次没正常结束就直接拒绝运行**：中途崩溃可能把坏代码留在工作区，后续所有测试都在坏代码上跑，比不跑更糟。
- **元验证**守的是一条容易被忽略的规则：`process.on('unhandledRejection')` 一旦注册，Node 就不再打印拒绝原因、也不再以非零码退出 —— 脚本会因为一个错误静默中断（退出码 0、stderr 为空），看起来像「跑完了」。

测试默认自己在随机端口起服务；也可以指向一个已在运行的实例：

```bash
DSH_TEST_BASE=http://127.0.0.1:5250 node test/run-tests.mjs
```

四个刻意的设计：

- **流式测试不走 fetch**：undici 会把多个响应块合并成一次 `reader.read()`，「逐字」这件事在 fetch 层根本量不出来。所以流式断言用原始 TCP socket，直接数服务端 flush 出了多少个独立数据段、隔了多久。
- **`verify-upstream-payload.mjs` 用一个假上游**：角色提示词、图片格式这类东西只有看「实际发出去的请求体」才算验证，而真实上游经常抽风。这个脚本起一个假的 OpenAI 兼容服务，把收到的请求抓下来断言 —— 完全不依赖网络。
- **`ui-tests.mjs` 用极简 DOM 替身跑真实的 `app.js`**：有些缺陷不是逻辑错，而是「两个界面元素说法不一致」（顶部标签显示 A、下拉框显示 B）或「某个动作少做了一步」（保存了却没收起面板）。纯函数测试看不见这类问题，只有真跑一遍才露出来。
- **编辑分页的判断抽成了纯函数**（`public/lib/versions.js`）：什么时候该新增一页、请求历史怎么拼，都是容易错又难察觉的地方。抽出来才能不依赖浏览器直接测，也才能被变异测试守住。

## 设计说明

**为什么是「对谈录」而不是气泡。** 气泡是即时通讯的隐喻，追问和回答被压成两条不同颜色的色块，多轮之后就分不清哪句是哪轮。这份界面按**轮次**组织：页边的大号序号是每一轮的锚点，贯穿竖线把一问一答绑在一起，回答用宋体排在正文栏里、按稿件的方式排版。红墨只用在两个地方——「问」标和书写光标——所以「正在写」这件事一眼就能看见。

**流式渲染的取舍。** SSE 到达的节奏不可控，逐 token 改 DOM 会让长回答抖动。前端用 `requestAnimationFrame` 合并成「一帧一渲染」，并且流式期间只重画当前那一条，不重建整个列表（否则滚动锚点和光标位置都会跳）。

**落盘节流。** 每来一个 token 就 `JSON.stringify` 整段对话，一轮回答就是上百次全量序列化，对话越长越卡。改成以「一个流式周期」计时：每条回答的**第一个**增量立即落盘（这样中途刷新一定看得到正文），之后最多每 250ms 一次，`finish` 和页面 `pagehide` 时立刻补写。

**离线模式不做假。** 没有 API Key 时，离线回答会如实说明自己不是真实模型，同时真的从你的原话里抽取事实（称呼、职业、在学什么、在做哪个项目）并在你追问时回到上文原样引用。演示的是机制——多轮上下文、逐字输出、刷新不丢——而不是伪装成模型推理。

## 已知限制

- **`localStorage` 约 5MB**：图片（base64）最占空间。写满后界面仍可用，只是不再落盘（控制台会警告）；添加图片时若超出容量会明确提示，不会静默丢。
- **会话上限 50 个**：超过后自动淘汰最久未使用的那个，避免把存储撑爆。
- **语音输入依赖浏览器**：Firefox 不支持；Chrome / Edge 的识别走云端，离线时不可用。
- **图片需要多模态模型**：DeepSeek 全系不支持，见上文。
- **离线回答没有知识**：只有少量技术小抄模板，其余问题会明确说「不编造」，图片也无法识别。
- **硬杀进程可能丢最后约 250ms 内容**：节流窗口内的最后一次写入靠 `pagehide` 补，正常刷新和关闭页面都没问题。
- 服务端兜底副本**不做鉴权**：它只按 `sessionId` 存文件，适合本机单人使用。放到公网前需要自行加访问控制。
- **服务端不能常驻**：`node server.mjs` 需要一个保持打开的终端窗口。

## 数据与隐私

| 数据 | 存在哪 | 说明 |
| --- | --- | --- |
| 全部会话（含图片） | 浏览器 `localStorage`（`duitanlu.sessions.v2`） | 唯一权威副本 |
| 每会话的模型 / 角色偏好 | 同上，存在会话里 | 另有全局模型偏好 `duitanlu.model.v1` |
| 对话纯文字兜底副本 | 服务端 `data/conversations/<id>.json` | **不含图片**；已 gitignore |
| 对回答的评价 | 浏览器（跟着那一版回答）+ 服务端 `data/feedback.jsonl` | 服务器那份是追加日志：档位、原因、说明，外加**答案开头 300 字**（用来知道评的是哪条）；已 gitignore |
| 上下文摘要 | 浏览器，存在会话里 | 压缩后生成的一段摘要；**原始消息仍然完整保留**（压缩只改发给模型的那一份）。服务端只在生成它时经手一次 |
| 图片 | 只在浏览器 | 发送时以 base64 随请求体交给上游模型服务 |

**旧版本数据会自动迁移**：第一次打开新版时，旧的单会话数据（`duitanlu.conversation.v1`）会被搬成一个会话并清掉旧键，对话不会丢。

另外两点值得知道：

- **Key 存放在用户级环境变量里时，该账号下启动的任何程序都能读到。** 更稳妥的做法是放进项目专属的 `.env`（已在根 `.gitignore` 的忽略范围内），只让本项目加载。
- `data/conversations/` 是**明文**落盘的对话正文，共享这台机器给别人用时留意一下。
