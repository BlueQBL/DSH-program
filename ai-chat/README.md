# 对谈录 · AI 聊天助手

一个能真正对话的聊天页面：你问，它答，回答**一个字一个字写出来**；一轮轮聊下去它记得你前面说过什么；刷新、关掉再打开，这一页的字都还在。

可以同时开好几个话题（左边一列会话，互不串台），每个会话有自己的**角色**（编程助手 / 写作助手 / 心理咨询师……或者你自己写提示词）和**模型**；能用**语音**说，能贴**图片**让它看图回答；聊完可以**导出**成 Markdown / 纯文本 / JSON。

界面不做「聊天气泡」，做的是一份**对谈记录**：页边有序号，一条竖线把一问一答串起来，回答像稿件一样写在正文栏里，正在生成时那里有一道红墨光标在写。

零依赖：Node 原生 HTTP + 原生 HTML/CSS/JS，`npm install` 都不用。

## 六个主要功能

| 功能 | 怎么用 | 说明 |
| --- | --- | --- |
| **会话管理** | 顶部「新对话」；左栏切换、改名、删除 | 每个会话各自保存消息、角色、模型；超过 50 个自动淘汰最旧的。**进入页面默认开新会话**（刷新除外）；切到已有对话时，自动开的那个空白会话会被清掉 |
| **角色 / 系统提示词** | 顶部「角色」下拉框；「系统提示词」可查看、可改、可收起 | 内置通用 / 编程 / 写作 / 心理咨询 / 学习导师 / 数据分析 / 翻译。**新会话一律从「通用助手」开始**，角色由你显式选择；回到旧会话时它自己的角色还在 |
| **语音输入** | 点「语音输入」开始，再点「结束」 | 用浏览器 Web Speech API；Chrome / Edge 可用，Firefox 不支持（按钮会直接说明原因） |
| **图片识别** | 「加图片」、直接粘贴、或拖进输入区 | 自动压缩到长边 1568px；**需要支持看图的模型**（见下） |
| **编辑并重新回答** | 提问右上角的「编辑」 | 改完可以「重新回答」或「只改不发」；**旧回答不会被覆盖**，改更早的那一页会生成新的一页 |
| **导出** | 底部「导出」，或左栏「导出全部」 | Markdown / 纯文本 / JSON / 复制全文 |

关于角色的几条约定（都来自实际使用中反馈的问题）：

- **新会话的角色是「通用助手」**，不继承上一个会话的角色 —— 角色的语义是「这个会话让 AI 扮演谁」，换话题就该重新选。**模型则相反**，会沿用上次选过的，因为那是「用哪个引擎」。
- **回到已有会话时，角色是那个会话自己的。** 会话 A 用编程助手、会话 B 用写作助手，来回切不会互相覆盖。
- **点「保存到本对话」不会改变你选的角色。** 在某个预设角色（比如编程助手）下只是看了看提示词就点保存的话，角色仍然是编程助手；只有你真的改了内容才会记录改动，而且角色名保持不变。想用完全自定义的角色，请显式在下拉框里选「自定义」。
- **只想看提示词**：展开后点右上角的 **×** 或底部的「收起」即可，不会写入任何数据。

代码块带**语法高亮**（关键字、字符串、注释、数字、函数名、类型名），支持 JS / TS / Python / Java / Go / Rust / Shell / SQL / CSS 及常见别名。高亮是**流式安全**的：代码写一半时该上色的照样上色，且不会把内容吞掉。

### 编辑并重新回答（分页）

对已经不理想的提问，把鼠标移到那条提问上会出现「**编辑**」：

- **重新回答** —— 用改后的内容再问一次，**每次都会新增一页**。原来那一页原样保留，
  所以「本次生成的内容」和「上一次生成的内容」都在，可以来回对比。
- **只改不发** —— 只把文字改掉，不触发回答。
- 多页之后，提问下方出现页码（**第 1 / 2 / 3 页**），点数字即可来回切换查看。

编辑框里会提前写明这一按的后果：**「将生成第 2 页，当前这一页会保留」**。

> **这里有一个我踩过的坑，值得说明。** 最初我把「编辑重发」实现成
> 「改的是最新一页就地覆盖」——想的是「用户就是在改当前这一页，没必要多出一页」。
> 结果用户实测反馈：*「我生成之后重新编辑了需求，生成的内容把上一次的内容给覆盖了」*。
> 覆盖之后旧内容就找不回来了，**这个动作的全部意义（保留旧版、对比着看）就没了**。
> 现在语义是硬的：**编辑一律追加新页，绝不覆盖**。

**发给模型的上下文是完整的**：编辑过的提问，它之前每一版以及各自得到的回答都会按顺序带上。
否则模型会看到「我问了 A，它答了 B，然后我又问 B」这种自问自答，回答就会跑偏。

**「重新生成」和「编辑后重新回答」是两个不同动作**，别混：

| 动作 | 输入 | 结果 |
| --- | --- | --- |
| 重新生成 | 不变 | 原地替换这一页的回答，**不新增页** |
| 编辑后重新回答 | 改了 | **新增一页**，旧页保留 |

### 图片：必须换成能看图的模型

**DeepSeek 全系不支持图片** —— 在 DeepSeek 模型上贴图，上游会直接拒绝。所以服务端会**提前拦住**，并告诉你当前账号里哪些模型能看图，而不是让你发出去才收到一个看不懂的报错。

能看图的通常是：`gpt-4o`、`gpt-4.1`、`gpt-5`、`gemini-*`、`claude-*`、`grok-4+`。模型下拉框里会给这些加「· 可看图」标记。

另外两点：

- 图片只在浏览器本地保存，**不会写入服务端兜底副本**（那是 base64，存进去会把 `data/` 迅速撑爆）。
- 每张图会先压到长边 1568px、单张约 1.2MB 以内；一条消息最多 4 张。GIF 不压缩（重绘会丢动画）。

### 语音输入的现实限制

用的是浏览器的 Web Speech API，各浏览器差别很大：

- **Chrome / Edge**：可用，识别走云端（需要联网）。
- **Firefox**：长期不支持，按钮会显示「语音不可用」并说明原因。
- **Safari**：支持但行为不同，可能提前结束。

首次点击会请求麦克风权限。识别过程中可以随时点「结束」，已经识别出的文字会留在输入框里（不会覆盖你原本打的字）。

## 运行

```bash
cd ai-chat
node server.mjs          # → http://127.0.0.1:5250
```

启动后终端会告诉你当前是哪种模式：

```
对话模式：本地离线回答（未配置 API Key）
接入真实模型：设置环境变量 DEEPSEEK_API_KEY 后重启（可选 AI_MODEL / AI_BASE_URL）
```

### 接入真实大模型（可选）

不配也能用。配上就是真实模型的回答，其余代码一行都不用改：

```bash
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-xxxx"; node server.mjs

# macOS / Linux
DEEPSEEK_API_KEY=sk-xxxx node server.mjs
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | 也接受 `OPENAI_API_KEY`。为空即进入离线模式 |
| `AI_MODEL` | `deepseek-v4.1-flash` | 也接受 `OPENAI_MODEL`。服务端的初始默认模型；页面上选过的模型优先 |
| `AI_BASE_URL` | `https://api.deepseek.com/v1` | 任何 OpenAI 兼容接口（也接受 `OPENAI_BASE_URL`） |
| `AI_MODEL_CANDIDATES` | 空 | 逗号分隔，覆盖内置候选模型链（测试用） |
| `AI_STALL_TIMEOUT_MS` | `45000` | 上游多少毫秒没有新内容就算卡住（见下） |
| `AI_FORCE_MOCK` | 空 | 设为 `1` 强制留在离线模式，便于演示 |
| `PORT` / `HOST` | `5250` / `127.0.0.1` | 监听地址 |

### 在页面上换模型

顶部有一个模型选择框，列出你这个上游账号**实际可用**的模型（服务端问上游拿，已过滤掉绘图 / 语音 / 向量 / 视频等非聊天模型 —— 那个账号 156 个模型里滤掉 28 个）。选中的模型存在浏览器本地，刷新后仍然生效。

两条明确的行为约定：

- **默认模型**取 `AI_MODEL`（默认 `deepseek-v4.1-flash`）。你没在页面上选过时就用它。
- **你选过就用你选的，绝不静默替换。** 如果选的模型挂了，会明确报错并让你换一个，而不是偷偷用别的模型回答 —— 那种「界面显示 A、实际回答来自 B」的行为比报错更糟。

### 上游模型挂住时

有些模型会长时间不返回。为了不让你对着「正在生成」干等，服务端用的是**卡住检测**而不是总时长上限：只要还在持续出字就一直等，但**超过 `AI_STALL_TIMEOUT_MS`（默认 45 秒）没有任何新内容就中断**，并提示换一个模型。

实测经验（同一个 Key、同一时刻）：`deepseek-v3.2` 与 `gpt-4o-mini` 稳定在 2 秒左右，而 `deepseek-v4.1-flash` / `deepseek-v4-flash` 会整轮无响应。**这是上游侧的状态，与本项目无关，也可能随时间变化** —— 哪个快就用哪个，随时用 `node test/check-upstream.mjs` 测一遍。

### 上游报错时先跑这个

```bash
node test/check-upstream.mjs      # 或 npm run check:upstream
```

它用与服务端完全相同的配置直接问上游三件事：**这个 Key 能用哪些模型**、**当前模型能不能跑通流式**、**不能的话哪个能用**，并给出可以直接照着改的启动命令。

最容易踩的坑：**第三方代理往往没有你想要的模型名**（例如某个代理在 default 分组下没有 `deepseek-chat`）。此时上游返回 `503 model_not_found` —— 这**不是**「服务暂时不可用」，等多久都不会好。服务端启动时会自动探测可用模型并改用它，启动日志里能看到：

```
  模型 deepseek-chat 不可用：上游没有 「deepseek-chat」 这个模型：…无可用渠道（model_not_found）
  已验证可用模型：deepseek-v3.2
```

想看这个 Key 的全部可用模型（含被过滤的非聊天模型）：`/api/models` 与 `/api/models?all=1`。

## 需求对照

| 需求 | 实现 |
| --- | --- |
| 完整聊天界面，输入问题 AI 回答 | 原生前端，问 / 答按轮次排版，回答支持 Markdown 与代码块 |
| 多轮对话，AI 记得之前说过的 | 每轮把完整历史一并发给模型；离线模式会真的从你的原话里抽取事实并回溯引用 |

| 清空对话，方便开始新话题 | 「清空」就地二次确认，清掉当前会话的消息；左栏每一行也能单独删除整个会话 |
| 系统提示词 / 角色扮演 | 7 个内置角色 + 自定义提示词，按会话独立保存，从下一轮生效 |
| 多个对话会话管理 | 左栏会话列表，新建 / 切换 / 重命名 / 删除，各自独立的角色、模型与消息 |
| 语音输入 | Web Speech API，实时显示识别中的文字，不支持时明确说明原因 |
| 图片识别 | 选择 / 粘贴 / 拖拽图片 → 压缩 → 以多模态格式发给模型；非多模态模型提前拦截并提示换哪个 |
| 导出对话记录 | Markdown / 纯文本 / JSON / 复制全文；可导出当前会话或全部会话 |

额外做了：手动停止生成、出错/中断后重新生成、复制回答、跨标签页同步、刷新时自动恢复中断的半截回答、旧版单会话数据自动迁移。

## 接口

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/chat` | POST | 主接口。请求 `{ messages, sessionId, model? }`，响应是 SSE 流 |
| `/api/config` | GET | 当前模式（`model` / `mock`）、默认模型、实际使用的模型、接入提示 |
| `/api/models` | GET | 本账号可用的**聊天**模型列表（带 5 分钟缓存）；`?all=1` 含非聊天模型，`?refresh=1` 绕过缓存 |
| `/api/history/:sessionId` | GET | 读兜底副本（会先等本轮落盘任务收尾） |
| `/api/history/:sessionId` | DELETE | 删除兜底副本 |
| `/api/health` | GET | 健康检查 |

`POST /api/chat` 的 `model` 字段就是页面上选的那个模型。它会被校验（只允许字母数字与 `._:/-`），非法值一律忽略并回落到服务端默认 —— 免得被塞进上游请求体。

SSE 帧格式（一行一个 JSON 对象）：

```
data: {"type":"meta","mode":"mock","model":"本地离线回答","sessionId":"s_xxx"}
data: {"type":"delta","text":"**闭包**指的"}
data: {"type":"delta","text":"是函数记住"}
data: {"type":"done","reason":"stop"}
```

中途失败会先发 `{"type":"error","message":"..."}` 再发 `done`，已经写出的部分会保留在界面上，可以原地重新生成。

模型名以 `meta` 帧里的值为初始值；如果服务端换了模型，会在第一段内容之前补发一帧：

```
data: {"type":"model","model":"deepseek-v3.2","switchedFrom":"deepseek-chat"}
```

```bash
npm test                     # 四个套件一起跑（433 项断言）

node test/store-tests.mjs    # 245 项：多会话、迁移、角色、编辑分页、请求历史、图片、导出
node test/ui-tests.mjs       # 43 项：界面状态同步（顶部标签 / 提示词面板 / 角色保持 / 会话切换）
node test/verify-upstream-payload.mjs   # 16 项：用假上游抓包，验证真正发出去的请求体
```

四个需要服务在跑的核对脚本：

```bash
node test/verify-sse.mjs      http://127.0.0.1:5250   # 直连 socket 看真实字节
node test/verify-turns.mjs    http://127.0.0.1:5250   # 多轮记忆与兜底副本
node test/verify-models.mjs   http://127.0.0.1:5250   # 模型选择是否真的生效
node test/verify-features.mjs http://127.0.0.1:5250   # 角色提示词、会话隔离、图片（需真实上游）
```

还有四个用来验证「**缺陷真的被修好、断言真的有效**」的脚本：

```bash
node test/repro-overwrite.mjs     # 缺陷复现：编辑重发后旧内容必须还在（不需要服务，可直接跑）
node test/ui-mutations.mjs        # 变异测试：改坏 app.js，看界面断言会不会失败
node test/version-mutations.mjs   # 变异测试：改坏编辑分页逻辑，看版本断言会不会失败
node test/verify-loud-failure.mjs # 元验证：注入错误，确认测试会大声失败而不是静默通过
```

`repro-overwrite.mjs` 就是用户报告的那个缺陷的最小复现（「编辑后生成的内容把上一次的覆盖了」）。
它连着跑一遍「发第一版 → 得到回答 → 编辑 → 重新回答」，然后断言两版内容都还在 ——
**修复前它会失败，修复后它通过**。这类脚本的价值在于：它把「用户描述的现象」变成了可执行的判据。

**变异测试**临时改坏源码里的一个关键判断（比如「编辑更早的版本改成覆盖」「请求历史里丢掉旧版本」），跑一遍对应套件，然后还原。**如果某个变异没被抓到，说明对应断言是无效的** —— 这两个脚本自己就是这么被验证出来的：早期版本有 3 个变异逃了过去，`version-mutations` 第一次跑时 9 个里也逃过 1 个（因为缺「早前消息带图」的用例），据此加强了断言。

关于它们的两点说明：

- 临时文件放在 `.tmp-mutations/`（已 gitignore）。脚本会在开工时写一个 `in-progress` 标记，**如果检测到上次没正常结束就直接拒绝运行** —— 因为中途崩溃可能把坏代码留在工作区，后续所有测试都在坏代码上跑，比不跑更糟。
- **元验证**针对的是一个真实踩过的坑：`process.on('unhandledRejection')` 一旦注册，Node 就不再打印拒绝原因、也不再以非零码退出 —— 于是脚本因为一个错误静默中断，退出码 0、stderr 为空，看起来像「跑完了」。

测试默认自己在随机端口起服务；也可以指向一个已在运行的实例：

```bash
DSH_TEST_BASE=http://127.0.0.1:5250 node test/run-tests.mjs
```

三个刻意的设计：

- **流式测试不走 fetch**：undici 会把多个响应块合并成一次 `reader.read()`，「逐字」这件事在 fetch 层根本量不出来。所以流式断言用原始 TCP socket，直接数服务端 flush 出了多少个独立数据段、隔了多久。
- **`verify-upstream-payload.mjs` 用一个假上游**：角色提示词、图片格式这类东西只有看「实际发出去的请求体」才算验证，而真实上游经常抽风。这个脚本起一个假的 OpenAI 兼容服务，把收到的请求抓下来断言 —— 完全不依赖网络。
- **`ui-tests.mjs` 用极简 DOM 替身跑真实的 `app.js`**：有些缺陷不是逻辑错，而是「两个界面元素说法不一致」（顶部标签显示 A、下拉框显示 B）或「某个动作少做了一步」（保存了却没收起面板）。纯函数测试看不见这类问题，只有真跑一遍才露出来。
- **编辑分页的判断抽成了纯函数**（`lib/versions.js`）：什么时候该新增一页、请求历史怎么拼，都是容易错又难察觉的地方。抽出来才能不依赖浏览器直接测，也才能被变异测试守住。

## 设计说明

**为什么是「对谈录」而不是气泡。** 气泡是即时通讯的隐喻，追问和回答被压成两条不同颜色的色块，多轮之后就分不清哪句是哪轮。这份界面按**轮次**组织：页边的大号序号是每一轮的锚点，贯穿竖线把一问一答绑在一起，回答用宋体排在正文栏里、按稿件的方式排版。红墨只用在两个地方——「问」标和书写光标——所以「正在写」这件事一眼就能看见。

**流式渲染的取舍。** SSE 到达的节奏不可控，逐 token 改 DOM 会让长回答抖动。前端用 `requestAnimationFrame` 合并成「一帧一渲染」，并且流式期间只重画当前那一条，不重建整个列表（否则滚动锚点和光标位置都会跳）。

**落盘节流。** 每来一个 token 就 `JSON.stringify` 整段对话，一轮回答就是上百次全量序列化，对话越长越卡。改成以「一个流式周期」计时：每条回答的**第一个**增量立即落盘（这样中途刷新一定看得到正文），之后最多每 250ms 一次，`finish` 和页面 `pagehide` 时立刻补写。

**离线模式不做假。** 没有 API Key 时，离线回答会如实说明自己不是真实模型，同时真的从你的原话里抽取事实（称呼、职业、在学什么、在做哪个项目）并在你追问时回到上文原样引用。演示的是机制——多轮上下文、逐字输出、刷新不丢——而不是伪装成模型推理。

## 已知限制

- **`localStorage` 约 5MB**：图片（base64）最占空间。写满后界面仍可用，只是不再落盘（控制台会警告）；添加图片时若超出容量会明确提示，不会静默丢。
- **会话上限 50 个**：超过后自动淘汰最久未使用的那个，避免把存储撑爆。
- **语音输入依赖浏览器**：Firefox 不支持；Chrome / Edge 的识别走云端，离线时不可用。
- **图片需要多模态模型**：DeepSeek 全系不支持，见上文。
- **离线回答没有知识**：只有少量技术小抄模板，其余问题会明确说「不编造」，图片也无法识别。
- **硬杀进程可能丢最后约 250ms 内容**：节流窗口内的最后一次写入靠 `pagehide` 补，正常刷新和关闭页面都没问题。
- 服务端兜底副本**不做鉴权**：它只按 `sessionId` 存文件，适合本机单人使用。放到公网前需要自行加访问控制。
- **服务端不能常驻**：`node server.mjs` 需要一个保持打开的终端窗口。

## 数据与隐私

| 数据 | 存在哪 | 说明 |
| --- | --- | --- |
| 全部会话（含图片） | 浏览器 `localStorage`（`duitanlu.sessions.v2`） | 唯一权威副本 |
| 每会话的模型 / 角色偏好 | 同上，存在会话里 | 另有全局模型偏好 `duitanlu.model.v1` |
| 对话纯文字兜底副本 | 服务端 `data/conversations/<id>.json` | **不含图片**；已 gitignore |
| 图片 | 只在浏览器 | 发送时以 base64 随请求体交给上游模型服务 |

**旧版本数据会自动迁移**：第一次打开新版时，旧的单会话数据（`duitanlu.conversation.v1`）会被搬成一个会话并清掉旧键，对话不会丢。

另外两点值得知道：

- **Key 存放在用户级环境变量里时，该账号下启动的任何程序都能读到。** 更稳妥的做法是放进项目专属的 `.env`（已在根 `.gitignore` 的忽略范围内），只让本项目加载。
- `data/conversations/` 是**明文**落盘的对话正文，共享这台机器给别人用时留意一下。
