# 校样 · Markdown 笔记台

左边写 Markdown，右边实时看到版面。图片、脚注、数学公式、大纲、主题、PDF 导出都有，
数据只留在本机浏览器里。

```bash
npm start                       # http://127.0.0.1:5220/
npm test                        # 解析 / 公式 / 打包 / 图片 / 数据 五层，共 647 项断言
node scripts/shots.js           # 版面 + 流程 + 边界 + 打印实测 + 五张截图（本机有 Chrome 即可）
```

不需要构建、不需要装依赖：六个 JS 文件、一个 CSS、一个 `index.html`，
双击 `index.html` 也能跑（用 `npm start` 起本地服务更稳妥，剪贴板与 IndexedDB 对 `file://` 有额外限制）。

---

## 一、它是什么

一个「校样」——排版行话里，稿子是墨，印张是纸，校对者用红笔在页边做记号。

```
┌──────────────┬──────────────────────────────┬──────────────────────────────┐
│ 目录栏        │  稿纸（墨）                    │  印张（纸）                    │
│              │                              │                              │
│ 笔记│大纲│图片 │  标题                         │  ┌── 排好的版面 ──────────┐    │
│ ─────────    │  创建时间 · 字数               │  │ # 标题                 │    │
│ 搜索框        │  ─────────────────────       │  │ 段落、列表、表格、图…    │    │
│ ● 笔记一      │  H2 B I </> 代码块 图片 公式…   │  │ ▓ 墨色代码卡片 ▓        │    │
│   笔记二      │                              │  │ ∑ 数学公式（MathML）    │    │
│              │  正文（Markdown 原文）         │  └────────────────────────┘    │
│              │                              │                        ◤ 红括号 │
│ 2 篇 · 2.2 KB │  已保存 08:27 │ 行 3 · 列 8   │  印张│目录 跟随光标● 导出PDF   │
└──────────────┴──────────────────────────────┴──────────────────────────────┘
```

- **左边是机器声部**：等宽字体、深墨底色，写的是一行行源码。
- **右边是纸面声部**：衬线排版、浅纸底色，看的是一页版面。
- **同一份墨**：印张里的代码卡片仍然是墨色的——稿纸的墨渗进了纸面。
- **全文只有一个强调色**（默认 proofred `#D93F2B`），只用在"当前位置"这一件事上：
  页边记号、选中的笔记、焦点、危险操作。其余一律黑白灰。

## 二、四个核心设计

**1. 页边红括号（签名交互）**
印张页边有一枚手画的竖线，红括号指着你光标所在的那一块，打字时跟着走，
印张也会滚动把那一块留在视野里（「跟随光标」可以关掉）。
反过来也成立：**点印张里任意一段，左边光标跳回对应的源码行**，不用自己数行号。
行号映射是解析器给的：每个块级元素都带 `data-line` / `data-end`（1 基、含首含尾），
嵌套列表里会选中最内层那个块。

**2. 纸面可以编辑墨**
`- [ ]` 任务清单在印张里渲染成真的复选框，点一下会**改回左边的原文**（`[ ]` ↔ `[x]`），顺手落盘。
空格和画勾，改的都是同一份 Markdown，不是两份数据。

**3. 不停手保存**
停手 400ms 落盘一次；一直打字也不会超过 4 秒不存。左下角始终写着状态：
`待保存…` → `已保存 08:27`，存不下就直说（`仅本次会话`、`未能保存：配额已满`），不假装成功。

**4. 标题只有一处，但两边都看得见**
标题是稿纸栏顶部单独一个输入框，印张会**自己把它排成版面最上面那一行**。
若正文开头已经写了一个一级标题（`# 标题`），印张就不再重复排，
判据 `store.bodyStartsWithH1()` 被预览和导出 `.md` 共用——所以"印张上看到的第一行标题"
和"导出文件里的第一个 H1"永远是同一个。

## 三、七项扩展

> 需求里的「目录导航」和「自动生成大纲」是同一件事的两面（大纲是数据、导航是用法），
> 合在下面第 2 节讲；其余各自一节。

### 1. 图片：一篇笔记一个目录

图片来源是文件选择、**粘贴**（截图后 Ctrl/Cmd+V）和**拖放**三种入口。因为浏览器里没有真正的
文件系统，这里的做法是：

- 图片以 Blob 存在 **IndexedDB**（`markdown-notes/images`，按 `noteId` 建索引），不占 LocalStorage 那 5MB；
- 每篇笔记对应一个**虚拟目录，目录名就是笔记标题**（`MDImages.folderName()` 清洗非法字符，
  重名往后排 `标题 (2)`）——目录名是**算出来的**，所以改标题目录名跟着变，不用同步任何状态；
- Markdown 里只写相对文件名：`![截图](截图-1.png)`，空格转义成 `%20`；
- 渲染时把相对路径解析到当前笔记的图库里（大小写不敏感、忽略扩展名、可带 `./` 或目录前缀）；
- 左栏「图片」页签就是这篇的目录：缩略图、大小、**被正文引用了多少次**、插入、删除（带撤销）；
- 删除笔记后，属于它的图片会在下次启动时被清掉，并如实报数（清了几张、多少字节）。

**导出 ZIP 时虚拟目录落成真目录**——文档在压缩包根目录，图片在**以标题命名的文件夹**里：

```
我的笔记.zip
├── 目录.md                     ← 全部导出时才有的索引
├── 我的笔记.md                  ← 文档在文件夹外面
├── 我的笔记/                    ← 图片都在这里（文件夹名 = 标题）
│   ├── 截图-1.png
│   └── 流程图.png
└── 另一篇.md
    另一篇/…
```

正文里写的是**文件名**（`![截图](截图-1.png)`）——这样改标题不会把引用写坏；
导出那一刻才把路径补成 `我的笔记/截图-1.png`（`MDImages.rewritePaths()`），
所以解压后在别的编辑器里点得开；只改"确实属于这篇笔记"的图，外链与找不到的图原样留着。
`.md` 单独导出时也用同一套目录约定，和 ZIP 保持一致。

ZIP 是自己写的（`js/zip.js`，store 模式不压缩，约 200 行，含 CRC32 与 UTF-8 文件名标志位），
所以零依赖。

**整篇被一层围栏包住时会提醒你**（`md.detectWrappingFence()`）：
从 AI 对话里粘过来的内容常常整段套着 ```md … ```，于是整篇文章在印张上变成一个代码块，
看起来"正文不见了"。印张顶部会出现一条提示 + 一个「拆掉外层围栏」按钮，
点一下就去掉外层围栏、按排版显示。**不做静默改写**——原文是你的，改不改你说了算。

**编辑时也看得到图**：稿纸栏底部有一条"本文图片"缩略图带（有图时才出现），
点某张缩略图跳到正文里引用它的那一行；还没被引用的图点一下插到光标处。
左边终究是 Markdown 原文（图片在那里只能是文字），这条缩略图带是"编辑时也能看见"的折中。

**找不到图时不会装死**：渲染成明确的"图库里没有这张图"占位，
并且区分「还没读完」（`正在取图…`）与「确实没有」两种状态——
`resolveImage` 返回 `undefined` 表示异步的图库还没就绪，返回 `null` 才是真没有。

### 2. 目录导航 + 自动大纲

左栏「大纲」页签里的树**直接从印张里已经排好的标题收集**（`#preview` 里的 `h1..h6`），
所以大纲和正文不可能不一致——改了正文，大纲跟着变。

- 层级缩进按标题级别算（最顶层齐左，往下每级 11px）；
- 点一条就滚过去，落点会闪一下红笔痕（一次性的 `.is-flash`）；
- 滚动时自动高亮当前章节（`requestAnimationFrame` 节流）；
- 窄屏（≤1080px）时大纲改成印张头部的「目录」按钮掉下来的浮层。

标题都带锚点：自动编号 `id="sec-N"`，也支持 `## 标题 {#自定义}`（严格 CommonMark 风格下不认）。
脚注引用和 `[跳到](#sec-2)` 这类站内链接由界面接住自己滚动，不动地址栏。

### 3. 脚注与数学公式

**脚注**：正文写 `[^名字]`，文末写 `[^名字]: 说明`。

- 编号按**引用出现的顺序**给（不是定义的顺序），跟常见实现一致；
- 定义在解析前先摘出来、原行清空，所以 `data-line` 行号不会错位——脚注区也能被光标联动点亮；
- 多段脚注（定义行下面缩进两格）会当成块级内容解析，里面照样能用 Markdown；
- 引用不存在的脚注 → 一个虚线问号并给出提示；定义了却没人引用 → 照样排出来并标「未引用」；
  两者都不静默丢弃。

**数学公式**：`$行内$` 与 `$$块级$$`，渲染成 **MathML**。

为什么不用 KaTeX：它是 100KB 级依赖加一套字体，而这个应用要零依赖、能离线。
现代浏览器（Chrome 109+ / Safari / Firefox）都原生渲染 MathML Core，
所以 `js/mathml.js` 做的事就是把 TeX 子集翻译成 MathML：

| 支持 | 写法 |
| --- | --- |
| 分数 / 根号 | `\frac{a}{b}`、`\sqrt[3]{x}` |
| 上下标 / 大运算符 | `x_i^2`、`\sum_{i=1}^{n}`、`\int_0^1`、`\lim_{x\to0}`（自动挂成上下限） |
| 希腊字母 / 运算符 / 箭头 | `\alpha`、`\times \le \approx \infty \partial`、`\to \Rightarrow` |
| 括号与矩阵 | `\left( \right)`、`\begin{pmatrix}a&b\\c&d\end{pmatrix}`、`\begin{cases}` |
| 重音与字体 | `\hat{x}`、`\bar{y}`、`\vec{v}`、`\overline{AB}`、`\mathbb{R}`、`\mathbf{v}`、`\text{中文}` |
| 间距 | `\,` `\;` `\quad` `\qquad` |

不支持的写法不会被静默吃掉：命令原样渲染出来并标红，`unknown` 列表记在
`data-unknown` 属性上，鼠标悬停能看到"有 N 处写法没认出来"；
结构性错误（括号不配对等）直接退回显示原始 TeX。
公式还带 `<annotation encoding="application/x-tex">`，所以复制出去是文字、读屏能念、也方便再编辑。

### 4. 导出 PDF

「导出 PDF」调用浏览器自己的打印引擎，在打印窗口里把目标选成「另存为 PDF」。

不自己拼 PDF 是有意的：中文要正常显示得内嵌字体子集（几 MB），
那意味着引入一个可观的依赖，而且排出来的还是图片或残缺字形。
浏览器打印出来的是**矢量文字**——能选中、能搜索、公式和代码块都不会糊。

打印样式（`@media print`）专门处理了几件事，每一条都是踩过坑之后加的：

- **一律回到纸白墨黑**：暗色主题直接打印会印出一张全黑的纸，所以打印时不认主题；
- 代码块从墨底换成浅底细框，并给了一份**打印专用的 token 配色**（深色主题的亮色 token 在纸上会看不见）；
- 界面全部让开（目录栏、稿纸、中缝、按钮、吐司、提示条、缩略图带），只留印张；
- 链接后面补出网址（仅 `http` 外链）；
- **打印时不留滚动容器**：Chrome 把"可滚动的盒子"当成整块不可分，
  高过一页时它挪到下一页、再放不下就干脆不画——内容会像凭空消失一样。
  所以 `.md-codeblock__pre` 在打印时改成 `overflow: visible` + `pre-wrap`（长行折行，不再被纸边裁掉）。
  同一类问题也出现在 `break-inside: avoid` 上：代码块加它就可能在放不下时被整块丢掉，
  现在只对"通常不会超过一页"的表格、公式、图片做整体保护；
- **响应式规则一律加 `screen and`**：打印的媒体查询按**纸面宽度**算（A4 约 794px），
  不加限定的话窄屏那套"一次只显示一栏"会命中打印，把印张当成"没选中的那一栏"藏起来；
- **窄屏导出前先切到「阅读」栏**：Chrome 不会给打印时仍处于 `display:none` 的子树重新排版，
  不切过去就可能打出白纸（`exportPdf()` 里先把印张显示出来，打印结束再切回原来那一栏）。

**PDF 的默认文件名就是笔记标题**：标签页标题**始终**跟着当前笔记走（`我的笔记 · 校样`，
编辑器都这么做），点导出时再换成纯笔记标题，打印结束（`afterprint`）后恢复——
不用固定延时，是因为 `window.print()` 在部分浏览器里会立刻返回，提前恢复标题的话文件名就丢了。

但**文件名取的是"最外层文档"的标题**，所以还有一种情况要单独处理：
应用被嵌在别的页面里打开时（预览面板、内嵌浏览器），那个标题是外层页面的、甚至是空的，
打印窗口里就会看到"文件名是空的"。所以导出前会判断：

- 独立打开 → 换自己的标题就行；
- **同源嵌套** → 顺手把外层标签页的标题也换成笔记标题，打印完再还回去（这样文件名是对的）；
- **跨域嵌套** → 够不着外层，就老实提示"请在新标签页打开"，而不是打一份文件名不对的 PDF。

另外无论哪种情况，导出提示里都带一个**「复制标题」**按钮——万一某个浏览器就是不填文件名，
一键复制粘进去即可。快捷键 `Ctrl/Cmd + Shift + P` 同效。

### 5. 主题切换（5 套）

设置弹层（左栏底部「设置」）里换主题，换的是**整套 token**：稿纸、印张、红笔、代码高亮一起换。

| 主题 | 长相 |
| --- | --- |
| **校样**（默认） | 墨黑稿纸 + 纸白印张 + 一支红笔 |
| **石墨** | 中性灰阶，蓝墨强调 |
| **夜读** | 连纸面也是暗的（`color-scheme: dark`） |
| **蓝图** | 冷色纸面 + 橙色笔 |
| **苔原** | 暖绿灰 + 莓红，久读不累 |

主题在 CSS 里就是 `[data-theme="x"]` 下的一组自定义属性，**CSS 是唯一真相**：
设置弹层里的色板是临时切主题、用 `getComputedStyle` 读回来的，不在 JS 里抄第二份颜色。

### 6. 多种 Markdown 风格

设置里的「Markdown 风格」决定哪些扩展语法生效。13 个开关 × 4 套预设：

| 开关 | 通用（默认） | 中文写作 | 全扩展 | 严格 CommonMark |
| --- | :-: | :-: | :-: | :-: |
| 表格 `\| a \| b \|` | ● | ● | ● | |
| 任务清单 `- [x]` | ● | ● | ● | |
| 删除线 `~~x~~` | ● | ● | ● | |
| 裸链接 `https://a.dev` | ● | ● | ● | |
| 脚注 `文字[^1]` | ● | ● | ● | |
| 数学公式 `$e^{i\pi}$` | ● | ● | ● | |
| 井号后可不空格 `#标题` | ● | ● | ● | |
| 标题自定义锚点 `## 标题 {#id}` | ● | ● | ● | |
| 中英之间留白 `用React写` | | ● | | |
| 单换行即换行 | | ● | | |
| 高亮 `==重点==` | | | ● | |
| 上下标 `H~2~O` `x^2^` | | | ● | |
| 定义列表 `术语` + `: 解释` | | | ● | |

- **中英留白**只在"本来就挨着"的地方插一个空的 `<span class="cjk-gap">`——
  写了空格的地方不再重复加，代码和公式里不插，复制出去的文本还是干净的；
- **严格 CommonMark** 只留核心语法：井号后必须有空格、没有表格 / 任务清单 / 自动链接 / 脚注 / 公式，
  适合"写出来的东西要喂给别的严格解析器"；
- 换了风格会弹一句说明改了什么（不让人对着变化发懵），选择写进界面偏好；
- 设置里的开关列表是**从解析层导出的**（`md.features` / `md.flavors`），不是界面里手抄的一份。

## 四、技术选择

**零依赖，手写解析器**（`js/markdown.js`，约 1100 行）。
块级元素要带行号区间（签名交互的前提）、高亮配色要服从整套配色、
扩展语法要能按风格开关——这三件事都要求自己掌握解析层。

**字体是"锦上添花"，不是"能不能用"**：外面那张 Google Fonts 样式表用
`media="print" onload="this.media='all'"` 非阻塞加载。
一开始是普通的 `<link rel=stylesheet>`，结果实测撞上一个很凶的 bug——
**样式表会挡住它后面所有的 `<script>`**：网络慢、被墙或离线时，整页一直停在
`readyState: "loading"`，脚本一行都不跑，应用等于打不开（我是靠 CDP 把
`document.scripts` 打出来，才看清"只解析到第一个 script"的）。
现在字体来不了也照样能用，`--mono` / `--page` 两套字体栈里都配了本地回退字体。

**安全**：笔记内容可能存在 LocalStorage 里被人手工改过，所以渲染侧自己兜底——
原文 HTML 一律转义（不做 raw HTML 透传），链接协议走白名单（`http/https/mailto/tel/#/相对路径`），
图片只认绝对 URL、`data:image/` 或"当前笔记图库里的文件名"。
公式与 MathML 生成器只产出转义过的文本节点。解析层与公式层都有专门的测试盯着这条线。

**可测**：解析层、公式层、打包层、图片层的纯逻辑都在 Node 里跑同一份代码。
浏览器相关的部分用两个探针验（见下）。

## 五、目录

```
markdown-notes/
├─ index.html            界面骨架（三栏 + 目录栏页签 + 设置弹层 + 吐司）
├─ styles.css            全部样式：五套主题、三栏布局、印张排版、公式/脚注、响应式、打印
├─ js/
│  ├─ mathml.js          TeX 子集 → MathML（零依赖，原生渲染）
│  ├─ markdown.js        Markdown → HTML（带行号区间与标题锚点）+ 语法高亮 + 风格开关
```

探针把报告 **POST 到 `server.js` 的 `/__probe-report/<名字>`**（开发用端点，落成
`.screens/<名字>.json`）。以前写 localStorage，但探针跑完是被 kill 掉的，
Chrome 还没把 localStorage 刷盘，报告就丢了——白白怀疑了半天自己的代码。
这个端点只在 `npm start` 起的本地服务里存在，不参与应用逻辑。

```bash
npm test                              # 五层纯逻辑测试，不需要浏览器
node scripts/shots.js                 # 全部探针 + 五张截图
PROBE_ONLY=1 node scripts/shots.js    # 只跑探针，跳过截图
PRINT_ONLY=1 node scripts/shots.js    # 只跑"导出 PDF 实测"
node scripts/cdp-print.js 900 1000 --layout     # 打印 + 打印媒体下的布局
node scripts/pdf-text.js 某个.pdf               # 把 PDF 里的文字抽出来看
node scripts/png-stats.js .screens/desktop.png 280 936 943
```

**探针为什么值钱**：肉眼看不出"三栏宽度之和等于视口宽""页边括号和段落对齐到 2px 内"这种事；
也点不完"上传图片 → 插图 → 预览 → 删除 → 撤销"这条链路。
版面探针跑虚拟时钟（快，够量几何），流程探针跑**真实时钟**——
IndexedDB、平滑滚动、CSS 过渡在虚拟时钟下都不准，量出来的问题多半是假的。
**打印必须用 CDP 真打一份再解 PDF**：`--print-to-pdf` 在窄窗口下配合
`--virtual-time-budget` 会打出整页空白，这个坑让我追了很久的"假 bug"；
而且 Chrome 的 PDF 用的是子集化字体（Identity-H），
内容流里是字形编号不是 Unicode，只能解 ToUnicode CMap 才读得出字。

## 六、已知边界

- 不支持原生 HTML 透传（安全优先，写在笔记里的 `<div>` 会原样显示成文字）；
  不支持脚注套脚注、数学宏定义（`\newcommand`）。
- 公式覆盖的是"技术笔记够用"的子集，复杂对齐环境（`align` 里的 `&` 对齐）按普通表格处理。
- 图片不做压缩/缩放（存原图）；外链图片能否显示取决于对方是否允许跨域。
- 导入只认 `.md` / `.txt` / JSON 备份，**不认 ZIP**（导出是单向的）；
  导入的 Markdown 里若引用了图片，图片不会跟着进来。
- 目录名跟着标题走：两篇同名笔记导出时会变成 `标题.md` + `标题/` 与 `标题 (2).md` + `标题 (2)/`。
- 左边是 Markdown 原文：图片在稿纸栏里只能以文字形式存在，看排版要到右边的印张
  （底部那条缩略图带是"编辑时也能看见"的折中）。
- 数据分两处：笔记文本在 LocalStorage（约 5MB），图片在 IndexedDB（按浏览器配额）。
  换浏览器、清站点数据都会没——重要内容请用「备份」（JSON）与「ZIP」各留一份。
- 导出 PDF 依赖浏览器的打印引擎（目标选「另存为 PDF」），
  默认文件名已自动填成笔记标题；页眉页脚、页码由打印对话框控制，应用管不到。
