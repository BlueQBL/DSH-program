# 蓝晒 · AI 图片生成器（ai-image-generator）

> 一句话：**写下画面 → 选画幅、风格、画质 → 出图 → 自动存档，随时下载。**
> 零依赖（Node 原生 + 原生前端），上游走 **OpenAI-HK** 的 OpenAI 兼容接口，API Key 只从环境变量读。

这也是本仓库里那一批「AI 应用」的第三个：前面是 [智能聊天助手](../ai-chat)、[智能写作助手](../writing-assistant)，
模型这一块的实现方式一脉相承 —— 但这里多做了一步：**从聚合平台几百个模型里筛出「能出图的、且真的能用」的那些**，
把可用性直接标在界面上。

---

## 1. 核心链路

```
画面描述 ──(可选) AI 优化提示词──┐
画幅 1:1 / 16:9 / 9:16 / 4:3 …    ├──▶ POST /api/images/generate ──▶ 上游 /v1/images/generations
清晰度 1K / 2K / 4K               │                                   │
风格 摄影写实 / 电影感 / 水彩 …    │                                   ▼
画质 低 / 中 / 高                  │                            落盘 data/images/
模型（只列能出图的） ─────────────┘                                   │
                                                         记录写进 data/history/
                                                                      │
                                        相纸上的小样（PLATE 01）◀─────┴──▶ 历史抽屉 / 下载
```

四个功能点对应四段代码：

| 功能 | 在哪 |
| --- | --- |
| 文字出图（尺寸 / 风格 / 画质） | `server.js` `handleGenerate()` + `lib/styles.js` `buildRequest()` |
| 优化提示词（AI 扩写） | `server.js` `handleOptimize()` + `lib/prompt.js` |
| 历史记录 + 下载 | `lib/store.js` + `/api/history*`、`/api/images/*` |
| 出图模型筛选与可用性 | `lib/models.js`（`createModelRegistry`）+ 界面右上角模型下拉框 |

## 2. 快速开始

```shell
cd ai-image-generator
node server.js              # → http://127.0.0.1:5270/（端口被占用会自动往后试 10 个）
```

**没有 Key 也能直接跑**：会切到「离线显影引擎」，按提示词的哈希画一张真的 PNG（渐变天空 + 太阳 + 山脊 + 颗粒），
配色跟着当前风格走。这样「出图 → 落盘 → 历史 → 下载」整条链路在没有 Key 的情况下也能被真的走一遍，
界面上会如实标成「离线显影」。它**不是** AI 出的图，接上 Key 之后出的才是。

### 接上 OpenAI-HK

Key 从环境变量读，**代码里没有任何 key 字面量**：

```powershell
# Windows PowerShell（hk-xxxx 换成你自己的 key）
$env:OPENAI_HK_API_KEY="hk-xxxx"
node server.js
```

```shell
# macOS / Linux
OPENAI_HK_API_KEY=hk-xxxx node server.js
```

默认上游地址就是 `https://api.openai-hk.com/v1`（可用 `AI_BASE_URL` 覆盖）。启动时它会：

1. 拉一次 `GET /v1/models`，把**能出图的**模型挑出来；
2. 用一个 1 token 的极小请求，探出一个能用的**聊天模型**（优化提示词要用它）；
3. 打印出来：

```
蓝晒 · AI 图片生成器 已启动：http://127.0.0.1:5270/
  上游地址：https://api.openai-hk.com/v1（Key 来自 OPENAI_HK_API_KEY）
  可出图的模型 4 个，来自账号模型列表：gpt-image-2、gpt-image-1、dall-e-3、flux-schnell
  优化提示词用：gpt-4o-mini
  可用性检测要点「检测」才跑（会生成一张最低画质的图，花一点点额度）
```

### 没有 Key 也想看真实链路长什么样

项目里带了一台**假上游**（OpenAI 兼容，故意做成「不好用的平台」：模型列表里混着向量 / 语音 / 视频模型，
有永远 404 的、有只给 URL 的、有不认 `response_format` 的）：

```shell
# 终端 1
node scripts/fake-upstream.js          # → http://127.0.0.1:5399/v1

# 终端 2
$env:DEEPSEEK_API_KEY="sk-fake"; $env:AI_BASE_URL="http://127.0.0.1:5399/v1"; node server.js
```

打开页面就能看到：启动探测把 15 个模型滤成 7 个能出图的、模型下拉框里带「已验证 / 待检测」标记、
点「检测」能把 `dall-e-2` 标成调不通、出图是真的走 HTTP、历史里那张图真的存到了磁盘上。

## 3. 界面

一屏两栏，左边是**曝光台**（所有输入），右边是**接触印相纸**（所有出图）。

| 位置 | 是什么 |
| --- | --- |
| 左上「蓝晒」名字章 | 蓝晒法（cyanotype）的普鲁士蓝 + 相纸白 |
| 右上 出图模型 + 检测 + 状态灯 + 历史 | 只列能出图的模型；状态灯说清「上游出图 / 离线显影」 |
| 画面描述 + ✦ 优化提示词 | 优化后可以「还原原文」，不会把你的原话弄丢 |
| 画幅 + 清晰度 | 8 种画幅 × 3 档清晰度，数字全部来自平台文档的常用尺寸组合 |
| 风格 | 10 种，每种对应一段英文后缀，界面上能看到最终提示词 |
| 画质 | 低 / 中 / 高，直接关系到花多少额度 |
| 最终发给模型的那段提示词 | 折叠区，随时可查 —— 用的就是服务端同一个函数（`lib/styles.js`） |
| 出图小样 | 带齿孔的胶片条 + `PLATE 01` 编号 + 尺寸 / 风格 / 画质 / 耗时 / 模型 |
| 历史抽屉 | 搜索（描述 / 风格 / 模型）、下载、删除、清空 |
| 看大图 | 点小样打开，带「下载这张 / 复制提示词」 |

快捷键：`Ctrl / Cmd + Enter` 曝光，`Esc` 关掉看大图或历史抽屉（一层一层往回退）。

## 4. 模型这一块（这个项目比前两个多做的一步）

聚合平台的 `/v1/models` 动不动列几百个，里面混着向量、语音、审核、视频，真正能**文生图**的只是很小一部分；
而且「列表里有」不等于「你这个账号能调通」。所以分两步：

### 4.1 先筛：只留文生图模型

- **认**：`dall-e` / `gpt-image` / `flux` / `seedream` / `sdxl|stable-diffusion` / `midjourney` / `ideogram` /
  `imagen` / `qwen-image|wanx` / `nano-banana` / `gemini-*-image` …（`lib/models.js` 的 `IMAGE_HINTS`）
- **排**：embedding、moderation、rerank、whisper/tts/audio、ASR/OCR、`*-edit`（只能改图、不能凭空出图）、
  sora/veo/kling 这类视频模型、suno 这类音乐模型（`NOT_IMAGE`）
- **排**：「只看得懂图」的视觉模型（`gpt-4o-vision` 这种）也不算
- **排序**：`gpt-image-2 → gpt-image-1.5 → gpt-image-1 → dall-e-3 → dall-e-2 → seedream → flux …`，最后按名字排

筛完的结果就是界面上那个下拉框的数据源，每个都带一个状态：

| 状态 | 意思 |
| --- | --- |
| `已验证` | 在这个进程里真的调通过一次（出过图，或者点过「检测」成功） |
| `待检测` | 列表里有、还没验证过 —— 大概率能用，但没实测 |
| `调不通` | 实测失败过：单独归到「检测没通过」分组里（灰掉，选不了），鼠标悬停能看到原因 |

### 4.2 再验：真的调一次才算「可用」

出图调用是要花钱的，所以**不做开机批量实测**（那是拿用户的钱做探针）。规矩是这样：

1. **出图成功 = 自动记为已验证**（不额外花钱）。
2. 想看某个模型到底行不行，点「检测」：会弹一句确认（说明会消耗少量额度），
   然后发一次**最低画质 + 最小尺寸**（1024×1024、`quality: low`）的真实请求。
   检测不只看「有没有返回」—— 它会把返回的东西**本地解一遍**（base64 解码 + 格式嗅探），
   所以「上游返回了、但里面不是图片」这类问题会在检测阶段就被抓住，而不是等真出图时才失败。
   通过时它会顺带告诉你「返回 PNG，1639 KB」或「返回的是图片地址（未下载）」。
3. 结果**落盘**到 `data/model-status.json`：重启之后还认得「上次这个模型调不通」。
4. 「不偷偷换模型」：你在下拉框选了 A，请求就只会用 A；A 已知不可用会**明确报错**让你换，
   而不是拿 B 的图冒充 A。只有「你没选、由服务端挑」时才走默认（已验证的优先 → 配置的 → 排序最前的）。

### 4.3 列表拿不到时也不装傻

如果 `/v1/models` 取不到，或者账号列表里一个文生图模型都没认出来，就退回**平台文档里明确写过的**那几个模型：

```
gpt-image-2 / gpt-image-1.5 / gpt-image-1 / dall-e-3 / dall-e-2
```

来源会在界面上标成「账号列表里没认出能出图的模型，先按平台文档列 N 个」——
不假装这是账号里的列表，也不让你以为它们一定可用（它们的状态是「待检测」）。

> 出处：OpenAI-HK 文档的 [gpt-image-2 绘图模型](https://www.openai-hk.com/docs/openai/gpt-image.html) 与
> [快速接入](https://www.openai-hk.com/docs/getting-started.html)（`/v1/images/generations`，模型 `gpt-image-2` /
> `gpt-image-1.5` / `gpt-image-1`，以及 `dall-e` 系列）。

### 4.4 尺寸不是随便填的

`gpt-image` 系对 `size` 有几条硬约束：最长边 ≤ 3840、两边都是 16 的倍数、长短边比 ≤ 3:1、
总像素 655,360 ~ 8,294,400。界面上的 8 种画幅 × 3 档清晰度全部落在这些约束里；
`dall-e-3` 只有三档固定尺寸（1024×1024 / 1792×1024 / 1024×1792）、`dall-e-2` 更少，选出界了会**就近换成它收的那一档**，
并把「换成了哪个、为什么」写进这张图的备注里（不悄悄改）。

## 5. 优化提示词

- **有 Key**：用平台上的聊天模型（启动时 1 token 探活选出来的那个）扩写，要求它返回
  `{"prompt":"<英文提示词>","notes":"<一句中文说明>"}`；不按 JSON 回也照收（按纯文本处理），
  并在界面上说明「上游没有按 JSON 返回」。
- **没 Key**：离线扩写 —— 按「主体 / 环境 / 光线 / 镜头 / 质感 / 色彩 / 构图」七层模板拼一段更具体的提示词，
  同样的输入永远得到同样的输出（不做随机，免得点两次得到两段互不相干的文字）。
- **不改你的意图**：系统提示词里写死了「主体、数量、动作、情绪以用户描述为准，没写的才补」。
- 优化之后可以点「还原原文」，原文一直留着。

## 6. 历史与下载

```
data/
├── history/        img_xxx.json   一条记录一个文件（描述、最终提示词、风格、尺寸、模型、耗时、备注）
├── images/         img_xxx.png    图片本体（上游给 base64 就解码存，给 URL 就下载回来再存）
└── model-status.json              模型可用性记忆（已验证 / 调不通 + 时间 + 原因）
```

- **先写临时文件再 rename**，断电或崩溃不会留下半截 JSON；Windows 上 rename 偶发被占用（EPERM）会重试，最后兜底覆盖写。
- 上游给的 `https://.../xxx.png` 链接会过期、可能带防盗链，所以**一律先落到本地**，页面和下载都指着自己的文件。
- **取不回来也不丢图**：万一图床坏了 / 链接打不开 / 返回的是 HTML 错误页，这张**已经付过钱**的图不会被丢掉——
  记录照样进历史，界面显示上游那个临时链接，备注里写明「这张没存到本地（原因），链接可能会过期」，
  按钮从「下载」变成「打开原图」。下载接口这时返回 `409 remote_only` 并把上游地址一起给它，而不是假装成功。

### 6.1 出图失败 / 没图时的排查顺序

上游「成功返回」但界面上没图，只有三种可能，服务端日志和提示文案会直接指向其中一种：

| 你会看到 | 说明 | 怎么看 |
| --- | --- | --- |
| 终端 `[出图] <模型> <尺寸> quality=… → base64 png 1639KB` | 一切正常，图已落盘 | 相纸上应该有 PLATE 新的一格 |
| 终端 `[出图] <模型> … 取图失败：…（保留上游地址 …）` | 上游给的东西取不回来，但图被保留了 | 界面会显示上游链接 + 「没存到本地」备注 |
| 提示里出现「找不到图片数据（响应字段：…）」 | 这个模型返回的结构没认出来 | 把括号里那段贴出来就能定位，见 `lib/upstream.js` 里 `collectImageEntries()` 支持的形状 |

已经支持的返回形状（都在 `test/upstream.test.js` 里有用例）：`data[0].b64_json`、`data[0].url`、
`data: [...]` 里直接放字符串、`data` 不是数组、`images` / `output` / `image_url` / `image` 字段、
`url` 本身是 data URL、以及聊天式的 `choices[0].message.content` 里夹 markdown 图片。
- 下载走 `/api/history/<id>/download`，文件名是 `lan-shai-<描述前 40 字>-<id 后 6 位>.png`。
- 删一条记录会连图片一起删（不留孤儿文件）；「清空」需要 `confirm=1`，界面上还要再确认一次。
- 坏掉的 JSON 会被跳过并留一句日志 —— **不会**因为一个坏文件就把整本历史当成空。

## 7. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 版本、引擎状态（上游 / 离线）、模型数量、历史数量、预设 |
| GET | `/api/presets` | 画幅 / 清晰度 / 风格 / 画质 / 限制（给非浏览器客户端用；页面本身用共用的 `lib/styles.js`） |
| GET | `/api/models?refresh=1` | **只返回能出图的模型**，带 `state`（verified / untested / unavailable）与尺寸规则 |
| POST | `/api/models` | `{model}` 实测一个模型能不能出图（真调一次，花少量额度），结果落盘 |
| POST | `/api/prompt/optimize` | `{prompt, styleId, size}` → 扩写后的提示词 + 中文说明 |
| POST | `/api/images/generate` | `{prompt, styleId, size, quality, model}` → 出图、落盘、写历史，返回整条记录 |
| GET | `/api/history?q=&limit=&offset=` | 历史列表 + 统计 |
| GET | `/api/history/:id` | 单条记录 |
| GET | `/api/history/:id/download` | 附件下载（`Content-Disposition: attachment`） |
| DELETE | `/api/history/:id` | 删一条（连图片） |
| DELETE | `/api/history?confirm=1` | 清空（必须带 `confirm=1`） |
| GET | `/api/images/:file` | 图片本体（`?download=1` 变成附件） |
| GET | `/lib/styles.js` | 前后端共用的纯函数（尺寸表 / 风格表 / 提示词拼法） |

出图出错时，状态码会尽量说清是谁的问题：上游 402 → 402（余额）、429 → 429（限流）、
404 → 404（模型名不对，并把这个模型标进「调不通」）、其余上游问题 → 502。

## 8. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OPENAI_HK_API_KEY` / `OPENAI_API_KEY` / `DEEPSEEK_API_KEY` | 空 | 有值就走真实模型；都没有就用离线显影引擎。**代码里不写任何 key** |
| `AI_BASE_URL` / `OPENAI_BASE_URL` | `https://api.openai-hk.com/v1` | 兼容网关地址（换平台就改这个） |
| `AI_IMAGE_MODEL` | `gpt-image-2` | 首选出图模型；不在账号列表里就用列表里排最前的那个 |
| `AI_MODEL` | `gpt-4o-mini` | 优化提示词用的聊天模型（开机用 1 token 探活确认） |
| `AI_FORCE_OFFLINE` | 空 | 设为 `1` 强制离线显影（演示、对比、跑测试时用） |
| `AI_STALL_TIMEOUT_MS` | `60000` | 聊天请求多久没有新内容算卡住 |
| `AI_IMAGE_PROBE_TIMEOUT_MS` | `180000` | 「检测」单个模型的超时 |
| `PORT` / `HOST` | `5270` / `127.0.0.1` | 监听地址 |
| `AIG_DATA_DIR` | `./data` | 历史 / 图片 / 可用性记录的存放目录 |

## 9. 目录结构

```
ai-image-generator/
├── server.js               HTTP 服务：静态文件 + 全部 /api（路由在文件末尾，一眼能看完）
├── lib/
│   ├── styles.js           尺寸表 / 风格表 / 提示词拼法（**前后端共用**，浏览器也加载这一份）
│   ├── models.js           模型筛选、排序、可用性检测、兜底清单（这一步是本项目的重点）
│   ├── upstream.js         上游接入：Key 从环境变量读、错误翻译、脱敏、出图 / 聊天 / 下载
│   ├── prompt.js           优化提示词的系统提示词、JSON 解析容错、离线扩写
│   ├── store.js            历史记录 + 模型可用性记忆（原子写、坏文件跳过）
│   ├── image.js            base64 解码、格式嗅探、下载文件名
│   └── offline.js          离线显影引擎（手写 PNG，zlib 压缩）
├── public/
│   ├── index.html          曝光台 + 接触印相纸 + 历史抽屉 + 看大图
│   ├── css/styles.css      蓝晒配色与版面（齿孔、相纸、显影动画都在这里）
│   └── js/{api.js,app.js}  取数层 / 界面逻辑
├── scripts/
│   ├── fake-upstream.js    假上游（没有 Key 时验证真实链路）
│   └── capture.js          CDP 截图脚本（`npm run shot`）
└── test/                   8 个测试文件，`npm test` 一次跑完
```

## 11. 设计说明（为什么长这样）

- **蓝晒法**：铁氰化钾晒出来的相纸就是普鲁士蓝，没晒到的地方留白 —— 这是「用光把画面做出来」这件事本身的样子，
  比通用的深色背景 + 荧光色更贴题。所以底色只有三种：相纸冷白、普鲁士蓝、晒过头的暗。
- **接触印相纸**：一次出图 = 一格小样。每格带齿孔和 `PLATE 01` 编号（编号按时间顺序给，像胶片小样按顺序排），
  网格随窗口宽度自动增减列数。
- **显影**：出图期间那一格是「苍白 → 深蓝」的可控变化 + 一道扫光（`prefers-reduced-motion` 下全部关掉），
  而不是转圈圈；出图完成时图片有一次「显影」出现的过渡。
- **字体**：标题用宋体（衬线）—— 一本相册的标题感；元数据（尺寸 / 模型 / 时间 / 编号）全部用等宽字体，
  因为它们是要被对照、被抄下来的信息，不是装饰。
- **交互文案**：按钮说清「按下会发生什么」（曝光 / 检测 / 下载这张 / 还原原文），
  错误说清「谁的问题、怎么修」（余额不足 / 尺寸不被支持 / 模型名不存在 / Key 该配哪个变量），
  空状态是邀请而不是安慰（「写一句描述、挑一个画幅，按下曝光」）。

安全上的几条不变量：

- Key 只在服务端环境变量里，**不进代码、不进前端、不进日志**；所有来自上游的文本出口统一脱敏
  （`Bearer ...`、`sk-` / `hk-` / JWT / 云厂商 key 形态）。
- 浏览器能取到的只有 `public/` 和 `lib/styles.js`；`server.js`、`lib/upstream.js`、`data/` 一律 404。
- 写操作（POST / DELETE）做同源检查，跨站的直接 403。
- 数据目录、截图目录都在 `.gitignore` 里，仓库里不会有运行时产物。

## 12. 已知边界

- **一次一张**：`n` 固定为 1（dall-e-3 本身也只支持 1 张），想要不同构图就多按几次「曝光」。
- **不做图片编辑**：`/v1/images/edits`（传参考图改图）没有接 —— 那是另一个功能，界面上不装作有。
- **可用性检测要花钱**：只在你点「检测」时跑，且用最低画质；出图成功会自动标记为已验证，不必特意去测。
- **历史不分账号**：本机单人使用；要多人分开的话，参考 `writing-assistant` 那套可选账号的做法。
- **上游链接失效的图**：如果当时图床就坏了，历史里那张只留着上游地址（会过期），只能趁链接还有效时手动另存；
  想彻底避免，就在模型可用时重出一张（正常路径都会落到本地）。
